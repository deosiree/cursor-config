# UI 交互测试用例撰写规范

与 `test-case-writing-rules.md`（API/test.ts 风格）**并列**，主 SKILL 按输入类型二选一。

## 核心原则

### 用户可感知原则（最优先）

UI 用例只测**用户能直接看到或感受到的行为**。以下类型**禁止**列入手工用例：

| 禁止类型 | 原因 | 错误示例 |
|---------|------|---------|
| sessionStorage / localStorage 缓存结构验证 | 用户不关心内部存了什么数据 | `展开 permsMap 核对是否含 menuName、routePath` |
| API 请求体/路径验证 | 用户不关心调了哪个接口 | `POST /menu/tree 请求体含 types=function` |
| 内部函数调用链路验证 | 用户不关心代码怎么跑的 | `触发 loadUserPermsMap 执行` |
| F12 / DevTools 步骤 | 手工用例不应依赖开发者工具 | `F12 观察 Network → 查看响应` |
| mock / 篡改请求 | 手工测真实环境，不 mock | `mock menu/tree 返回 code≠0` |
| 内部状态断言 | 用户看不见代码状态 | `permsMap 为 {}`、`props 含 userInfo` |

**正确写法**：
- 用户看到 toast / 弹窗 / 按钮显隐 / 页面跳转 → ✅ 写用例
- 用户登录成功/失败、菜单刷新后内容变化 → ✅ 写用例
- 前置条件用业务语言：`后端权限接口返回业务错误` ✅ / `可 mock menu/tree` ❌

### 一条用例一个验证点

| 正确 ❌ 合并 | 正确 ✅ 拆分 |
|-------------|-------------|
| TC1/TC2 因「步骤类似」合并为一条 | 关联设备 Tab 校验、菜单权限 Tab 校验各一条 |

### 用例名称

- 格式：`{页面/弹窗}-{场景}-{期望摘要}`
- 可独立检索，禁止「同 TC1，第 3 步改为…」
- 示例：`新增角色-关联设备Tab提交空角色名-应跳回基础信息并提示`

### 前置条件

- 登录、菜单位置、环境（如 microfb + 子应用）写进 **前置条件** 列
- 不写进测试步骤
- 示例：`用户已登录；已进入「安全管理 > 角色管理」页面；microfb与apex_dev子应用可用`

### 测试步骤

- 编号 `1. 2. 3.` 列表
- **动词开头**：点击、输入、切换到、查看
- ≤ 7 步；过长则拆用例
- 禁止写入：`activeTab`、`handleConfirm`、文件路径、代码调用

### 预期结果

- **cases.json**：使用编号列表，界面语言（Tab 名、toast 文案、红字提示、弹窗是否关闭）
- **CSV 导出**：合并进「测试步骤」列的「预期结果：」段，**不写入「用例结果」列**（见 [`csv-export-format-rules.md`](csv-export-format-rules.md)）
- 示例（cases.json）：
  ```
  1. 当前 Tab 自动切回「基础信息」
  2. 「角色名称」标签前显示必填标识（*）
  3. 「角色名称」下方显示错误提示「角色名称不能为空」
  4. 弹窗不关闭，未创建新角色
  ```

### CSV 导出格式

所有 UI/API 路径导出 CSV 时须遵守 [`csv-export-format-rules.md`](csv-export-format-rules.md)：

```text
测试步骤：
1. ...
---
预期结果：
1. ...
```

- 「用例结果」/「预期结果」列留空
- 新增用例「用例ID」留空；更新场景 `--preserve-ids-from` 回填

### 禁止

- 填 **功能集合** 列
- 在步骤/预期里写代码断言、`expect()`、Markdown 链接
- 名称加 `[正向]` / `[反向]` 前缀

## 与 API 用例共存

同一 `role.csv` 可既有模板内 API 行（如「角色名的表单校验约束」），也有 UI 行：

| 区别 | API 行 | UI 行 |
|------|--------|-------|
| 用例ID | 有数字（如 `199`） | **留空** |
| 预期结果 | `正向：…` / `反向：…` | 编号列表，界面语言 |
| 前置条件 | 可选 | **必填**（登录/环境/路径） |
| develop结果 | 0（固定默认值） | 0（未执行状态） |
| 数据来源 | `*.test.ts` 代码 | 开发交互结论 + UI 验收 |

## 每条用例的必填列

| 列 | UI 路径 |
|----|---------|
| 名称 | ✅ |
| 前置条件 | ✅ |
| cases.json `steps` | ✅ |
| cases.json `expected` | ✅ |
| CSV 测试步骤 | 脚本合并 steps + expected |
| CSV 用例结果 | ❌ 留空 |
| develop结果 | = 0（未执行） |
| 功能集合 | v1 留空；v2 必填 |
| 用例ID | 新增留空；更新 `--preserve-ids-from` |
