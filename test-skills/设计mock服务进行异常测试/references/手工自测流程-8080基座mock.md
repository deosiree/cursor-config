# 手工自测流程 — Phase 2：8080 基座 mock

> 技能唯一源；目标仓库副本：`apex_dev/hytests/docs/workflow.md` §8。子应用用例仍走 [[手工自测流程-8081注入权限.md]]。

## 1. 适用用例

CSV 环境列含 `microfb :8080`、且失败发生在**基座侧栏/登录菜单**链路的用例（当前：**3699**）。

与 3700 区别：3700 在 apex 菜单管理页（8081）；3699 在基座 `MenuGateway.tree`（8080）。

## 2. 双进程启动

```bash
# 终端 1 — 子应用 dynamic entry
cd apex_dev && pnpm dev

# 终端 2 — 基座 mock
cd microfb && pnpm dev
```

确认：8081（apex）、8080（microfb）。

## 3. 启用 microfb mock

`microfb/.env.development.local`：

```env
VITE_MOCK_DEV_SERVER=true
```

重启 microfb dev。mock 插件优先于 proxy，无需改 `VITE_APP_API_URL`。

> **例外**：microfb 首次接入 mock 需改 `vite.config.ts` 注册插件（一次性）；之后仅用 env 开关。

## 4. 场景切换

编辑 **`microfb/.mock-shared/error-scenario.json`**（非 apex 目录）：

```json
{ "active": "3699" }
```

保存后刷新浏览器，一般无需重启 dev。

## 5. 浏览器步骤（3699）

1. 打开 `http://localhost:8080/cloud`
2. mock 登录（密码非 `wrong`；3699 时 login 返回空 `menuTree`）
3. **推荐**：登录成功后 **F5 刷新**
4. 期望：toast「加载菜单数据失败」一次

## 6. curl 快验

```bash
curl -X POST "http://localhost:8080/dev-api/forward/seccenter/v2/menu/tree" \
  -H "Content-Type: application/json" \
  -d "{\"tenantId\":\"1\",\"roleId\":\"1\",\"includeApis\":false}"
```

期望：`code: 40039`（HTTP 200）。

## 7. 故障排查

| 现象 | 处理 |
|------|------|
| 全是真实 `code:0` | 确认 `microfb` 的 `.env.development.local`；mock url 含 `forward/` |
| toast 是「加载权限数据失败」 | mock 误伤了带 `types` 的 tree；见 `scenario-helpers.ts` |
| 子应用白屏 | 启动 apex 8081 |
| 用 8081 测 3699 | 错误入口；必须 8080 |

## 路径约定（microfb）

| 类型 | mock url 前缀 |
|------|----------------|
| 鉴权直连 | `direct/seccenter/v2/auth/*` |
| 业务转发 | `forward/seccenter/v2/*` |

详见 `microfb/mock/README.md`。
