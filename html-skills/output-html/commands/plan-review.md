description: 生成可视化 HTML 方案审查——当前代码库 vs 提议的实现方案
---

加载 html-visual-explainer 技能，然后生成全面的可视化方案审查，作为自包含 HTML 页面，对比当前代码库与提议的实现方案。

遵循 html-visual-explainer 技能工作流程。在生成前阅读参考模板、CSS 模式和 mermaid 主题参考。使用 blueprint/editorial 审美，当前状态 vs 计划状态面板，但每次变化字体和调色板。

**输入：**
- 方案文件：`$1`（markdown 方案、规格或 RFC 文档路径）
- 代码库：`$2`（如提供），否则为当前工作目录

**数据收集阶段**——在生成前阅读并交叉引用：

1. **完整读取方案文件。** 提取问题陈述和动机、每个提议的变更、被拒绝的替代方案、明确的范围边界。
2. **读取方案引用的每个文件。** 读取导入或依赖这些文件的相关文件——方案可能未提及所有连锁效应。
3. **映射影响范围。** 识别导入变更文件的内容、存在的测试、可能需要更新的配置文件/类型/模式、调用者依赖的公共 API 表面。
4. **方案 vs 代码交叉引用。** 验证方案引用的文件/函数/类型是否真正存在、方案对当前行为的描述是否匹配实际代码。

**验证检查点**——在生成 HTML 前，创建结构化事实表。

**图表结构**——页面应包括：

1. **方案摘要**——先说直觉：这个方案解决什么问题？然后范围：多少文件、规模估计、计划的新模块或测试。
2. **影响仪表盘**——要修改的文件、要创建的文件、要删除的文件、估计新增/删除行数、计划的新测试文件、受影响的依赖。
3. **当前架构**——Mermaid 图展示受影响子系统现在的工作方式。`.mermaid-wrap` 带缩放控件。
4. **计划架构**——Mermaid 图展示方案实施后子系统的工作方式。使用相同节点名和布局方向。
5. **逐项变更分解**——方案中每个变更的并排面板。当前（左）vs 计划（右），记下任何当前行为描述与实际代码不符之处。
6. **依赖与涟漪分析**——正在变更的文件的调用方、导入者和下游影响。颜色编码：方案覆盖（绿）、未提及但可能受影响（琥珀）、肯定遗漏（红）。
7. **风险评估**——方案未涉及的边界情况、需要验证的假设、排序风险、回滚复杂度、认知复杂度。
8. **方案审查**——好/差/丑分析，引用具体方案章节和代码文件。
9. **理解差距**——汇总决策依据差距和认知复杂度标志的仪表盘。

写入 `~/.agent/diagrams/` 并在浏览器中打开。
