---
description: 生成可视化 HTML 实现方案——包含状态机、代码片段和边界情况的详细功能规格
---

加载 html-visual-explainer 技能，然后为 `$@` 生成全面的可视化实现方案，输出为自包含 HTML 页面。

遵循 html-visual-explainer 技能工作流程。在生成前阅读参考模板、CSS 模式和 mermaid 主题参考。使用 editorial 或 blueprint 审美，但每次变化字体和调色板。

**数据收集阶段**——在设计之前理解上下文：

1. **解析功能请求。** 提取：
   - 要解决的核心问题
   - 期望的用户可见行为
   - 提及的任何约束或要求
   - 范围边界（明确不包含什么）

2. **阅读相关代码库。** 识别：
   - 需要修改的文件
   - 要遵循的现有模式（代码风格、架构、命名约定）
   - 功能应集成的相关功能
   - 功能必须符合的类型、接口和 API

3. **理解扩展点。** 寻找：
   - 钩子点、事件系统或插件架构
   - 配置选项或标志
   - 可能需要扩展的公共 API
   - 代码库中使用的测试模式

4. **检查先例。** 搜索：
   - 已实现的类似功能
   - 相关的问题或讨论
   - 可以复用或扩展的现有代码

**设计阶段**——在写 HTML 前完成实现设计：

1. **状态设计。** 需要哪些新状态变量？哪些现有状态受影响？如果行为有多个模式，画出状态机。
2. **API 设计。** 添加了哪些命令、函数或端点？签名是什么？错误情况是什么？
3. **集成设计。** 此功能如何与现有功能交互？涉及哪些钩子或事件？
4. **边界情况。** 走查不常见场景：并发操作、错误条件、边界值、用户错误。

**验证检查点**——在生成 HTML 前，创建一个结构化事实表：
- 每个状态变量（新的和修改的）及其类型和目的
- 每个函数/命令/API 及其签名
- 每个需要修改的文件及具体变更
- 每个边界情况及其预期行为
- 方案依赖的每个关于代码库的假设
- 将每项与代码验证。如果某项无法验证，标记为不确定。

**图表结构**——页面应包含：

1. **头部**——功能名称、一行描述、范围摘要。*视觉处理：使用独特的头部——等宽标签、大号斜体标题、柔和副标题。为页面定调。*
2. **问题**——并排对比面板，显示当前行为 vs 期望行为。使用具体示例而非抽象描述。*视觉处理：两列网格，玫瑰色"之前"和鼠尾草色"之后"头部。编号流程步骤，带箭头。*
3. **状态机**——展示状态和转换的 Mermaid 流程图或 stateDiagram。用触发条件标注边缘。*使用 `.mermaid-wrap` 带缩放控件和点击展开。如果标签需要冒号或括号等特殊字符，使用 `flowchart TD` 而非 `stateDiagram-v2`。*
4. **状态变量**——卡片网格显示新的和修改的状态。使用带 `white-space: pre-wrap` 的代码块。*视觉处理：两张并排卡片，抬高深度，等宽标签。*
5. **修改的函数**——对每个需要更改的函数展示函数名和文件路径、关键代码片段、变更解释。*视觉处理：文件路径在代码块上方。*
6. **命令/API**——表格展示命令/函数名、参数和行为描述。*视觉处理：带粘性表头的带边框表格，交替行背景。*
7. **边界情况**——表格列出场景和预期行为。*视觉处理：与命令部分相同表格样式。*
8. **测试要求**——表格或卡片网格展示测试分类及要添加的特定测试。按单元测试、集成测试、边界测试分组。
9. **文件引用**——表格映射文件到所需变更。*视觉处理：紧凑引用表，文件多时用 `<details>`。*
10. **实现注意事项**——标注框：向后兼容性（金色边框）、关键实现警告（玫瑰色边框）、性能考虑（琥珀色边框）。

写入 `~/.agent/diagrams/` 并使用描述性文件名。在浏览器中打开结果。告知用户文件路径。
