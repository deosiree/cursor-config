description: 验证文档相对于实际代码库的事实准确性，并就地纠正不准确之处
---

加载 html-visual-explainer 技能，然后验证一个对代码库做出声明的文档的事实准确性。读取文件，提取每个可验证的主张，对照实际代码和 git 历史检查每个主张，就地纠正不准确之处，并添加验证摘要。

对于 HTML 文件：读取 `./references/css-patterns.md` 以在插入验证摘要时匹配页面现有样式。

**目标文件**——根据 `$1` 确定要验证的内容：
- 显式路径：验证该特定文件（`.html`、`.md` 或任何文本文档）
- 无参数：验证 `~/.agent/diagrams/` 中最新修改的 `.html` 文件

自动检测文档类型并调整验证策略：
- **HTML 审查页面**：从页面内容检测，基于所用 git ref 或方案文件验证
- **方案/规范文档**：验证文件引用、函数/类型名、行为描述和架构声明
- **其他文档**：提取并验证其中关于代码的事实声明

**阶段 1：提取声明。** 读取文件。提取每个可验证的事实声明：
- **量化**：行数、文件数、函数数、模块数、测试数
- **命名**：函数名、类型名、模块名、文件中引用的路径
- **行为**：代码做什么、如何工作、前后对比
- **结构**：架构声明、依赖关系、导入链、模块边界
- **时间**：git 历史声明、提交归属、时间线条目

跳过主观分析。

**阶段 2：对照源码验证。**
- 重新读取文档引用的每个文件
- 对于 git 历史声明：重新运行 git 命令对比
- 对于 diff-review：读取 ref 版本和工作树版本以确保前后声明正确
- 分类每个声明：已确认、已纠正、不可验证

**阶段 3：就地纠正。** 使用精确文本替换直接编辑文件。

**阶段 4：添加验证摘要。** 包含检查总数、已确认数、纠正列表、不可验证声明。

**阶段 5：报告。** 告知用户检查内容、纠正内容和打开文件。

这不是重新审查。它验证呈现的数据是否匹配现实，纠正不匹配的，其他一切保持不变。

写入纠正到原文件。
