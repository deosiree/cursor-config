description: 生成可视化 HTML 差异审查——前后架构对比含代码审查分析
---

加载 html-visual-explainer 技能，然后生成全面的可视化差异审查，输出为自包含 HTML 页面。

遵循 html-visual-explainer 技能工作流程。在生成前阅读参考模板、CSS 模式和 mermaid 主题参考。使用 GitHub diff 风格的红绿前后面板，但每次变化字体和调色板。

**范围检测**——根据 `$1` 确定要 diff 的内容：
- 分支名（如 `main`、`develop`）：工作树 vs 该分支
- 提交哈希：该特定提交的 diff（`git show <hash>`）
- `HEAD`：仅未提交的变更（`git diff` 和 `git diff --staged`）
- PR 编号（如 `#42`）：`gh pr diff 42`
- 范围（如 `abc123..def456`）：两个提交之间的 diff
- 无参数：默认 `main`

**数据收集阶段**——先运行以下命令了解全貌：
- `git diff --stat <ref>` 获取文件级概览
- `git diff --name-status <ref> --` 获取新增/修改/删除文件
- 行数对比：`git show <ref>:file | wc -l` vs `wc -l`
- 新公共 API 表面：grep 新增行中的导出符号、公共函数、类、接口
- 功能清单：grep 新操作、快捷键、配置字段、事件类型
- 读取所有变更文件的完整内容
- 检查 `CHANGELOG.md` 是否有这些变更的条目
- 检查 `README.md` 或 `docs/*.md` 是否需要更新
- 重构决策依据：从对话中挖掘讨论过的方法、被拒绝的替代方案和权衡

**验证检查点**——在生成 HTML 前，制作你将呈现的每个声明的结构化事实表：
- 每个量化数据：行数、文件数、函数数、测试数
- 每个你将引用的函数、类型和模块名
- 每个行为描述：代码做了什么、改变了什么、前后对比
- 为每项标注来源：产生它的 git 命令输出，或你读到它的文件:行
- 将每个声明与代码验证。如果无法验证，标记为不确定。

**图表结构**——页面应包括：
1. **执行摘要**——不仅是前后对比。先说明直觉：这些变更为什么存在？然后做事实范围（X 文件、Y 行、Z 新模块）。
2. **KPI 仪表盘**——新增/删除行数、变更文件数、新模块、测试数。包含维护指标。
3. **模块架构**——Mermaid 依赖关系图展示当前状态文件结构变化。使用 `.mermaid-wrap` 带缩放控件。
4. **主要功能对比**——每个重要变更区域的并排前后面板。
5. **流程图**——Mermaid 流程图、时序图或状态图展示新生命周期/管道/交互模式。
6. **文件映射**——完整文件树，颜色编码的新增/修改/删除指示器。*紧凑型，可考虑用 `<details>`。*
7. **测试覆盖**——前后测试文件数及覆盖内容。
8. **代码审查**——结构化好/差/丑分析：
   - **好**：合理的选择、改进、值得提及的干净模式
   - **差**：具体问题——bug、回归、缺失错误处理、逻辑错误
   - **丑**：微妙问题——引入的技术债务、可维护性问题、现在能用但以后会出问题的地方
   - **疑问**：不清楚或需要作者澄清的地方
   - 使用带绿/红/琥珀/蓝左边框强调的样式化卡片。
9. **决策日志**——每个 diff 中的重要设计选项：决策摘要、理由、考虑的替代方案、置信度。
10. **重新进入上下文**——"现在的你给未来的你的备忘"。关键不变量、非明显的耦合、陷阱、后续工作。

使用 diff 风格的视觉语言：红色表示删除/之前，绿色表示添加/之后，黄色表示修改，蓝色表示中性上下文。

写入 `~/.agent/diagrams/` 并在浏览器中打开。
