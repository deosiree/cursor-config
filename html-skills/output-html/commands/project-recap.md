加载 html-visual-explainer 技能，然后生成全面的可视化项目回顾，作为自包含 HTML 页面。

遵循 html-visual-explainer 技能工作流程。在生成前阅读参考模板、CSS 模式和 mermaid 主题参考。使用暖色 editorial 或 paper/ink 审美，搭配柔和蓝绿色，但每次变化字体和调色板。

**时间窗口**——根据 `$1` 确定回顾窗口：
- 简写如 `2w`、`30d`、`3m`：解析为 git 的 `--since` 格式
- 如果 `$1` 不匹配时间模式，将其视为自由形式上下文并使用默认窗口
- 无参数：默认 `2w`（两周）

**数据收集阶段**——先运行以下命令了解项目：

1. **项目身份。** 读 `README.md`、`CHANGELOG.md`、`package.json` 等获取名称、描述、版本、依赖。读取顶级文件结构。
2. **近期活动。** `git log --oneline --since=<window>`、`git log --stat --since=<window>`、`git shortlog -sn --since=<window>`。识别代码库中最活跃的区域。
3. **当前状态。** 检查未提交变更、陈旧分支、TODO/FIXME 注释、进度文档。
4. **决策上下文。** 读取近期提交信息。挖掘对话历史。读取任何方案文档、RFC 或 ADR。
5. **架构扫描。** 读取关键源文件，理解模块结构和依赖关系。

**验证检查点**——在生成 HTML 前，创建结构化事实表。

**图表结构**——页面应包括：

1. **项目身份**——当前状态摘要：项目做什么、谁在用、处于什么阶段。包含版本、关键依赖。
2. **架构快照**——Mermaid 图展示系统当前状态。关注概念模块及其关系。`.mermaid-wrap` 带缩放控件。
3. **近期活动**——按主题分组的人类可读叙述：功能工作、bug 修复、重构、基础设施。时间线可视化。
4. **决策日志**——时间窗口内的关键设计决策。从提交信息、对话、方案文档中提取。
5. **事物状态**——KPI 卡片展示：正常工作、进行中、已损坏或降级、受阻的内容。
6. **心智模型要点**——在此项目上高效工作需要记住的 5-10 件事：关键不变量、非明显耦合、陷阱、命名约定。
7. **认知债务热点**——琥珀色卡片。理解最弱的领域：无记录依据的近期变更、无测试的复杂模块、多人重叠修改的区域、频繁修改但理解不足的文件。
8. **下一步**——从近期活动、开放 TODOs、项目轨迹推断。

包含响应式章节导航。使用温暖、亲切的视觉语言。写入 `~/.agent/diagrams/` 并在浏览器中打开。
