# mvp-01：最小闭环（真实历史样本）

> 本文件沉淀自 2026-06-03 会话。供人类阅读和 agent few-shot 参考。
> 对应 write-skill 规范中的「真实历史样本型模板 — 写 mvp」。

## 最小可复现路径

从用户需求到可验证产物的最短路径：

```
用户需求（7 个模块配置权限点）
  → 1. 分析-perms-apis现状（扫描源码）
  → 2. 人工确认 2 个决策点（个人中心策略 + 跨模块归属）
  → 3. 策略-设计权限点（产出权限设计方案）
  → 4. 生成菜单树权限补丁（YAML）
  → 5. 菜单树导入验证（dry_run → 正式导入）
```

## 为什么这是最小闭环

- 跳过了「源码改动」（Phase D），因为菜单导入 + 角色配置后即可验证权限效果
- 跳过了「合并菜单树」（独立 skill），因为补丁 YAML 可直接导入
- 包含了不可跳过的 2 个人工决策点

## 关键输入输出

| 步骤 | 输入 | 输出 |
|------|------|------|
| 分析 | 仓库路径 + API 契约 | 盘点文档 |
| 设计 | 盘点文档 + 人工决策 | 权限设计方案 |
| 补丁 | 权限设计方案 | 菜单 YAML 补丁 |
| 导入 | 补丁 YAML | 导入结果 + 角色配置 |

## 最小触发示例

```text
使用 $梳理权限点与apis，扫描 apex_dev 的首页和租户管理，
先做分析，再设计权限点，最后生成菜单补丁 YAML。
```

预期执行序列：
1. 进入 `分析-perms-apis现状` → 消费 `扫描源码权限点与API`
2. 人工确认权限粒度
3. 进入 `策略-设计权限点` → 消费 `设计权限点与API映射`
4. 进入 `生成菜单树权限补丁`

## 不可跳过的门禁

- 盘点文档未产出 → 不进入设计
- 权限粒度未确认 → 不进入补丁
- function ID 未获取 → 不提交补丁
