# E2E 测试编排策略

> 本文件为 `编排-权限E2E测试` 的决策参考。
> 执行流程详见 `[[../../../feature-skills/OpenCLI双会话权限验证/references/dual-session-procedures.md]]`。

## 配置组合策略选择

| 策略 | 适用场景 | 每轮 perm 数 | 优点 | 缺点 |
|------|---------|------------|------|------|
| 逐个测试 | 首次验证，需要精确定位 | 1 | 隔离性好，哪个 perm 出问题一目了然 | 轮数多，耗时长 |
| 批量测试 | 回归验证，信任基础 | N（≤5） | 效率高 | perm 间可能互相干扰 |
| 负向测试 | 验证权限拦截有效性 | 全部取消 | 验证"无权限时全拦截" | 不验证单个 perm 的正确性 |

## 推荐测试顺序

```
1. 负向测试（全部取消）→ 确认基线：所有入口不可见/不可访问
2. 逐个测试（page 级 perm）→ 验证页面守卫
3. 逐个测试（operation 级 perm）→ 验证功能按钮
4. 批量测试（同模块 perm）→ 验证无交互干扰
5. 批量测试（跨模块 perm）→ 验证跨模块权限隔离
```

## 停止条件

| 条件 | 行为 |
|------|------|
| 所有测试 perm 完成 | 正常停止，输出完整 CSV |
| 连续 3 轮失败 | 暂停，排查环境问题（isOwner / sessionStorage / 角色同步） |
| 用户指定轮数已到 | 停止，输出已完成部分 |
| 环境不可用 | 停止并报告 |

## 模块特定依赖

### 菜单管理权限依赖矩阵

| 目标验证 | 前置依赖 perm | 原因 |
|---------|-------------|------|
| 工具栏"新增"按钮 | sys:menu:add + **显示状态=显示** | 显示状态为隐藏时不渲染 |
| 工具栏"导入"按钮 | sys:menu:import + **显示状态=显示** | 同上 |
| 工具栏"导出"按钮 | sys:menu:export + **显示状态=显示** | 同上 |
| 工具栏"查询"/搜索 | sys:menu:query + **显示状态=显示** | 同上 |
| 行内"编辑"按钮 | **sys:menu:query** + sys:menu:edit | 编辑按钮在树节点行内，需先有 query 加载树数据 |
| 行内"删除"按钮 | **sys:menu:query** + sys:menu:delete | 同上 |
| "API配置"按钮 | sys:menu:configApi + **显示状态=显示** | 显示状态为隐藏时不渲染 |

> **关键**：`sys:menu:query` 是行内操作的前提。没有它，树数据不加载，行内按钮不渲染，即使 edit/delete 已授权。
> **另一关键**：`checkHasPerm` = `permissions` + `permsMap[perm].isVisible`。显示状态为"隐藏"时，即使角色授权正确，按钮也不可见。

## 常见环境问题

| 症状 | 可能原因 | 检查方法 |
|------|---------|---------|
| 所有 test 用户验证都 pass（包括应被拦截的） | test 用户也是 owner | `sessionStorage.userInfo.isOwner` |
| admin 配置后 test 用户不生效 | 未等待同步 / Cookie 未过期 | 等待 3 秒后重试；确认 test 用户分组独立 |
| 上一轮配置残留 | test 用户未清空 sessionStorage | 每次切用户前 `sessionStorage.clear()` |
