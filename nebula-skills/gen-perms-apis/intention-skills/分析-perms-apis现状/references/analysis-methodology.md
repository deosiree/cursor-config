# 分析方法论

## 分析目标

从仓库源码中还原完整的权限覆盖现状：
- 哪些路由页面存在
- 每个页面已命中哪些 perm
- 每个 perm 管控哪些 API
- 哪些操作调用了 API 但未挂 perm

## 分析步骤

1. **建立路由表**：从 `router/index.ts` 提取所有静态路由
2. **递归扫描组件**：从路由页面出发，深度优先扫描所有业务子孙组件
3. **提取 perm 命中**：扫描所有 `v-hasPerm` 指令（过滤注释中的）
4. **API 反查**：对每个 perm 管控的操作，沿三类链路追到最终 API URL
5. **识别遗漏**：找出调用了 API 但未挂 perm 的操作
6. **契约匹配**：在默认和补充契约中查找 API 的 description

## 分析边界

- 全路由域扫描（除非用户提供了关注模块/路由）
- 递归包含所有业务子孙组件
- 公共基础组件仅在其包含该页面真实权限逻辑时纳入
- 子组件 emit/prop/v-model 必须继续追父组件

## 输出要求

- 每个路由独立章节
- 组件用完整源码路径（非中文描述）
- API 表优先契约 description，契约缺失标记"待人工确认"
- 未命中项分别归入"未命中权限控制的组件"和"未命中权限控制的权限点"
