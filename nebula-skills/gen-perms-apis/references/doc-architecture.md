# 文档架构说明

## 目标
把同一页面上的组件关系、已命中权限点、未命中权限点与 API 证据收敛进一份文档，同时保留两种阅读路径：

1. 从路由出发看页面整体
2. 从组件路径出发反查源码位置

## 章节顺序
每个路由固定使用：

1. `# <routePath>`
2. `## 组件`
3. 页面组件总表
4. 若干 `### <完整组件路径>`
5. `### 未命中权限控制的组件`
6. `## 权限点`
7. 已命中权限点总表
8. 若干 `### <权限标识>`
9. `### 未命中权限控制的权限点`

## 设计理由
- 页面组件总表回答“这个页面及其业务子孙组件由哪些源码路径构成”
- 组件小节回答“我去哪个文件里找，以及这个文件里有哪些真实权限命中”
- 未命中权限控制的组件回答“哪个组件的真实交互还没挂权限”
- 权限点小节回答“这个权限点具体控了什么、会调哪些 API”
- 未命中权限控制的权限点回答“这里还缺什么权限设计”
