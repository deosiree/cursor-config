## 本次试跑发现的模板风险

1. 若属性头前面还有标题，Obsidian 不会把属性识别为笔记属性。
2. 若组件字段只写中文描述，读者无法直接反查源码路径，所以统一改成完整组件路径。
3. 若不拆“未命中权限控制的组件”和“未命中权限控制的权限点”，就无法分别回答“哪个组件缺权限”和“应该补什么权限点”。
4. 若样本只按命中组件扫描，容易误导正式 skill 的能力边界，因此需要在规则层明确“全路由域递归扫描”。
5. 若默认契约不全却继续使用“源码语义推断”填 description，会让最终文档真假混杂，因此改成“待人工确认 + 多轮补全”。
6. 若查到 gateway 方法或子组件 emit 就停止，会把真实 API 误判成“无后端调用”，因此必须追到 api 文件和契约。
7. 若不解析 api base URL、模板字符串和 `direct/forward` 前缀，会输出未解析变量或错误中间路径。
