# 证据规则

## 权限命中证据

- 必须能回到真实模板或运行时代码
- 表达格式优先：`起止行号（业务动作）`

## 组件归属证据

- 若子组件由页面直接 import 或通过弹窗/表格操作链归属页面，则并入该页面
- 不单独为子组件建立路由章节
- 正式 skill 需从路由页面组件出发，递归扫描该页面的所有业务子孙组件
- 公共基础组件仅在其内部包含该页面真实权限逻辑或真实 API 触发逻辑时纳入

## 建议落点证据

- 未命中权限点的“对应行号”表示建议添加 `v-hasPerm` 的位置
- “对应代码”表示要包裹或新增权限的交互代码，不表示它当前已存在权限指令

## 组件路径表达

- 页面组件总表、权限落点表、未命中组件小节中，组件字段统一写完整源码路径
- 不允许使用“Tenant 页面”“UserTable 操作列”之类的中文角色描述替代路径

## 允许的占位

只有在完成 `业务层 -> gateway -> api -> 契约`（该链路可以消费技能..\..\route-api-gateway\SKILL.md）和 `业务层 -> api -> 契约` 反查后，确认该权限点只是路由跳转或纯前端状态操作，才能申请人类介入，只有人类确定了确实无后端API调用，才可在 API 表写 `- / - / 当前无后端 API 调用`；不能因为业务层没有直接 import `src/api` 就提前停止：

- 纯前端状态恢复
- 仅路由跳转
- 仅打开弹窗但真实提交接口在其他组件
- 当前按钮尚未绑定任何后端接口
