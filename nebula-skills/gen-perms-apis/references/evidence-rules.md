# 证据规则

## 权限命中证据

- 必须能回到真实模板或运行时代码
- 表达格式优先：`起止行号（业务动作）`

## 组件归属证据

- 若子组件由页面直接 import 或通过弹窗/表格操作链归属页面，则并入该页面
- 不单独为子组件建立路由章节
- 正式 skill 需从路由页面组件出发，递归扫描该页面的所有业务子孙组件
- 公共基础组件仅在其内部包含该页面真实权限逻辑或真实 API 触发逻辑时纳入
- 子组件没有直接调用 API 不等于“无后端调用”；必须继续检查 `emit`、`update:*`、`v-model`、props 回调、组合式函数返回方法是否把业务状态或动作抬升给父组件
- 父组件或组合式函数拿到子组件抬升的数据后，若调用 gateway/api 或在保存/提交时统一调用 gateway/api，则该子组件交互必须归入对应权限点

## 建议落点证据

- 未命中权限点的“对应行号”表示建议添加 `v-hasPerm` 的位置
- “对应代码”表示要包裹或新增权限的交互代码，不表示它当前已存在权限指令

## 组件路径表达

- 页面组件总表、权限落点表、未命中组件小节中，组件字段统一写完整源码路径
- 不允许使用“Tenant 页面”“UserTable 操作列”之类的中文角色描述替代路径

## 允许的占位

只有在完成以下三类反查后，确认该权限点只是路由跳转或纯前端状态操作，才能申请人类介入；只有人类确定了确实无后端 API 调用，才可在 API 表写 `- / - / 当前无后端 API 调用`：

- `业务层 -> gateway -> api -> 契约`，该链路可以消费技能 `..\..\route-api-gateway\SKILL.md`
- `业务层 -> api -> 契约`
- `子组件 emit/prop 抬升 -> 父组件方法 -> gateway/api -> 契约`

不能因为业务层没有直接 import `src/api`、子组件没有直接调 API、gateway 方法内部又包了一层映射函数就提前停止。gateway 方法内部可能通过 map 函数转换稳定模型与 wire 模型，必须继续追到最终 api 方法/URL。

- 纯前端状态恢复
- 仅路由跳转
- 仅打开弹窗但真实提交接口在其他组件
- 当前按钮尚未绑定任何后端接口
