## 口径说明
- 仅统计源码中已命中的 `v-hasPerm` 权限点。
- `apiUrl` 去掉 `direct` / `forward` / `{direct|forward}` 前缀，统一落业务路径。
- `description` 优先读取默认契约或补充契约的 `description`；若缺失，回退 `summary`。
- 若所有已知契约都未命中，不允许主观推断，必须标记为“待人工确认”，并进入文末 `# 待人工介入`。
- 每个路由必须补充“未命中权限控制的组件”和“未命中权限控制的权限点”，用于识别权限遗漏面。

## 归属规则
- 页面级章节的单位是静态路由对应的页面，而不是单个 Vue 文件。
- 子组件中的权限点并入父路由页面，不单独升格成路由。
- 正式 skill 需要从路由页面组件出发，递归扫描该页面的所有业务子孙组件。
- 组件小节的作用是反向定位源码，不是替代页面总表。

## 过滤规则
- 注释中出现的 `v-hasPerm` 不算真实命中。
- 只有真实模板消费、指令绑定或等价运行时消费，才算命中。

## API 证据规则
- 优先按源码真实调用建立 API 清单。
- 若默认或补充契约中存在对应 path，`apiMethod / apiUrl / description` 优先取契约。
- 若所有已知契约都不存在对应 path，不允许回退成正式推断描述，必须请求人工介入。

## 未命中权限点规则
- 没有挂 `v-hasPerm`、但能触发真实 API 的元素，需要设计建议权限点。
- 建议权限点应放在所属路由下的“未命中权限控制的权限点”章节。
- 该章节中的行号与代码是“建议加权限的位置”，不是既有命中证据。
