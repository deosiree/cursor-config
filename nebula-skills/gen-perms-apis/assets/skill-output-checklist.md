# 输出检查清单

- [ ] 属性头从文件第一行开始
- [ ] 属性头包含完整输入契约的中英文字段
- [ ] 属性头包含 `补充契约路径 / extra_api_contracts`
- [ ] 属性头包含 `关注模块 / focus_modules` 与 `关注路由 / focus_routes`
- [ ] `focus_modules` 与 `focus_routes` 均为空时，正文口径说明为默认全量关注
- [ ] 正文不存在总标题 `# <仓库名> ...`
- [ ] 存在 `# 口径说明`
- [ ] 每个路由存在 `## 组件` 与 `## 权限点`
- [ ] 页面组件总表只写完整组件路径
- [ ] `未命中权限控制的组件` 下每个组件都列出“期望补齐的权限点”
- [ ] “期望补齐的权限点”能和 `未命中权限控制的权限点` 小节对应
- [ ] 已命中权限点的落点表中只写完整组件路径
- [ ] 默认契约、补充契约、待人工介入三段式解析成立
- [ ] API 表中的 URL 已追完 gateway/api/base URL，不停在 gateway 方法名或映射函数
- [ ] API 表不出现未解析变量，例如 `/${BASE_URL}/xxx`、`/${MENU_BASE_URL}/export`
- [ ] API 表不出现因漏看 gateway/base URL 得到的错误中间路径，例如错误 `/menu/activate`
- [ ] 子组件通过 `emit`、props 回调或 `v-model` 抬升时，已继续追到父组件/组合式函数的 gateway/api 调用
- [ ] 正式 API `description` 不允许写 `源码语义推断`
- [ ] 契约缺失时文末存在 `# 待人工介入`
- [ ] 未完成三类 API 反查前，不允许写 `当前无后端 API 调用`
- [ ] 若人工已给出“暂不处理”的业务结论，文档保留挂起说明且不继续追问
