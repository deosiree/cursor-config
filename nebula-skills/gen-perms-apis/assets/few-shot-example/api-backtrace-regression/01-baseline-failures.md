# 01 初版失败记录

## 用户反馈前的错误形态

初版扫描只从页面和组件表面找权限点与 API，遇到以下情况就提前停止：

- 业务层没有直接 import `src/api`，就误写“当前无后端 API 调用”。
- 子组件只负责 `emit`、`update:*`、props 回调或 `v-model`，就误判没有后端接口。
- 查到 gateway 方法后没有继续追 api 文件。
- 查到 api 文件中的 base URL 常量或模板字符串后没有展开。
- 默认只查 `seccenter.swagger.json`，没有根据用户补充去查其他契约。

## 典型错误

| 初版错误 | 根因 | 应修正为 |
| --- | --- | --- |
| 设备激活被写成错误菜单路径 | 漏看 gateway 到 api 的真实 URL | 追 `DeviceGateway -> DeviceAPI -> devmgr.swagger.json` |
| API URL 保留未解析设备 base URL | 只读字符串模板，没有解析常量 | 展开常量后再进入契约匹配 |
| 安全配置页被判定为无后端调用 | 子组件没有直接调 API，被当作终点 | 追子组件抬升到父组件/组合式函数 |
| 个人中心只识别查看资料 | 漏掉弹窗和表单提交链路 | 追修改资料、密码、邮箱、手机号 |

## 需要沉淀的规则

- “业务层没直接调 api”不是无 API 的证据。
- “子组件没直接调 api”不是无 API 的证据。
- gateway、映射函数、base URL 常量、模板字符串都只是中间节点。
- 契约缺失应进入待人工介入或补充契约，不得主观补 description。
