# 03 关注路由与后端待开发记录

## 用户补充

用户说明只关心以下路由的权限点和 API：

- `/Apex/tenant`
- `/Apex/system/User`
- `/Apex/system/Role`
- `/Apex/systemMenu`
- `/Apex/system/SecurityConfig`
- `/Apex/profile`

其他模块不是本轮负责范围，可以弱化为“不关心”。

## 修正动作

- 继续保持全路由扫描能力。
- 结论、提醒和待人工介入优先收敛到关注路由。
- 非关注路由不继续扩散待人工项，可按用户口径标记“不是我负责的关心，不关心”。
- 未提供 `关注模块` 或 `关注路由` 时，不启用非关注策略，默认全量。

## 后端待开发记录

用户明确说明以下接口前端已实现，但后端待开发，先不设计权限点与 API：

- 用户导入接口
- 菜单导出接口
- 菜单导出 base URL 链路

## 输出策略

- 保留业务层到 gateway/api 的链路说明。
- 不生成建议权限点。
- 不写入已确认 API 表。
- 不继续追问契约。
- 在待人工或暂不处理小节记录用户结论，避免下一轮重复追问。

## 需要沉淀的规则

- 关注范围是结论收敛参数，不是扫描能力边界。
- 非关注策略只有在用户显式提供关注范围时启用。
- 用户明确“后端待开发，先不设计”时，不要强行补权限点与 API。
