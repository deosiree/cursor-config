# 命令与输入格式

工作目录：本 skill 根目录  
`huiyanSkills/nebula-skills/菜单节点的唯一性和有效性校验/`

**不要**在 `apex_dev` 落扫描脚本。

## 1. YAML 导出 → JSON

```bash
python scripts/convert-menu-yaml-to-json.py <yaml目录> <输出json目录>
```

例：

```bash
python scripts/convert-menu-yaml-to-json.py \
  F:/Documents/Repertory/Sieyuan/nebula/docs/menu/t-cloud \
  F:/Documents/Repertory/Sieyuan/nebula/docs/menu/t-cloud/_scan_json
```

产物：

- 每文件一个 `{stem}.json`
- 合并 `_all.json`（多项目当「全库」时用）

转换要点：

- `route_path` → `routePath`，`parent_id` → `parentId` 等
- `params` JSON 字符串解析为数组
- 导出 `project_id` 常为 0 → 用**文件名**写入 `projectId`，避免误跨文件判重/合并语义混乱

依赖：`pip install pyyaml`

## 2. 只读扫描

```bash
node scripts/scan-menu-rules.mjs --help
node scripts/scan-menu-rules.mjs --input <menu.json> [--out report.json] [--project-id <id>]
```

退出码：`0` 无违规 · `1` 有违规 · `2` 参数/读文件错误。

## 3. 输入 JSON 形状

支持：

- `MenuVO[]` 树
- `{ "result": MenuVO[] }` / `{ "menus": MenuVO[] }`
- `[{ "projectId", "menus": MenuVO[] }, ...]`

YAML 侧顶层需有 `menus:`；`menus: []` 为空项目。

## 4. 失败分支

| 症状 | 处理 |
|------|------|
| 直接扫 `.yaml` | 先 convert |
| 全 0 命中但直觉有问题 | 查 `routePath` 是否仍为 `route_path`；type 是否齐全 |
| `_all` 大量 `route.combo` | 先分文件扫；确认是否同库共存再决策 |
| 写接口/推送 | **禁止**；本 skill 只读 |
| 在 apex 里找 `scan-menu-rules` | 已迁出；用本 skill `scripts/` |
