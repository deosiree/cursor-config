# 返回动态拼接的工具函数：MVP 经验贴

## 结论

当一个工具函数返回的不是单个稳定 i18n key，而是**由多个片段和动态变量拼接出来的最终文案**时，不要在定义点给词条包trans()再在消费点外层整体 `t(...)`，因为词条的返回值不唯一。

推荐做法：

1. 重构工具函数
2. 给函数增加入参 `t`
3. 在函数内部按片段翻译
4. 在引用点把 `t` 传进去
5. 引用点直接消费最终字符串，不再二次 `t(...)`

这个模式适用于本次 `src/utils/login-mfa.ts` 中的 `resolveMfaHintText`。

---

## 什么时候要这样改

满足下面任一条件，就不要再走“返回 key，外层统一 `t(...)`”的模式：

- 文案由多个 key 拼接而成
- 文案中混有动态变量，例如手机号、邮箱、用户名
- 返回值不是稳定 key，而是运行时生成的整句文本

## 典型错误写法：

### 定义点

```ts
import { trans } from 'vue-i18n-kit-sy/runtime'

/**
 * 生成 MFA 面板提示文案。
 *
 * @param params MFA 提示所需上下文。
 * @returns 提示文本。
 */
export function resolveMfaHintText(
  requiresMfa: boolean;
  isMfaChallengeActive: boolean;
  channel: MfaChannel;
  maskedPhone?: string;
  maskedEmail?: string;
): string {
  if (!requiresMfa) return trans("当前登录配置无需 MFA。");
  if (!isMfaChallengeActive) return trans("请先点击“登录”完成账号密码校验，再发送 MFA 验证码。");

  const channelText = getMfaChannelLabel(channel);
  const masked = channel === mfaChannel.sms ? maskedPhone : maskedEmail;
  const prefix = trans("验证码将发送到");
  return masked
    ? prefix + trans(channelText) + trans("：") + masked
    : prefix + trans(channelText) + trans("。");
}
```

### 引用点

```vue

</template>

<script setup lang="ts">

```

如果 `resolveHint(...)` 返回的是：

```text

```

那外层 `t(...)` 就会把整句动态文本当作 key 去查，这是错误翻译时机。

## 推荐模板

### 工具函数定义

```ts
export function resolveDynamicText(params: {
  t: (message: string) => string;
  foo: string;
  bar?: string;
}): string {
  const { t, foo, bar = "" } = params;

  const prefix = t("前缀");
  const label = t("标签");

  return bar ? prefix + label + "：" + bar : prefix + label + "。";
}
```

### 调用点引用

```ts
const text = computed(() =>
  resolveDynamicText({
    t,
    foo: foo.value,
    bar: bar.value,
  })
);
```

```vue
{{ text }}
```

核心点：

- `t` 在调用点拿
- `t` 作为参数传进工具函数
- 工具函数返回最终字符串
- 模板直接显示，不再二次 `$t(...)`

## 项目内实例

### 定义点

文件：[login-mfa.ts](F:\Documents\Repertory\Sieyuan\nebula\microfb\src\utils\login-mfa.ts:131)

```ts
export function resolveMfaHintText(params: {
  t: (message: string) => string;
  requiresMfa: boolean;
  isMfaChallengeActive: boolean;
  channel: MfaChannel;
  maskedPhone?: string;
  maskedEmail?: string;
}): string {
  const { t, requiresMfa, isMfaChallengeActive, channel, maskedPhone = "", maskedEmail = "" } =
    params;

  if (!requiresMfa) return t("当前登录配置无需 MFA。");
  if (!isMfaChallengeActive) return t("请先点击“登录”完成账号密码校验，再发送 MFA 验证码。");

  const channelText = getMfaChannelLabel(channel);
  const masked = channel === mfaChannel.sms ? maskedPhone : maskedEmail;
  const prefix = t("验证码将发送到");

  return masked
    ? prefix + t(channelText) + "：" + masked
    : prefix + t(channelText) + "。";
}
```

这个函数为什么必须吃 `t`：

- 它不是返回单个 key
- 它会拼接：
  - `验证码将发送到`
  - `短信` / `邮箱`
  - `：` / `。`
  - `maskedPhone` / `maskedEmail`

因此它应该直接返回最终文案。

## 对比：哪些函数不需要这样改

如果工具函数只是简单映射单个 key，就没必要加 `t` 入参。

例如：

- [normalizeMfaText](F:\Documents\Repertory\Sieyuan\nebula\microfb\src\utils\login-mfa.ts:45)
- [normalizeMfaPlaceholder](F:\Documents\Repertory\Sieyuan\nebula\microfb\src\utils\login-mfa.ts:101)
- [resolveMfaSendSuccessText](F:\Documents\Repertory\Sieyuan\nebula\microfb\src\utils\login-mfa.ts:121)

这类函数返回 key 更合适：

```ts
export function normalizeMfaPlaceholder(channel: MfaChannel): string {
  return channel === "sms" ? trans("请输入短信验证码") : trans("请输入邮箱验证码");
}
```

调用点再翻译：

```ts
const placeholder = computed(() => t(normalizeMfaPlaceholder(channel.value)));
```

## 经验规则

记一个最小判断法：

- 返回单个 key：函数返回 key，调用点 `t(...)`
- 返回动态拼接文案：函数接收 `t`，内部翻译并返回最终字符串

不要混用。

## 检查清单

- [ ] 这个函数返回的是 key，还是最终文案？
- [ ] 是否包含动态变量？
- [ ] 是否包含多个文案片段拼接？
- [ ] 如果是最终文案，是否已改成接收 `t`？
- [ ] 如果函数已返回最终文案，模板/调用点是否避免再次 `$t(...)`？

---

## MVP 适用范围

这个模式优先用于：

- hint text
- toast message 片段拼接
- placeholder / label 的动态组合
- 带脱敏账号、倒计时、渠道名等运行时变量的提示文案

如果后续语言差异更大，再进一步升级为完整模板翻译，而不是继续手工字符串拼接。
