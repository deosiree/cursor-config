# 后端国际化方案说明

## 1. 目标

SDK基于 GoFrame 的 `gi18n` 能力，结合业务自定义逻辑，解决以下问题：

*   后端统一返回可国际化文本给前端
    
*   支持单变量和多变量替换
    
*   支持组态模板渲染
    
*   支持浏览器 `Accept-Language` 与显式 `lang` 参数
    
*   支持自动抽取中文词条并同步到多语言 yaml 文件
    
*   支持自动生成可导入平台翻译工具的翻译文件
    
*   支持平台翻译导出文件回写到对应的yaml文件内
    

## 2. SDK 使用说明

### 2.1 主要提供以下功能：

*   词条标记：`T("...",AppName)``AppName`参数非必填
    
*   翻译调用：`Translate(ctx, input)`
    

其中：

*   `T` 用来标记需要抽取的文本
    
*   第二个可选参数 `appName` 用来给词条加分组命名空间
    
*   如果 `T("...")` 没传 `appName`，抽词工具会读取接入方项目根目录 `k8s.yaml` 中的 `metadata.name` 作为默认命名空间
    
*   `Translate` 用来根据当前语言获取翻译结果
    

模块名：

`go.lanniu.top/nebula-cloud/sdk/i18n`

包路径：

```go
import sdk "go.lanniu.top/nebula-cloud/sdk/i18n/pkg/i18n"
```

### 2.2 SDK API

 API 如下：

```go
func T(text string, appName ...string) string
func Translate(ctx context.Context, in TranslateInput) (TranslateOutput, error)
func DetectLanguage(ctx context.Context, lang string) string //判断使用用哪个语言
func SupportedLanguages() []string //获取sdk默认支持的语言
```

这几个接口支持：

*   在业务代码里用 `T` 标记词条
    
*   通过抽词脚本扫描这些标记并生成语言包
    
*   业务代码自行组装 `TranslateInput`
    
*   在运行时调用 `Translate` 获取当前语言对应的翻译值
    

### 2.3 使用方项目

SDK 基于 GoFrame 的 g.I18n() 来取翻译，所以项目需要满足这些条件：

*   使用方项目本身也使用 GoFrame
    
*   使用方项目运行时存在 i18n 或 manifest/i18n 目录
    

总结：

**SDK 负责标记词条和触发翻译 使用方项目负责提供语言包目录和 GoFrame 运行环境**

## 3. 基本用法

### 3.1 普通词条

```go
import sdk "go.lanniu.top/nebula-cloud/sdk/i18n/pkg/i18n"

input := sdk.TranslateInput{
	Lang: "en-US",
	Key:  sdk.T("设备不存在"),
}

result, err := sdk.Translate(ctx, input)
if err != nil {
	return err
}

fmt.Println(result.Message)

```

### 3.2 带变量的词条

```go
input := sdk.TranslateInput{
	Lang: "ja-JP",
	Key:  sdk.T("你好,我叫{name}"),
	Params: map[string]interface{}{
		"name": "Tom",
	},
}

result, err := sdk.Translate(ctx, input)

```

### 3.3 带 AppName 的词条

```go
input := sdk.TranslateInput{
	Lang: "en-US",
	Key:  sdk.T("未定义", "devmgr"),
}

result, err := sdk.Translate(ctx, input)
```

这时 `sdk.T("未定义", "devmgr")` 返回的实际 key 是：

```text
devmgr.未定义
```

抽词脚本会把它写到 YAML 的 `devmgr` 分组下面，例如：

```yaml
devmgr:
  未定义: 未定义
```

### 3.4 模板词条

```go

input := sdk.TranslateInput{
	Lang:     "en-US",
	Template: sdk.T("设备 {name} 温度 {temp}℃"),
	Bindings: map[string]string{
		"name": "device.name",
		"temp": "device.temp",
	},
	Data: map[string]interface{}{
		"device": map[string]interface{}{
			"name": "A1机柜",
			"temp": 36.5,
		},
	},
}

result, err := sdk.Translate(ctx, input)

```

## 4. 多语言值获取

`Translate` 本身不会手动去拼接语言目录路径，它的流程是：

*   通过 `DetectLanguage` 确定最终语言
    
*   用 `gi18n.WithLanguage(ctx, lang)` 把语言写入上下文
    
*   调用 `g.I18n().T(ctx, key)`
    

*   由 GoFrame 按默认规则去使用方项目的 `i18n` 或 `manifest/i18n` 目录中找语言文件
    
*   所以，只要使用方项目里有标准的 `i18n` 目录，SDK 的 `Translate` 就可以自动查到翻译。
    

## 5. 抽词脚本

*   扫描 Go 源码中的 `T("...")` 和 `T("...", "appName")`
    
*   抽取中文词条
    
*   同步到语言包 YAML
    

当代码里使用 `T("中文")` 没有显式传 `appName` 时，工具会读取接入方项目根目录的 `k8s.yaml`，并使用其中的 `metadata.name` 作为默认命名空间。

![image.png](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/KM7qeobPEgoa7lpj/img/09ac190f-2c33-4e7e-a923-3342c0320622.png)

例如项目根目录存在`k8s.yaml`：

```yaml
metadata:
	name: devmgr
```

那么：

```go
sdk.T("未定义")
```

会被抽取到：

```yaml
devmgr:
	未定义: 未定义
```

### 5.1 如何执行 `**make i18n-sync**`

先把 SDK 根模块引入到自己的项目，再在自己的项目里新增一个 `Makefile` 目标。

第一次接入时，先执行：

```bash
go env -w GOPRIVATE=go.lanniu.top
go get go.lanniu.top/nebula-cloud/sdk/i18n@latest

```

如果语言包目录使用 `manifest/i18n`：

```make
.PHONY: i18n-sync

i18n-sync:
	go run go.lanniu.top/nebula-cloud/sdk/i18n/utility/i18n-sync -root . -i18n-dir manifest/i18n

```

如果语言包目录直接使用 `i18n`：

```make
.PHONY: i18n-sync

i18n-sync:
	go run go.lanniu.top/nebula-cloud/sdk/i18n/utility/i18n-sync -root . -i18n-dir i18n

```

然后在项目根目录执行：

```bash
make i18n-sync

```

运行 SDK 仓库提供的抽词工具

扫描当前项目源码

识别当前项目里的 `sdk.T("...")`

将词条写入当前项目自己的语言包目录

### 5.2 语言包生成目录

当前抽词工具会在你指定的 `-i18n-dir` 目录下读写 YAML 文件，但不会自动创建上层目录。

第一次执行前，至少要先创建下面两种目录之一：

*   `manifest/i18n`
    
*   `i18n`
    

例如：

```bash
mkdir -p manifest/i18n

```

或者：

```bash
mkdir -p i18n

```

目录创建好之后，再执行 `make i18n-sync`，工具会根据项目根目录 `i18n.yaml` 中定义的语言列表生成对应语言文件；如果没有提供 `i18n.yaml`，则回退到默认的：

`zh-CN.yaml`

`en-US.yaml`

`ru-RU.yaml`

`ja-JP.yaml`

新增词条：

*   `zh-CN.yaml`：生成 `key: key`
    
*   `en.yaml`：生成 `key: ""`
    
*   `ja.yaml`：生成 `key: ""`
    

### 5.3 语言包抽取语种定义

项目根目录需要定义i18n.yaml文件，如果没有提供 `i18n.yaml`，则抽取sdk里默认语种：

```typescript
supportedLanguages:
  - zh-CN
  - en-US
  - ja-JP
  - ru-RU
```

## 6.导入导出csv

### 6.1 导出`**make i18n-csv**`

把当前 `i18n` 目录下的 YAML 汇总成一个 Excel 文件，可以执行 SDK 提供的 `i18n-xlsx` 工具。

如果语言包目录使用 `manifest/i18n`：

```make
.PHONY: i18n-csv

i18n-csv:
	go run go.lanniu.top/nebula-cloud/sdk/i18n/utility/i18n-csv -root . -i18n-dir manifest/i18n

```

如果语言包目录直接使用 `i18n`：

```make
.PHONY: i18n-csv

i18n-csv:
	go run go.lanniu.top/nebula-cloud/sdk/i18n/utility/i18n-csv -root . -i18n-dir i18n

```

执行后，工具会在对应语言目录下生成 `i18n.csv`。

### 6.2 导入`**make i18n-yaml**`

 平台翻译工具导出的`i18n.csv`，可以使用 `i18n-yaml` 工具把它重新写回各语言 YAML。

如果语言包目录使用 `manifest/i18n`：

```make
.PHONY: i18n-yaml

i18n-yaml:
	go run go.lanniu.top/nebula-cloud/sdk/i18n/utility/i18n-yaml -root . -i18n-dir manifest/i18n

```

如果语言包目录直接使用 `i18n`：

```make
.PHONY: i18n-yaml

i18n-yaml:
	go run go.lanniu.top/nebula-cloud/sdk/i18n/utility/i18n-yaml -root . -i18n-dir i18n

```

这个工具会读取同目录下的 `i18n.xlsx`，并按表头中的语言列覆盖生成对应的 YAML 文件。

## 7. 注意

当前sdk设计下，使用方项目需要：

GoFrame 运行环境

`i18n` 或 `manifest/i18n` 目录

对应语言的 YAML 文件

## 8.数据库CODE映射表

### 8.1 主表：语言 Key 表（定义语义）

```json
CREATE TABLE i18n_key (
    id            BIGINT PRIMARY KEY AUTO_INCREMENT,
    key_code      VARCHAR(255) NOT NULL COMMENT '语言key（中文key or 语义key）',
    module        VARCHAR(100) DEFAULT '' COMMENT '模块（order/device/ui）',
    description   VARCHAR(255) DEFAULT '' COMMENT '备注说明',
    is_active     TINYINT DEFAULT 1,
    created_at    DATETIME,
    updated_at    DATETIME,
    UNIQUE KEY uk_key (key_code)
);
```

### 8.2 翻译表

```json
CREATE TABLE i18n_translation (
    id            BIGINT PRIMARY KEY AUTO_INCREMENT,
    key_id        BIGINT NOT NULL,
    lang          VARCHAR(20) NOT NULL COMMENT '语言（en/zh-CN/ja）',
    content       TEXT NOT NULL COMMENT '翻译内容（支持模板/DSL）',
    
    tenant_id     BIGINT DEFAULT 0 COMMENT '租户ID',
    
    version       INT DEFAULT 1,
    is_active     TINYINT DEFAULT 1,
    
    created_at    DATETIME,
    updated_at    DATETIME,

    UNIQUE KEY uk_key_lang_tenant (key_id, lang, tenant_id)
);
```
