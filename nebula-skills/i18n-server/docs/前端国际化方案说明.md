# 前端国际化方案说明

## 目标

本方案基于 vue 的 `i18n` ，结合业务自定义逻辑，解决以下问题：

*   降低开发接入成本：开发时直接写中文，不需要先设计一套英文 key
    
*   保持代码可读性：业务代码里看到的就是实际中文语义，降低理解门槛
    
*   避免无用词条堆积：代码中移除的文案可以从语言包中自动清理
    
*   兼顾多种使用场景：既支持 Vue 组件，也支持路由、常量、枚举等非组件文件
    
*   支持接入平台翻译：提供`vue-i18n-kit-sy` npm包，通过脚本自动扫描、导入导出词条
    

## 2. 方案概览

1.  在页面、脚本、路由、常量等位置直接写 key
    
2.  通过 `t('key')`、`$t('key')` 或 `trans('key')` 标记这些词条
    
3.  中文语言包默认使用 key 本身，其他语言包补充翻译内容
    
4.  运行时由 Vue i18n 根据当前语言返回对应文案
    
5.  执行词条抽取脚本扫描 src 目录下的代码
    
6.  提供脚本把扫描到的 key 自动写入 `src/i18n/locales/*.json`
    
7.  提供脚本对接平台翻译工具进行词条翻译归档、回写到项目语言包
    

## 3. 目录结构

核心目录如下：

```json
src/
  i18n/
    index.ts          # 创建 vue-i18n 实例
    messages.ts       # 语言包与 fallback 配置
    element.ts        # Element Plus 的 locale 映射定义
    locales/
      zh_CN.json      # 中文语言包
      en_US.json      # 英文语言包
      ru_RU.json      # 俄语语言包
      lang.xlsx       # 对接平台翻译
  stores/
    lang.ts                  # 语言切换 store
i18n-extract.config.ts       # 词条抽取配置
package.json
```

各文件作用：

*   `src/i18n/index.ts`：创建 Vue I18n 实例
    
*   `src/i18n/messages.ts`：聚合语言包、语言类型和 fallback 规则
    
*   `src/i18n/locales/*.json`：各语言包
    
*   `i18n-extract.config.ts`：抽取、导出、导入共用配置
    
*   `lang.xlsx`：执行脚本进行语言包词条导出，平台翻译工具翻译完后执行脚本更新翻译到对应语言json文件内
    

## 4. 运行机制

### 4.1 i18n 实例初始化

#### 4.1.1安装插件(安装最新版即可，旧i18n版本需要卸载)

```json
pnpm add vue-i18n-kit-sy vue-i18n
```

项目在 `src/i18n/index.ts` 中创建 `Vue i18n` 单例，并完成以下配置：

*   使用 `Composition API` 模式，即 `legacy: false`
    
*   启用 `globalInjection: true`，因此模板里可以直接使用 `$t`
    
*   配置 `fallbackLocale`
    
*   配置数字格式化 `numberFormats`
    
*   配置日期格式化 `datetimeFormats`
    
*   配置俄语复数规则 `pluralRules`
    

注意：

*   运行时使用的 locale 是 `zh-CN、en-US、ru-RU`
    
*   语言包文件名是 `zh_CN.json、en_US.json、ru_RU.json`
    

#### 4.1.2 创建 `**src/i18n/index.ts**`

ps：如果`import { createAppI18n } from 'vue-i18n-kit-sy/runtime'`红色提示找不到模块，需要修改`tsconfig.json`里的`moduleResolution` 配置为`bundler`

"moduleResolution": "bundler"

```typescript
import { createAppI18n } from 'vue-i18n-kit-sy/runtime'
import { LANG_STORAGE_KEY, fallbackMap, messages } from './messages'

export default createAppI18n({
  defaultLocale: 'zh-CN',
  localeStorageKey: LANG_STORAGE_KEY,
  fallbackMap,
  messages,
  missingWarn: false,
  fallbackWarn: false,
  globalInjection: true,
})
```

#### 4.1.3 创建 `**src/i18n/messages.ts**`

文件名和运行时语言编码不是同一种分隔符风格，。`src/i18n/messages.ts` 写了它们之间的映射。

```ts
import zhCN from './locales/zh_CN.json'
import enUS from './locales/en_US.json'
import type { LocaleMessages } from 'vue-i18n-kit-sy/runtime'

export type Lang = 'zh-CN' | 'en-US'
export const LANG_STORAGE_KEY = 'lang'

export const messages: Record<Lang, LocaleMessages> = {
  'zh-CN': zhCN,
  'en-US': enUS,
}

export const fallbackMap: Partial<Record<Lang, Lang[]>> = {
  'en-US': ['zh-CN'],
  'zh-CN': ['en-US'],
}
```

#### 4.1.4  创建 `**i18n-extract.config.ts**`

```ts
import { defineI18nExtractConfig } from 'vue-i18n-kit-sy/extractor'

export default defineI18nExtractConfig({
  srcDir: 'src',
  localeDir: 'src/i18n/locales',
  languages: [
    { code: 'zh_CN', defaultValue: 'key' },
    { code: 'en_US', defaultValue: '' },
    { code: 'ru_RU', defaultValue: '' },
  ],
  sort: true,
  removeUnused: true,
})
```

#### 4.1.5 创建`**src/store/lang.ts**`

```typescript
import { defineStore } from 'pinia'
import i18n from '@/i18n'
import { LANG_STORAGE_KEY } from '@/i18n/messages'

import type { Lang } from '@/i18n/messages'

export const useLangStore = defineStore('lang', {
  state: () => ({
    lang: 'zh-CN' as Lang,
  }),

  actions: {
    setLang(lang: Lang) {
      i18n.global.locale.value = lang
      this.lang = lang
      localStorage.setItem(LANG_STORAGE_KEY, lang)
    },
    init() {
      const saved = (localStorage.getItem(LANG_STORAGE_KEY) as Lang) || null
      if (saved) {
        i18n.global.locale.value = saved
        this.lang = saved
      }
    },
  },
})
```

### 4.2 应用挂载`**main.ts**`

```ts
import { createApp } from 'vue'
import App from './App.vue'
import i18n from './i18n'

createApp(App).use(i18n).mount('#app')
```

项目在 `src/main.ts` 中通过 `app.use(i18n)` 注册国际化插件，所以：

*   模板里可以直接用 `$t`
    
*   setup 中可以通过 `useI18n()` 获取`t`
    

同时，项目在 `src/App.vue` 中使用了 `el-config-provider`，并根据当前语言动态切换 `Element Plus locale`。

Element Plus 的 `locale` 映射定义在`src/i18n/element.ts` 中。

### 4.3 语言切换

语言切换逻辑在 `src/stores/lang.ts` 中：

*   `setLang(lang)` 会同步修改 `i18n.global.locale.value`
    
*   同时把当前语言写入 `localStorage`
    
*   `init()` 会在应用启动时恢复上次选择的语言
    
*   页面刷新后仍能保留上次选择的语言
    

由于 App.vue 中的 `el-config-provider` 直接依赖 `langStore.lang`，所以当前语言变化后：

*   Vue i18n 文案会切换
    
*   Element Plus 内置组件文案也会同步切换
    

## 5. 业务代码编写

### 5.1 Vue 模板中使用

模板里推荐直接使用 `$t`：

```json
<p>{{ $t('保存') }}</p>
<el-table-column :label="$t('时间')" />
```

这是最常见、也最容易被抽取脚本识别的写法。

### 5.2 script setup 或 ts 中使用

在组件脚本中使用 `useI18n()` 获取`t`：

```json
import { useI18n } from 'vue-i18n'

const { t } = useI18n()

const saveText = computed(() => t('保存'))

```

如果文案需要参与计算属性、消息提示、标题更新等逻辑，优先使用这种方式。

### 5.3 非组件文件中使用

像路由、常量、枚举映射这类文件，通常拿不到 `useI18n()`，这时不要直接翻译，而是先用 `trans()` 标记词条：

```json
import { trans } from 'vue-i18n-kit-sy/runtime'

meta: {
 title: trans('首页')
}
```

`trans()` 的作用只有一个：让抽取脚本识别这是一条国际化 key

它在运行时只是原样返回字符串，不做翻译。真正显示时，仍然要在组件里再调用 `$t()`：

`{{ $t(route.meta?.title as string) }}`，比如项目的路由菜单里可以这样使用。

### 5.4 带变量的文案

项目支持占位符变量：

```json
t('{user} 于 {date} 下单，金额 {amount} 元', {
 user: '张三',
 date: '2026-01-01',
 amount: 100,
})
```

翻译时必须保留同名占位符，否则运行时无法正确替换。

例如英文语言包可以写成：

```json
{
 "{user} 于 {date} 下单，金额 {amount} 元": "{user} placed an order of {amount} USD on {date}"
}

```

### 5.5 复数文案

项目使用 `Vue i18n` 的复数字符串格式，**语言包中通过 | 分隔不同复数形式**。

例如英文：

```json
{
 "删除{count}条": "Delete {count} item | Delete {count} items"
```

调用方式：

```json
t('删除{count}条', { count: 1 })
t('删除{count}条', { count: 15 })
```

俄语也可以支持更多复数形态。

### 5.6 同词不同义的语境文案

如果中文相同，但语义不同，可以通过“正文 + 语境”的方式区分 key：

```json
$t('打开 || 文件')
$t('打开 || 灯')
$t('打开 || 开关')
```

中文语言包中可以统一翻成“打开”，但英文语言包可以分别翻译为：

*   Open
    
*   Turn on
    
*   Switch
    

这种方式适合处理一词多义问题。

## 6. 语言包维护

语言包位于 `src/i18n/locales` 目录

### 6.1 中文语言包

中文语言包 **zh\_CN.json** 的默认值就是 key 本身，例如：

```json
{
 "保存": "保存",
 "首页": "首页"
}
```

这是抽取脚本自动生成的。

### 6.2 其他语言包

英文、俄语等语言包在首次抽取时会自动生成空字符串：

```json
{
 "保存": "",
 "首页": ""
}
```

后续由开发或翻译人员补齐真实翻译。

### 6.3 fallback 规则

`src/i18n/messages.ts` 中配置了 **fallback** 关系：

*   en-US 缺失时回退到 zh-CN
    
*   zh-CN 缺失时回退到 en-US
    
*   ru-RU 缺失时回退到 en-US
    

因此：

*   某个英文 key 没翻译时，界面会退回中文
    
*   某个俄语 key 没翻译时，优先展示英文
    

## 7. 词条<font color="#ff0000">抽取</font>机制

### 7.1 执行命令

当前项目通过根目录脚本执行抽取：

`npm run extract:i18n`

**脚本会扫描 src/\*\*/\*.{js,ts,vue}。**

![[Pasted image 20260505142211.png]]

### 7.2 脚本

词条抽取脚本处理流程如下：

1.  扫描 src 下所有 js、ts、vue 文件
    
2.  对 .vue 文件分别解析 template、script、script setup
    
3.  对 JS/TS 代码做 AST 分析
    
4.  收集可识别的国际化调用中的第一个字符串字面量参数
    
5.  合并已有语言包，保留已翻译内容
    
6.  自动删除未使用的旧 key
    
7.  对 key 排序后重新写回语言包
    
8.  输出新增、删除、总数等扫描结果
    

### 7.3 当前支持识别的写法

脚本目前支持以下模式：

```json
t('保存')
$t('保存')
this.$t('保存')
i18n.global.t('保存')
trans('首页')
```

在 Vue 模板里，这些调用如果出现在以下位置，也能被识别：

*   插值表达式，如 `{{ $t('保存') }}`
    
*   指令表达式，如 `:label="$t('时间')"`
    
*   其他包含 JS 表达式的模板绑定
    

### 7.4 抽取脚本的关键限制

脚本只会抽取“第一个参数是字符串字面量”的调用。因此以下写法不建议使用：

```json
t(text)
t(prefix + suffix)
t(`保存${name}`)
t(getLabel())
```

原因是这类写法在静态扫描阶段无法稳定提取 key。

这也意味着类似下面这种动态 key，当前不会被自动抽取：`$t(data.name)`

如果 key 来自 JSON、接口返回值或运行时拼装结果，需要保证这些 key 已经通过其他静态方式被扫描到，否则语言包里不会自动生成对应项。

建议改成下面这种可抽取方式：

```json
t('保存')
t('{name} 保存成功', { name })
```

### 7.5 自动新增与自动删除

执行脚本后：

*   新增 key 会自动写入所有语言包
    
*   已存在翻译会被保留
    
*   代码中已经不再使用的 key 会从语言包中自动清理(可配置)
    

这语言包应当以脚本结果为准，不建议手工长期维护无引用词条。

## 8. <font color="#ff0000">开发流程</font>

建议按下面的顺序开发：

1.  在业务代码中直接写中文 key
    
2.  组件内使用 `t` 或 `$t`
    
3.  非组件文件使用 `trans`
    
4.  开发完成后执行 `npm run extract:i18n`
    
5.  检查 `src/i18n/locales/zh_CN.json` 是否新增了对应词条
    
6.  补齐 `en_US.json、ru_RU.json` 中的翻译内容
    
7.  切换不同语言自测页面展示效果
    

**示例：**

### 8.1 第一步：在代码中写词条

```json
<script setup lang="ts">
import { useI18n } from 'vue-i18n'

const { t } = useI18n()

function handleSubmit() {
 console.log(t('提交成功'))
}
</script>

<template>
 <el-button>{{ $t('提交') }}</el-button>
</template>
```

### 8.2 第二步：执行抽取脚本

```json
npm run extract:i18n
```

### 8.3 第三步：补充语言包

脚本执行后，语言包中会新增类似内容：

```json
{
 "提交": "",
 "提交成功": ""
}
```

导出规则：

*   默认文件路径是 `localeDir/lang.xlsx`

*   固定包含 `词条`、`comment`
    
*   后面的语言列按 `i18n-extract.config.ts` 中的 `languages` 生成

*   `zh_CN`

*   `ru_RU`

```json
"打开 || 开关": "打开"
```

*   `词条`：`打开`
    
*   `comment`：`开关`

```typescript
执行：
pnpm run import:i18n
或：
pnpm exec i18n-extract excel:import i18n-extract.config.ts src/i18n/locales/lang.xlsx
```

![image.png](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/4maOgXbNBoGVmlWN/img/5f8e1c4f-1208-47b2-8e89-3332e341823d.png)

导入规则：

*   读取第 2 行表头
    
*   用 `词条 + comment` 匹配 `zh_CN.json` 中原始 key
    
*   按配置里的语言列把翻译写回对应 JSON
    
*   空白单元格不会覆盖已有翻译
    
*   如果 Excel 中新增了一条词条，只要这条词条所在语言属于配置里的 `languages`，导入时也会自动把它补进 JSON
    

注意：

*   导入不会按 Excel 中额外多出的语言列自动扩语言种类
    
*   未在 `i18n-extract.config.ts` 里声明的语言，不会被处理
    
*   导出的xlsx文件多语言表头按照`i18n-extract.config.ts`配置的语言命名，导入到平台翻译工具的时候，需要改成平台翻译工具约束的表头。比如：`en_US`改成**英文翻译**，`ru_RU`改成**俄文翻译**

## 10.新增语言如何处理

如果要新增一种正式语言，例如 `ja_JP`，至少需要同步调整：

`i18n-extract.config.ts` 中的 `languages`

`src/i18n/messages.ts` 中的语言类型、语言包导入和 fallback 配置

如果项目接了 Element Plus、日期格式、数字格式，也要一起补齐

## 11. 文本常见场景

### 11.1 路由标题

在路由配置中使用 `trans()` 标记：

```json
meta: {
 title: trans('用户管理')
}
```

在展示处再使用 `$t()`：`{{ $t(route.meta?.title as string) }}`

### 11.2 常量枚举

状态映射、下拉选项、表格状态等常量，推荐在定义处使用 `trans()`：

```json
export const STATUS_MAP = {
 '1': trans('待确认'),
 '2': trans('待推送'),
}
```

使用时再翻译：

`{{ $t(STATUS_MAP['1']) }}`

### 11.3 页面标题和消息提示

像 `document.title、ElMessage` 这类运行时文本，建议在触发时调用 t()，不要提前缓存成固定字符串。

例如：

```json
ElMessage({
 message: t('{val} 切换成功', { val }),
 type: 'success',
})

document.title = t('多语言项目demo')
```

## 12. 注意事项

### 12.1 不要把未标记的中文直接写进界面

例如下面这种普通文本：

```json
<p>保存</p>
```

不会被抽取脚本识别，也不会自动翻译。

应改成：

```json
<p>{{ $t('保存') }}</p>
```

### 12.2 不要动态拼 key

不要写：

```json
t('保存' + type)
```

建议改成完整句子或明确枚举映射，否则脚本无法稳定抽取。

### 12.3 占位符名称前后要一致

源文案和翻译文案里的变量名必须一致，例如 `{count}、{user}、{date}`，否则替换会失败。

### 12.4 语言包文件建议只改 value，不改 key

key 来自代码扫描结果。如果直接手改 key，下一次执行抽取脚本时可能会被覆盖或清理。

### 12.5 新增语言时需要同步修改多处配置

如果后续要新增语言，例如日语，需要至少同步修改以下位置：

1.  `i18n-extract.config.ts` 中的 `languages`（**支持抽取的语言列表**）
    
2.  `src/i18n/messages.ts` 中注册语言包
    
3.  `src/stores/lang.ts` 中扩展 Lang 类型
    
4.  页面语言切换下拉选项
    
5.  如有需要，补充 `numberFormats、datetimeFormats、fallbackMap`
    

### 12.6 Element Plus 文案切换依赖 locale 映射完整性

当前项目通过 `src/i18n/element.ts` 维护语言到 `Element Plus locale` 的映射，再由 `App.vue` 中的 `el-config-provider` 动态注入：

*   新增业务语言时，也要同步补充对应的 `Element Plus locale` 映射
    
*   如果某个语言没有对应映射，`Element Plus` 内置文案无法跟随业务语言正常切换
    

## 13. 总结

当前项目的国际化核心原则可以概括为：

*   写文案时，中文就是 key
    
*   组件里用 `t / $t`
    
*   非组件里用 `trans`
    
*   语言包不手工建 key，统一靠 `pnpm extract:i18n`自动生成
    
*   `lang.xlsx` 是项目语言包和平台翻译工具的中间产物，通过脚本导入导出
