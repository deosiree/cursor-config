# 策略-新增新i18n

用于当前模块没有旧 i18n，或旧 i18n 已经彻底退化完成，只需要接入新 i18n 方案时使用。

## frontmatter 模式

本节点采用“本地中文模式”：

- `name` 使用中文 skill 名
- `description` 使用中文触发描述

## 节点定位

- 属于 `intention-skills/`
- 只处理“新增新 i18n”阶段
- 不再回头处理旧 i18n 冲突治理

## 主 few-shot 来源

本节点的主 few-shot 事实来源固定优先参考：

- `references/skill历史版本对应-沉淀为子skill及其few-shot.md`
- 其中 `microfb` 在旧 i18n 退化完成后的第二阶段

这条真实路径包含：

- `新i18n-安装插件`
- `新i18n-样板代码`
- `新i18n-基座-语言选择器`
- `新i18n-补充翻译json`
- `新i18n-Vue模板中使用$t()`
- `新i18n-纯ts中用i18n.global.t`
- `新i18n-ts或script setup中使用t(),可以包变量`
- `新i18n-编译宏外的定义点包trans+消费点包t`
- `新i18n-动态拼接：业务层回调t到函数定义`

## 输出重点

- 新增阶段的功能 skill 序列
- 为什么当前可以跳过旧 i18n 相关策略
- 新增前后链路与验证点

## 使用示例

```text
当前模块从未做过 i18n，只想接入新的 i18n 方案。
```

```text
旧 i18n 已经退化完了，参考 microfb 第二阶段，帮我规划新增新 i18n。
```

```text
请直接给我新增阶段推荐的功能顺序，并说明为什么不需要再回到 legacy 策略。
```

```text
我还不能确认旧 i18n 是否已经完全退化，你先判断；如果已经退化完了，再按新增新 i18n 阶段给我后续顺序。
```

## 边界提醒

- 如果用户只想知道“当前一步该选哪个功能 skill”，应优先进入 `[[../路由-选择功能子skill]]`
- 如果用户需要比较多个迁移方案、改动面和推荐路径，应优先进入 `[[../编排-i18n迁移]]`
- 如果用户还不能确认是否已经进入“无旧 i18n”状态，应先消费 `[[../分析-i18n链路]]`
