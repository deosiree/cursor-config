# 编排-i18n迁移

这个节点是套件内的总编排器，不是顶层总入口。

## frontmatter 模式

本节点采用“本地中文模式”：

- `name` 使用中文 skill 名
- `description` 使用中文触发描述

## 典型场景

- 同一个仓库里既有旧 runtime，又有新 runtime 试点
- 不同模块状态不一致，无法直接进入单个迁移节点
- 需要比较多个迁移方案、改动面、功能序列与推荐路径

## 与分析链路的关系

本节点不是默认假设链路已经清楚。

- 若链路不明确，应先消费 `[[../分析-i18n链路]]`
- 若已有高置信度链路产物，则直接进入方案矩阵

## 输出重点

- 候选方案矩阵
- 推荐方案
- 每个方案的 `analysisBasis`
- 改动面大小与明细
- 前后链路
- 功能 skill 序列

## 模板定位

本节点属于新增型 skill，优先使用 `mvp/snapshot`，输出方案矩阵、推荐理由和下一轮动作，而不是直接给源码 before/after。

## 使用示例

```text
帮我比较这个仓库接新 i18n 的几个方案，给出改动面、前后链路和推荐路径。
```

```text
我想知道是先退化再新增，还是带中间态收敛更合适，顺便给出理由。
```

```text
当前链路我也说不清，但我还是需要一个总方案，你先分析再做推荐。
```

## 边界提醒

- 如果用户只想知道当前一步进入哪个功能 skill，应优先进入 `[[../路由-选择功能子skill]]`
- 如果用户只想做链路摸底，不要直接给方案矩阵，应优先进入 `[[../分析-i18n链路]]`
- 如果用户已经明确只有“无旧 i18n 后的新增阶段”，应优先进入 `[[../策略-新增新i18n]]`
