# 迁移-退化->新增(无中间态)

用于旧 i18n 仍深度参与运行、改动面较大、且不推荐长期保留中间态时的迁移策略。

## frontmatter 模式

本节点采用“本地中文模式”：

- `name` 使用中文 skill 名
- `description` 使用中文触发描述

## 与分析链路的关系

若以下事实不明确，应先消费 `[[../分析-i18n链路]]`：

- 是否仍存在旧 runtime
- 旧 i18n 的耦合深度
- 是否确实不适合保留中间态

## 与其他 skill 的关系

- 退化动作通常会进入 `feature-skills/旧i18n-硬切静态化`
- 退化完成后，新增阶段交给 `[[../策略-新增新i18n]]`

## 使用示例

```text
旧 i18n runtime 还深度参与运行，先退化旧方案，再新增新 i18n。
```

```text
我不想长期保留中间态，哪怕改动面大一点，也要先把旧链路拿掉。
```

```text
请解释为什么这个场景不适合走“有中间态收敛”的路径。
```

## 边界提醒

- 如果用户已经没有旧 i18n，只想规划新增阶段顺序，应优先进入 `[[../策略-新增新i18n]]`
- 如果用户接受中间态且重点是小改动面，应优先进入 `[[../迁移-收敛旧到新-有中间态]]`
- 如果用户只想知道当前一步进哪个功能节点，应优先进入 `[[../路由-选择功能子skill]]`
