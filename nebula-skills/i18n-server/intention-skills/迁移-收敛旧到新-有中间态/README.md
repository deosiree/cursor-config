# 迁移-收敛旧到新(有中间态)

用于旧 i18n 仍存在，但改动面较小、允许保留中间态，并希望逐步把旧方案收敛到新方案的场景。

## frontmatter 模式

本节点采用“本地中文模式”：

- `name` 使用中文 skill 名
- `description` 使用中文触发描述

## 与分析链路的关系

若无法确认：

- 是否适合保留中间态
- 哪些功能风险会阻断收口

应先消费 `[[../分析-i18n链路]]`。

## 输出重点

- 中间态描述
- 功能 skill 序列
- 验证与停机条件

## 使用示例

```text
这个仓库 legacy 负担不算太重，我接受中间态，帮我规划逐步收口到新 i18n。
```

```text
我更关心改动面小，不想先大规模退化旧方案。
```

```text
请解释为什么这个场景更适合保留中间态，而不是先退化再新增。
```

## 边界提醒

- 如果 legacy 负担很重且不适合长期保留接缝，应优先进入 `[[../迁移-退化到新增-无中间态]]`
- 如果当前已经没有旧 i18n，只想规划新增阶段，应优先进入 `[[../策略-新增新i18n]]`
- 如果用户只想知道当前一步该改哪个功能点，应优先进入 `[[../路由-选择功能子skill]]`
