# Feature Deprecation

用于在仓库落地新国际化方案前，先系统性退化旧 i18n 方案，把消费侧从旧 runtime 脱钩，回归到可验证的硬编码/静态常量中间态，并保留可复用词条资产。

## 适用场景

- 仓库已经存在 `src/lang`、`src/locales`、旧 `vue-i18n` 包装层或历史翻译常量。
- 需要把“运行中的旧方案”降级为“只读遗产资产”，避免和新方案并存冲突。
- 需要分批执行：先完成退化并验证开发环境正常，再单独提交一次代码，之后再执行迁移。
- 需要把旧词条、旧路由标题、旧提示文案改名备份，供新方案迁移时直接消费。

## 输入

- `feature-analysis` 输出的旧链路分析文档。
- 目标仓库源码。
- 旧 i18n 入口文件、语言包、路由翻译工具、语言切换 store。
- `i18n-server/docs` 中的新方案文档。

## 输出

- 旧 i18n 入口清单。
- 消费侧脱钩清单：哪些 `t/$t/useI18n/i18n.global.t` 需要先回退为硬编码或静态常量。
- 退化策略：删除、保留、改名备份、只读兼容。
- 旧资产映射：哪些词条/常量可以被新方案直接消费。
- `feature-migration` 可直接使用的迁移契约。

## 与 feature-migration 的关系

- 本 skill 必须建立在 `feature-analysis` 已完成的前提上。
- 是否真的需要本 skill，应该先由 `feature-strategy` 判断。
- 本 skill 只处理旧方案退场与消费侧脱钩，不负责接入新 runtime。
- 本 skill 的输出应成为 `feature-migration` 的输入。

## 模板说明

`template` 下提供：

- 清单型模板，方便 agent 逐项执行。
- `microfb` 的旧源码、脱钩后的中间态示例、以及 legacy 冻结示例，方便人类直接看最终形态。
