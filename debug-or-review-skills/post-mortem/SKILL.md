# 目标
从“事件描述”转为“可执行改进计划”。

## 执行步骤
1. 还原时间线（发现、响应、缓解、恢复）。
2. 明确影响范围（用户、功能、时长、数据）。
3. 分析根因（直接原因与系统性原因）。
4. 总结有效动作与失效动作。
5. 形成改进项（责任人、截止时间、验收标准）。

## 输出结构
1. 事件摘要。
2. 时间线。
3. 根因分析。
4. 行动项（短期/长期）。
5. 防复发机制。

## 约束
1. 避免归因到个人；聚焦系统与流程。
2. 每条行动项必须可验证。

## 外部最佳实践校验（必做）
1. 无论是否使用本 skill，都先进行一次 web search，确认当前任务的最佳实践与最新约束。
2. 优先来源顺序：官方文档 > 标准组织/维护者仓库 > 高质量技术文档。
3. 至少引用 2 个来源；高风险任务（生产、权限、安全、数据）至少 3 个来源交叉验证。
4. 输出中必须包含：来源链接、采纳点、未采纳点与原因。
5. 若检索结果不足或冲突，必须明确不确定性并给出保守方案。
