# 分析-i18n链路

用于在退化、迁移、总编排或单次功能路由之前，先还原仓库当前 i18n 是如何工作的。

## frontmatter 模式

本节点采用“本地中文模式”：

- `name` 使用中文 skill 名
- `description` 使用中文触发描述

## 节点定位

这是 `intention-skills/` 中的公共事实层节点：

- 用户可以直接使用它
- 其他意图 skill 也可以把它当作前置能力消费
- 它的输出不只服务“分析报告”，还服务“后续能否继续判断”

## 适用场景

- 仓库已存在一套 i18n 方案，但链路分散在 `runtime`、`store`、`router`、`utils`、`components` 中
- 用户不知道当前链路怎么跑，但想继续做策略、总编排或功能路由
- 需要确认是否仍存在旧 runtime、是否已处于中间态、是否适合直接新增新 i18n

## 输出

- 当前 i18n 链路说明文档
- 至少一张 `sequenceDiagram`
- 参与者、变量、函数、文件的源码落点表
- `chainConfidence`
- `legacyPresenceAssessment`
- `newI18nReadinessAssessment`
- `candidateNextIntentions`
- `candidateFeatureRisks`
- `analysisBlockingUnknowns`

## 与其他 skill 的关系

- `编排-i18n迁移` 在链路不明确时应先消费本节点
- `路由-选择功能子skill` 在 gap 不明确时应先消费本节点
- 迁移类策略与新增策略在事实不足时也应先消费本节点

## 模板说明

`template/` 下提供：

- 通用时序图模板
- 通用源码落点模板
- 示例分析文档

本节点的模板优先服务事实沉淀，不直接给出源码修改 before/after。

## 使用示例

```text
我不知道当前 i18n 是怎么跑的，先帮我把链路、参与者和时序图画出来。
```

```text
我想选迁移策略，但现在不清楚旧 runtime 还在不在，先做链路分析。
```

```text
我只知道下一步要改 i18n，但不知道该进哪个功能 skill，先分析事实再判断。
```

```text
我想做总方案比较，但当前链路不清楚，先把事实盘清楚再说。
```

## 边界提醒

- 如果用户已经明确需要多个方案比较，应在分析完成后进入 `[[../编排-i18n迁移]]`
- 如果用户已经明确只差一个功能点，应在分析完成后进入 `[[../路由-选择功能子skill]]`
- 如果用户已经确认没有旧 i18n，只差新增阶段能力，可在分析完成后进入 `[[../策略-新增新i18n]]`
