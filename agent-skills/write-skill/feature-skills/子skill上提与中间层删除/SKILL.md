# 核心任务
识别没有独立职责的中间层，把真正承担能力的节点上提到合适层级，减少空壳目录和无效包装。

## 何时触发
- 某一层目录只是在多包一层，没有额外判断职责。
- 真正的执行内容都在更深层，当前层只有转发或占位说明。
- 子 skill 的组织方式让路由成本高于实际收益。

## 输入 / 前置条件
- 当前目录结构
- 各层职责说明
- 现有引用关系

## 输出
- `redundantLayers`
- `promotedSubskills`
- `removedMiddleLayers`
- `syncPoints`

## 边界
- 它负责层级整理，不负责重命名所有节点。
- 如果问题是主 `SKILL.md` 过重，优先配合 `[[../主SKILL瘦身与下沉/SKILL.md]]`。
- 如果结构是否需要拆层仍不明确，先回到 intention 节点做判断。

## 常用配套
- `[[../中文技能命名收敛/SKILL.md]]`
- `[[../主SKILL瘦身与下沉/SKILL.md]]`
- `[[../references与evals补全/SKILL.md]]`

## 使用示例
```text
这个 skill 套件里有一层目录只是多包了一层，但没有独立判断职责。
使用 $子skill上提与中间层删除 识别应删除的中间层，并说明哪些子skill 应上提。
```
