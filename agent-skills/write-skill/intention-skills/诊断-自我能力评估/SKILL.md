# 核心任务

在写 skill 实跑完成后，对 write-skill 自身做能力自检，判断是否需要新增或调整子 skill。

## 何时触发

- `编排-skill质量迭代` 流程末尾
- 用户说"检查 write-skill 是否需要新增功能"

## 检查点

| 触发点 | 检查内容 |
|--------|----------|
| 路由决策时 | 当前 intention-skill 是否覆盖所有任务类型？是否有无法路由的请求？ |
| 模板生成时 | 当前 template 是否满足新 skill 的需求？有无未覆盖的模板类型？ |
| Darwin 评估时 | 评估流程是否需要新增评估维度？baseline 评分是否偏低？ |
| 用户反馈时 | 用户是否提出新的 skill 改造需求类型？意图路由表是否够用？ |

## 流程

### Step 1：遍历检查点

```
对 4 个检查点逐一检查：
  ├── 能正常处理 → 记录 OK
  └── 发现功能缺口 → 记录到缺口清单
```

### Step 2：防误触过滤

```
连续<3次同一缺口 → 记录但暂不触发
连续≥3次 → 进入 Step 3
```

### Step 3：分类 & 输出

```json
{
  "缺口数": 1,
  "缺口列表": [
    {"类型": "intention-skill", "描述": "缺少对'批量多skill生成'请求的路由"}
  ],
  "触发迭代": true
}
```

## 关键约束

- 只评估 write-skill 自身，不评估用户写的 skill
- 连续 3 次触发才执行，防误触
