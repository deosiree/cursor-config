# Markdown 格式规则

## 用途

这份文档只负责约束 skill 套件产物的 Markdown 结构正确性，不负责定义 skill 的业务能力。

主 `SKILL.md` 保持轻量；需要格式规则时，从这里和 `[[../assets/skill-output-checklist.md]]` 读取。

## 标题空行规则

- 所有标题前后都要有空行。
- frontmatter 结束后，正文第一个标题前保留一个空行。
- 列表、代码块、表格与相邻标题之间都要有空行。

这条规则主要用于避免 `MD022`。

## 单文档 H1 策略

- `README.md`、`SKILL.md` 默认保留单一 H1。
- 如果文档已经通过 frontmatter 中的 `名称`、`title` 等属性承载标题语义，正文默认不再写总 H1。
- 一个 Markdown 文档中不允许出现多个顶级 H1。

这条规则主要用于避免 `MD025`。

## 正文首行标题规则

- 这不是 Markdown 语法的硬性要求，而是 markdownlint 的 `MD041` 规则约束。
- frontmatter 不算正文；若启用了 `MD041`，则 frontmatter 之后的第一行正文应为顶级标题。
- 对 `README.md`、`SKILL.md` 这类说明型文档，默认满足 `MD041`，即在 frontmatter 后提供一个 H1。
- 对属性头已经完整承载标题语义的模板、样本、边界文件，可以不强制沿用 `MD041`；若团队 lint 配置未放宽该规则，则应补一个合适的 H1，或统一调整 lint 配置。

## frontmatter 文档默认策略

- 对带 frontmatter 的模板、样本、边界文件：
  - 如果属性头已经能表达文档名，正文从下一层标题开始。
  - 不要再补一个只起展示作用的总标题。
- 对带 frontmatter 的 `SKILL.md`：
  - 可以保留一个 H1，用于 agent 快速识别正文主题。
- 对带 frontmatter 的普通说明文档：
  - 先判断标题语义是否已经在属性头中表达；若已表达，优先不写正文总 H1。

## 常见结构约束

- 标题层级要连续，不要从 `#` 直接跳到 `###`，除非上层语义确实由模板或固定块承载。
- 代码块前后保留空行。
- 表格前保留空行，表格后再接正文时也保留空行。
- 清单项内若包含代码块或表格，优先拆成独立段落，避免可读性和 lint 双重问题。

## 套件内的默认实践

- 给维护者看的说明文档：
  - 优先保留单一 H1
- 给 agent 读的 `SKILL.md`：
  - 保留单一 H1
- 给人类仿写的样本、边界文件、试跑文档：
  - 若属性头已承载标题，正文不写总 H1

## 交付前检查

交付前至少确认：

- 标题上下都有空行
- 每个 Markdown 文件只有单一 H1 或无 H1
- 带 frontmatter 的文档遵守统一标题策略
- 模板、样本、README、SKILL 的标题层级一致

更精简的收尾检查清单见 `[[../assets/skill-output-checklist.md]]`。
