# 核心任务

在逐知识点写作后，检查并建立知识点之间的关联，防止各章节各自为政。

## 何时触发

- `编排-QA沉淀为经验贴` 在写完整篇文章后调用（全篇建模）
- 也可在写每个知识点时适时调用（单知识点关联建模）

## 建模手段

| 场景 | 工具 | 形式 |
|------|------|------|
| 多个概念有层级/派生关系 | Mermaid graph | 纵向分层图（如五层参考模型） |
| 多个概念有时序/调用关系 | Mermaid sequence | 调用链时序图 |
| 多个概念可放进统一场景 | 费曼叙事 | 一个故事串联所有概念 |
| 概念之间有实体-关系映射 | ER图/关系表 | 谁基于谁、谁实现了谁 |
| 概念属于不同层级但容易混淆 | 分层对比表 | 表头=层级，行=概念 |

## 输出

- `relationModel`：选用的建模手段
- `output`：具体的 mermaid 代码块 / 关系表 / 叙事文本
- `placement`：该内容在文档中的插入位置

## 关键原则

- 全文至少有一处"全景图"让读者看清所有概念的位置关系
- 费曼叙事本身也是一种关系建模——故事中角色的互动就是概念的关联
- 不要让每一章的知识点完全孤立，章与章之间应有调用、引用、承接

## 边界

- 不做过度建模——2-3个概念的关系不值得画图，用一句话承接即可
- 建模目的是帮助理解，不是炫技

## 使用示例

```text
知识点：RPC、HTTP、gRPC、JSON-RPC、MCP、FC、Skill、SDK
→ 输出：五层参考模型（Mermaid graph 纵向分层图）
→ 每个概念标注所在层及其与其他概念的基承/派生关系
```
