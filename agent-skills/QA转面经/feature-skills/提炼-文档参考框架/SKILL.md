# 核心任务

提取**结构方法论**；原文以**源文件名**存入对应 structureId 目录。

## 何时触发

- 用户说「提炼这个文档的框架」
- `分析-参考框架就绪` 返回 `need_extract`
- 新文档需入库

## 输入

- `文档路径`：待提炼 .md
- `structureId`（可选）：归入已有结构；缺省则提炼后**新建**目录名（按章节序列命名，禁止领域名）
- 或 `归入已有structureId`：仅 copy 原文，更新样本列表

## 输出

| 产物 | 路径 |
|------|------|
| 结构骨架 | `references/框架结构库/{structureId}/框架说明.md` |
| 原文 | `references/框架结构库/{structureId}/{源文件名}.md`（**不改名** copy） |
| 索引 | 更新 `references/框架结构库/README.md` |

## 流程

```
1. 读源文档，按五维度提炼（钩子/章节/深度/答题/收束）→ 写入或更新 框架说明.md
2. 判定是否与已有 structureId 同构
   - 同构 → 不新建目录，copy 进该目录
   - 异构 → 新建 {structureId}/（用户确认或 Agent 提议结构名）
3. Copy-Item 源文件到目标目录，保留文件名
4. 更新 框架结构库/README.md 样本列表
```

## 提炼维度

（同前：开场钩子、章节组织、技术深度、答题策略、收束升华）

## 边界

- 不评价原文质量
- structureId **禁止**用「前端面经」「吴师兄」等领域/作者名；用结构序列命名
- 样本仅入 `references/框架结构库/{structureId}/`，不改文件名

## 使用示例

```text
提炼 Obsidian/某文.md，结构归入 面试钩子-对比递进-答题收束
→ 更新 框架说明.md（若需）+ copy 原文进该目录

提炼 新文.md，章节为 背景-实现-核心-取舍
→ 新建目录 + 框架说明 + copy 原文
```
