# 框架说明 · 背景-实现-核心-取舍

> structureId = 目录名。偏工程复盘与方案说明，面经钩子可选弱化。

## 章节组织逻辑

```
背景 → 实现 → 核心设计点（3～5）→ 取舍
```

| 章 | 设计意图 |
|----|----------|
| 背景 | 业务痛点、工程问题、为什么要做 |
| 实现 | 最终方案形态、核心 API/模块 |
| 核心 | 每个设计点：为何如此、面试如何讲清 |
| 取舍 | 做了什么/没做什么、适用与不适用场景 |

## 技术深度要求

- 每个核心点可独立成段，避免流水账
- 有依赖选择与替代方案对比（表或短列表）
- 可含代码落点，但以「设计动机」为主

## 与面经结构的差异

- 默认**无**强面试现场钩子；若 `doc_type=面经` 可在背景章末加 1 段追问情境
- 卷尾可用「面试怎么讲本章」代替快问快答（仍建议 K 题对齐契约）

## 收束模式

- 取舍章体现工程判断力
- 可选：新人常背的观点 vs 项目真实决策
