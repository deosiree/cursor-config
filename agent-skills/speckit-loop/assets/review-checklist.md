# 独立审查清单

审查者应未参与该任务实现。若做不到，标注非独立审查。

## 规格符合性

- 每条验收条件是否有实现及测试证据？
- 是否误解需求、遗漏异常边界或实现非目标？
- 是否修改范围外文件或出现无法复核的完成声明？

## 代码质量

- 架构和依赖是否符合现有项目约定？
- 是否引入重复、过度设计、安全/隐私、资源/异常、并发或性能风险？
- 测试是否脆弱或只验证实现细节？

## 结论

- 结论：通过 / 不通过
- Critical / Major 阻塞：
- Minor 建议：
- 复验范围：

## 阶段放行证据

| 阶段 | 放行前证据 |
|---|---|
| Spec | 用户目标、关键边界、可观察验收、非目标；影响产品行为的歧义已裁定 |
| Plan/Tasks | 验收条件映射到任务；修改范围、依赖、验证方法和回滚路径明确 |
| Task | Red 因目标行为缺失而失败；Green 后相关测试通过；真实命令和退出结果已记录 |
| 规格审查 | 审查者未参与实现；逐条验收映射；阻塞项关闭或明确回流 |
| Converge | 最新文档版本与 diff 对齐；无 Critical/Major；未运行项和风险公开 |

每个阶段的结论必须同时写 status（pass / blocked / conditional）、evidence、owner 和 nextAction。缺少任一项不得写 pass。

## 删除或不可逆数据操作

本套件可以准备方案与验证门禁，不代替用户授权，也不自行执行生产删除。

| 时点 | 必需证据 |
|---|---|
| 执行前 | 已确认规则与授权主体；候选范围、精确数量和可审阅清单；预览查询/筛选版本；关联数据与保留要求；备份及恢复演练结果；dry-run 结果；幂等与回滚方案 |
| 执行后 | 实际成功/失败数量及对象清单；审计记录；恢复抽查结果；与批准范围的差异；未完成项及下一步 |

任一项缺失时为 blocked。用户确认“做删除”但规则、范围或恢复能力仍未验证，不构成放行证据。
