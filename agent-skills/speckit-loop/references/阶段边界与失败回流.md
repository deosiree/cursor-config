# 阶段边界与失败回流

## 阶段责任

| 阶段 | 负责问题 | 主要产物 |
|---|---|---|
| 需求采访 / Clarify | 用户需要什么、哪些边界未定义 | Constitution 约束引用、Spec、验收、非目标 |
| Plan / Tasks / Analyze | 如何实现、先后依赖、每项如何验证 | 技术方案、任务映射、依赖与文档审查 |
| TDD / 独立审查 | 当前 Task 是否按规格正确实现 | 测试证据、diff、分开的规格/质量审查 |
| Converge | 全部实现是否与规格及验收收敛 | 差异清单、修复归属、复验与停止结论 |
| 人类验收 | 产品价值、体验、策略和风险是否接受 | 用户决定或带风险交付结论 |

## 回流判定

| 证据 | 责任节点 | 复验 |
|---|---|---|
| 验收词语无法测试或需求互相冲突 | 需求采访与规格澄清 | Spec/Clarify |
| Task 无需求来源、依赖环、Plan 违反约束 | 计划拆分与依赖排程 | 文档 Analyze |
| 红测试未失败、绿实现仍失败、越权修改 | TDD 实现与独立审查 | 失败测试、相关测试、diff |
| 规格漏项、非目标实现、实现没有测试 | 对应 Task；规格缺陷则先回 Spec | 独立规格审查 |
| 文档说完成但代码缺失，或代码改变但文档未同步 | Converge 后回责任阶段 | 相关测试和 Converge |
| 权限、数据策略、发布/删除等取舍未决 | 人类 | 不允许自动继续 |

## 有限循环

- 一个问题的首次回流必须产生明确修复或新的证据。
- 同一问题连续两轮无实质进展，停止自动迭代并向用户汇报选项。
- Spec 改变后重新分析受影响 Plan、Tasks 和测试；只影响局部时不得无理由重开全部阶段。
- 任意测试、类型、Lint 或构建未运行/失败时，结论必须标出，不可把门禁写成通过。
