# 完整样例：订单批量取消

> 说明性虚构示例。展示 medium/large 门禁，不构成真实业务规则或历史记录。

## 需求与风险

目标：运营人员从订单列表批量发起取消。影响状态和审计；哪些状态允许取消、部分失败如何展示、是否需要二次确认均需用户/业务规则确认。未确认前不得假设允许取消或直接实现。

## Spec 摘要

- 用户故事：有权限的运营人员选择符合条件的订单并发起取消。
- 验收：每种允许状态有明确结果；不允许的状态不被修改并显示可理解原因；每次成功取消留有操作者、时间和来源记录。
- 异常：部分订单失败时展示成功/失败明细，不重复取消已完成项。
- 非目标：自动退款、批量删除、无权限角色授权。

## Plan / Tasks

1. 确认状态与审计契约、失败语义和回滚策略。
2. 服务端取消校验和审计测试。
3. 批量接口与幂等/部分失败处理。
4. 列表选择与结果明细。
5. 规格审查、代码审查、集成测试和人工场景验收。

接口契约未冻结前，2-4 不并行修改同一领域边界；契约确认后仅独立前端任务可并行。

## 执行 / 收敛

每项任务先写行为测试并确认 Red，再做最小 Green 和 Refactor。未参与实现者先逐条核验 Spec，再检查代码质量。Analyze 映射每条验收与任务；Converge 核实代码、异常测试、审计证据和文档。

## 停止条件

允许状态、权限、部分失败语义或业务风险任一项未确认则 STOP。验证命令没有实际运行时不得宣称通过。人类最终确认操作策略、交互与风险。
