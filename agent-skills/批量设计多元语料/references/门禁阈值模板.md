# 门禁阈值模板（默认对齐 v1.1 量级）

> 复制到目标仓 `EVAL_GATES.md` 后按产品改模块名；**改严须 🔴 确认并升版本号**。  
> 脚本常量须与本文一致。

## 建议版本

首次落盘：`v1.1.0`（含跨模块旅程 + md 数量下限）。若产品极小，可经确认用 `v1.0.x` 仅结构门，但须在 EVAL_GATES 写明技术债。

## 默认阈值表

| 键 | 默认 | 说明 |
|----|------|------|
| MIN_VOLUME | 80000 | styles 下去垫汉字总和 |
| MIN_MD_FILES | 200 | 去垫 `.md` 文件数 |
| MAX_FILE | 12000 | 单文件汉字上限 |
| JOURNEY_MIN | 2000 | 单篇旅程汉字 |
| GOLDEN_TOTAL | 120 | 金标合计下限 |
| GOLDEN_TEST | 80 | split=test |
| GOLDEN_RUNTIME | 40 | split=runtime |
| QA_PER_JOURNEY | 6 | 每 journey_id 金标数 |
| SOP_MIN / SOP_COMPLEX_MIN | 1500 / 2500 | 可选 SOP 粒度 |
| skip_shots | true | 文档 Goal 默认可跳过截图 |

## 去垫规则

- `MANIFEST` 中 `status: deprecated|pad` 的 path 不计入
- 文件名匹配 `附录|加厚` 不计入

## 旅程结构锚点

正文须出现（子串即可）：`前置`、`步骤`、`模块切换`、`失败`、`证据`。

## 升版流程

1. 分析-语料缺口与阈值提案 → 提案表  
2. 人确认  
3. `vX.Y.Z` bump + 改脚本常量 + 改本表  
4. 再跑门禁至 PASS
