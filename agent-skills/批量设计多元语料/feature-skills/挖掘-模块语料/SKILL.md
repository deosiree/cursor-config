# 目标

为**单个产品模块**（菜单/页面）写出可检索、可操作的多元文体，深度来自源码与真实流程，不来自字数填充。

## 何时使用

- 编排中的模块扩面
- 用户点名「补工作台 FAQ / 配置 SOP」等单模块

## 输入

- 模块名、路由/视图路径（如 `views/workbench`）
- `styles/` 目标子目录约定：`faq/` `sop/` `troubleshooting/` `scenarios/` `user-manual/` 等
- 覆盖矩阵中该模块行（若有）

## 步骤

1. **定位源码**  
   打开模块入口 Vue/组件：按钮 `okText`、`message.*`、placeholder、Modal 标题、权限 `v-if`。建立「文案 → 文件:符号」证据表（可内嵌文末「证据」节）。

2. **选文体（按缺口）**  
   - FAQ：高频误操作 / 权限 / 空态  
   - SOP：主路径步骤（前置/步骤/失败/证据）  
   - 排障：报错文案驱动  
   - 场景：一条用户故事串起来  
   - 说明书：功能面综述（勿与 SOP 完全重复）

3. **撰写**  
   步骤用编号；失败分支写清触发文案；截图位用 `【待补截图：模块-场景】`，不贴假图。  
   单文件避免堆超门禁 `MAX_FILE` 汉字；过长拆篇，勿附录加厚。

4. **更新 coverage-matrix**  
   模块×文体单元格标已覆盖；不把「有文件」当成门禁 PASS。

5. **自检**  
   全文搜索是否出现源码中不存在的按钮名；有则删或改证。

## 输出

- `styles/<style>/<模块相关>.md`（一篇或多篇）
- 证据路径列表
- 矩阵行更新说明

## 失败分支

| 情况 | 动作 |
|------|------|
| 找不到组件 | 问用户路径；或从路由表反查；仍无则只写「入口未证实」骨架并标 TODO |
| 文案全动态拼接 | 写行为描述 + 证据到拼接头文件；不编完整句 |
| 与旅程重复 | 模块文保本地细节；闭环交给旅程 feature |

## 反例

- 复制通用「点击确定即可」无产品差异
- 文件名含附录/加厚凑量
- 编造不存在的菜单名

## 验收

- 每篇含可核对证据（路径或符号）
- 关键字符串能在 `ui_src_root` 搜到（或显式标注动态）
