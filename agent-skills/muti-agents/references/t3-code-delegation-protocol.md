# T3 Code 委派协议

## 任务

规定通过登记为 t3-code 的宿主适配器发送研发任务时，所需能力检查、传输选择、等待和验收边界。

## 输入

- 当前会话实际的 orchestrator_capabilities 输出。
- 当前可调用的原生 delegate_task 工具，或 ACP MCP 环境与脚本入口。
- schemes-registry.json 中已选方案。
- 经过门禁确认的任务简报。

## 协议

1. **能力探测**：调用当前宿主提供的能力查询，核对目标 provider/model、role、interactionMode、isolation、mode 与选项是否受支持。查询不到时标记未验证。
2. **传输选择**：原生工具可用时优先直接调用 delegate_task。否则仅在注册 ACP 通道已确认且当前平台环境满足要求时使用 delegate-t3-task.mjs；兼容脚本适用于注册支持的 Windows ACP 路径。
3. **请求构造**：--scheme 读取 schemes-registry.json 的默认值；CLI 覆盖仅限显式批准的参数。可附计划文件，确保任务文本包括路径与限制。
4. **敏感信息**：脚本将请求 JSON 的非 ASCII 字符转义后传递；不得因此把凭据加入任务。探测输出只记录环境变量是否存在。
5. **失败语义**：缺少 ACP 环境、可执行文件不存在、子进程启动失败或返回非零码均是失败。记录状态和退出码，停止，不改用未经批准的路径。
6. **异步语义**：mode=async 返回任务已提交不等同于完成。等待宿主完成通知，不轮询 task_status。通知后仍需主 Agent 验收。

## 输出

请求 ID、已验证传输、目标参数、退出码或完成通知、差异和验收结果。

## 边界

该协议解释注册适配器的能力，不把每次会话预先判作可用。原生工具与 ACP 环境都不可用时返回明确阻塞；不得静默切换到单 Agent 执行。

## 示例

能力检查显示当前会话支持 delegate_task 和 S-01 参数时，确认简报后用原生工具发送；如果没有原生工具但 Windows ACP T3_ACP_MCP_CALL 已存在且脚本成功 DryRun，则可按计划运行脚本。真实调用失败时停止并报告失败码。
