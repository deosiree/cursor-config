# 故障排查决策树

快速定位常见问题并提供修复步骤。

---

## 🔍 症状 A：内网 ping 不通

### 决策流程

```
内网 ping 不通 (ping 10.17.196.39 请求超时)
    ↓
【步骤 1】检查静态路由是否存在
    命令：route print | findstr "10.0.0.0"
    ↓
    ┌─ 不存在 → 【修复 A1】添加静态路由
    └─ 存在 ↓
        【步骤 2】检查以太网网关是否可达
            命令：Test-NetConnection 10.17.77.1
            ↓
            ┌─ 不可达 → 【修复 A2】检查以太网物理连接
            └─ 可达 ↓
                【步骤 3】检查 FlClash 是否排除了内网
                    命令：Select-String -Path "~\.config\clash\profiles\*.yml" -Pattern "inet4-route-exclude"
                    ↓
                    ┌─ 未排除 → 【修复 A3】修改 FlClash 配置
                    └─ 已排除 ↓
                        【步骤 4】检查防火墙规则
                            命令：Get-NetFirewallRule | Where-Object {$_.Enabled -eq 'True'}
```

### 修复步骤

#### 【修复 A1】添加静态路由
```powershell
# 添加持久化静态路由
route add -p 10.0.0.0 mask 255.0.0.0 10.17.77.1 metric 5 if 10

# 验证
route print | findstr "10.0.0.0"

# 测试
ping 10.17.196.39
```

#### 【修复 A2】检查以太网物理连接
```powershell
# 检查以太网状态
Get-NetAdapter | Where-Object {$_.Name -like "*以太网*"} | Select Name, Status

# 如果状态为 Down，检查网线连接或启用接口
Enable-NetAdapter -Name "以太网"
```

#### 【修复 A3】修改 FlClash 配置
编辑 `~/.config/clash/profiles/*.yml`，添加：
```yaml
tun:
  inet4-route-exclude-address:
    - 10.0.0.0/8
```
然后重启 FlClash。

## 🔍 症状 B：外网 curl 不通

### 决策流程

```
外网 curl 不通 (curl: (35) SSL/TLS connection failed)
    ↓
【步骤 1】检查 FlClash 是否运行
    命令：Get-Process | Where-Object {$_.Name -like "*clash*"}
    ↓
    ┌─ 未运行 → 【修复 B1】启动 FlClash
    └─ 运行中 ↓
        【步骤 2】检查 FlClash interface-name
            命令：Select-String -Path "~\.config\clash\profiles\*.yml" -Pattern "interface-name"
            ↓
            ┌─ 未设置或错误 → 【修复 B2】修改为 WLAN
            └─ 正确 ↓
                【步骤 3】检查 WiFi metric
                    命令：Get-NetIPInterface -InterfaceAlias "WLAN" | Select InterfaceMetric
                    ↓
                    ┌─ 过高 (>20) → 【修复 B3】降低到 10
                    └─ 正常 ↓
                        【步骤 4】检查 WiFi 是否有网
                            命令：Test-NetConnection 8.8.8.8
                            ↓
                            ┌─ 无网 → 【修复 B4】检查手机热点
                            └─ 有网 ↓
                                【步骤 5】检查代理节点
                                    命令：Test-NetConnection planb.mojcn.com -Port 16617
```

### 修复步骤

#### 【修复 B1】启动 FlClash
```powershell
# 启动 FlClash（替换为实际路径）
Start-Process "C:\Program Files\FlClash\FlClash.exe"

# 等待 5 秒
Start-Sleep -Seconds 5

# 验证
Get-Process | Where-Object {$_.Name -like "*clash*"}
```

#### 【修复 B2】修改 FlClash interface-name
编辑 `~/.config/clash/profiles/*.yml`，添加：
```yaml
interface-name: WLAN
```
然后重启 FlClash。

#### 【修复 B3】降低 WiFi metric
```powershell
Set-NetIPInterface -InterfaceAlias "WLAN" -InterfaceMetric 10

# 验证
Get-NetIPInterface -InterfaceAlias "WLAN" | Select InterfaceMetric
```

#### 【修复 B4】检查手机热点
1. 确认手机热点已开启
2. 确认电脑已连接到热点
3. 测试手机自身是否有网

#### 【修复 B5】检查代理节点
```powershell
# 测试代理节点可达性
Test-NetConnection planb.mojcn.com -Port 16617

# 如果不通，尝试更换节点或检查订阅
```

## 🔍 症状 C：curl 通但浏览器不通

### 决策流程

```
curl 通但浏览器无法访问 (ERR_TIMED_OUT)
    ↓
【步骤 1】检查系统代理是否启用
    命令：Get-ItemProperty ... | Select ProxyEnable
    ↓
    ┌─ ProxyEnable = 0 → 【修复 C1】启用系统代理
    └─ ProxyEnable = 1 ↓
        【步骤 2】检查代理地址是否正确
            命令：Get-ItemProperty ... | Select ProxyServer
            ↓
            ┌─ 地址错误 → 【修复 C2】修改为 127.0.0.1:7890
            └─ 地址正确 ↓
                【步骤 3】检查浏览器代理设置
                    ↓
                    ┌─ 被覆盖 → 【修复 C3】改为"使用系统代理"
                    └─ 正常 ↓
                        【步骤 4】重启浏览器
                            → 【修复 C4】完全关闭并重新打开
```

### 修复步骤

#### 【修复 C1】启用系统代理
```powershell
Set-ItemProperty -Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name ProxyEnable -Value 1

# 验证
Get-ItemProperty -Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select ProxyEnable, ProxyServer
```

#### 【修复 C2】修改代理地址
```powershell
Set-ItemProperty -Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name ProxyServer -Value "127.0.0.1:7890"

# 验证
Get-ItemProperty -Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select ProxyServer
```

#### 【修复 C3】浏览器代理设置
**Chrome**：
1. 设置 → 系统 → 打开计算机的代理设置
2. 确认"使用代理服务器" = 开启
3. 地址：127.0.0.1，端口：7890

**Edge**：
1. 设置 → 系统和性能 → 打开计算机的代理设置
2. 同上

#### 【修复 C4】重启浏览器
```powershell
# 完全关闭 Chrome
taskkill /F /IM chrome.exe

# 等待 2 秒
Start-Sleep -Seconds 2

# 重新打开
start chrome
```

## 🔍 症状 D：内网和外网都不通

### 决策流程

    ↓

    命令：Get-NetAdapter | Where-Object {$_.Name -like "*clash*"}

    ┌─ 未运行 → 【修复 D1】启动 FlClash

        【步骤 2】检查所有网卡状态

## 🔍 症状 E：Kiro AI 报错地区限制

### 决策流程

```
Kiro AI 报错 "Too many requests" 或地区检测失败
    ↓
【步骤 1】检查代理是否生效
    命令：curl https://api.ipify.org?format=json
    ↓
    ┌─ 返回国内 IP → 代理未生效
    │   ↓
    │   检查 FlClash TUN 是否启用
    │       ↓
    │       ┌─ 未启用 → 【修复 E1】启用 TUN 模式
    │       └─ 已启用 → 按症状 B 排查
    └─ 返回国外 IP ↓
        【步骤 2】检查节点地区
            ↓
            ┌─ 节点在中国大陆 → 【修复 E2】更换非大陆节点
            └─ 节点正常 ↓
                【步骤 3】检查节点质量
                    命令：Test-NetConnection <节点IP> -Port <端口>
                    ↓
                    延迟过高 (>500ms) → 【修复 E3】更换节点
```

### 修复步骤

#### 【修复 E1】启用 TUN 模式
编辑 FlClash 配置：
```yaml
tun:
  enable: true
```
重启 FlClash。

#### 【修复 E2】更换非大陆节点
1. 打开 FlClash
2. 选择香港/台湾/新加坡/日本节点
3. 测试：`curl https://api.ipify.org?format=json`

#### 【修复 E3】更换高质量节点
```powershell
# 测试多个节点延迟
Test-NetConnection hk-node1.example.com -Port 443
Test-NetConnection sg-node2.example.com -Port 443

# 选择延迟最低的节点
```

## 快速诊断矩阵

| 症状 | 可能原因 | 快速检查命令 | 快速修复 |
|------|---------|-------------|---------|
| 内网不通 | 缺少静态路由 | `route print \| findstr "10.0.0.0"` | `route add -p 10.0.0.0 mask 255.0.0.0 10.17.77.1 metric 5 if 10` |
| 外网 curl 不通 | FlClash interface-name 错误 | `Select-String -Path "~\.config\clash\profiles\*.yml" -Pattern "interface-name"` | 修改为 `WLAN` |
| 外网 curl 不通 | WiFi metric 过低 | `Get-NetIPInterface -InterfaceAlias "WLAN" \| Select InterfaceMetric` | `Set-NetIPInterface -InterfaceAlias "WLAN" -InterfaceMetric 10` |
| 浏览器不通 | 系统代理未启用 | `Get-ItemProperty ... \| Select ProxyEnable` | `Set-ItemProperty ... -Name ProxyEnable -Value 1` |
| 全部不通 | TUN 未运行 | `Get-Process \| Where-Object {$_.Name -like "*clash*"}` | 启动 FlClash |
| Kiro 地区限制 | 代理未生效或节点在大陆 | `curl https://api.ipify.org?format=json` | 启用 TUN + 更换节点 |

## 通用诊断命令清单

### 网络状态
```powershell
# 查看所有网卡
Get-NetAdapter | Select Name, InterfaceIndex, Status

# 查看 IP 和网关
Get-NetIPConfiguration

# 查看 metric
Get-NetIPInterface | Select InterfaceAlias, InterfaceMetric | Sort InterfaceMetric
```

### 路由表
```powershell
# 查看完整路由表
route print

# 查看特定网段
route print | findstr "10.0.0.0"

# 查看默认路由
Get-NetRoute -DestinationPrefix 0.0.0.0/0
```

### FlClash
```powershell
# 检查进程
Get-Process | Where-Object {$_.Name -like "*clash*"}

# 检查配置
Select-String -Path "$env:USERPROFILE\.config\clash\profiles\*.yml" -Pattern "interface-name|inet4-route-exclude"

# 检查 TUN 接口
Get-NetAdapter | Where-Object {$_.Name -like "*clash*"}
```

### 系统代理
```powershell
# 查看代理设置
Get-ItemProperty -Path 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select ProxyEnable, ProxyServer
```

### 连通性测试
```powershell
# Ping
ping 10.17.196.39  # 内网
ping 8.8.8.8       # 外网

# Test-NetConnection
Test-NetConnection 10.17.77.1  # 内网网关
Test-NetConnection planb.mojcn.com -Port 16617  # 代理节点

# Curl
curl https://www.google.com  # 外网 HTTP
curl https://api.ipify.org?format=json  # 查看出口 IP

# 路由追踪
tracert -d -h 5 10.17.196.39  # 内网路由
tracert -d -h 5 8.8.8.8       # 外网路由
```
