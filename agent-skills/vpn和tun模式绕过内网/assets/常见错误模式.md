# VPN TUN 模式常见错误模式

## 错误模式分类

### RED 级别：关键业务中断（需立即处理）

#### ❌ 错误 1：外网 API 服务异常
**症状**:
```
Too many requests, please wait before trying again.
Request ID: 023da2fa-fd35-4585-87b0-caae2ab6c4ef
```
或
```
TimeoutError: Request timed out
Connection refused
```

**根因**:
- 过度排除 `10.0.0.0/8`，导致云厂商 IP（AWS、Azure、GCP）走了物理网卡
- DNS 解析后的 IP 被误判为内网，流量走错接口
- ISP 对非 VPN 流量限流或阻断

**快速修复**:
```yaml
# 错误配置
inet4-route-exclude-address:
  - 10.0.0.0/8    # ❌ 过大

# 正确配置
inet4-route-exclude-address:
  - 10.17.196.0/24  # ✓ 仅排除确认的内网子网
```

**影响范围**: Kiro/Claude API、GitHub、npm、Docker Hub

**验证命令**:
```powershell
Test-NetConnection api.anthropic.com -Port 443
nslookup api.anthropic.com
```

#### ❌ 错误 2：内网完全无法访问（IP 直连）
**症状**:
```powershell
PS> ping 10.17.196.39
请求超时
```

**根因**:
- TUN 接口 metric (0) < 物理网卡 metric (256)
- 内网流量被 TUN 劫持，发送到 VPN 服务器
- VPN 服务器不认识内网地址，丢弃数据包

**诊断命令**:
```powershell
# 查看路由表
route print | findstr 10.17.196

# 预期输出（错误）：
# 0.0.0.0    0.0.0.0    <VPN网关>  <TUN接口>  0    ← metric 0，劫持所有流量

# 预期输出（正确）：
# 10.17.196.0  255.255.255.0  10.17.77.1  <物理网卡>  40  ← 内网路由优先
```

**快速修复**: 见 [修复-TUN路由排除](../feature-skills/修复-TUN路由排除.md)

### YELLOW 级别：部分功能受限

#### ⚠️ 错误 3：域名访问失败，IP 访问正常
**症状**:
```bash
# 失败
curl http://gitlab.company.com
Failed to resolve host

# 成功
curl http://10.17.196.39
HTTP/1.1 200 OK
```

**根因**:
- DNS 查询返回 fake-ip (198.18.x.x)
- 应用使用 fake-ip 连接，但路由表中没有对应规则
- 或 fake-ip 被 TUN 劫持到 VPN

**诊断命令**:
```powershell
nslookup gitlab.company.com

# 错误输出：
# Address: 198.18.123.45   ← fake-ip

# 正确输出：
# Address: 10.17.196.39    ← 真实 IP
```

**快速修复**: 见 [修复-fake-ip过滤](../feature-skills/修复-fake-ip过滤.md)

---

#### ⚠️ 错误 4：跨子网访问失败
**症状**:
```powershell
# 同子网成功
ping 10.17.77.2
回复来自 10.17.77.2: 字节=32 时间<1ms TTL=64

# 跨子网失败
ping 10.17.196.39
请求超时
```

**根因**:
- 路由表缺少目标子网路由
- 或目标子网路由 metric 高于 TUN 默认路由
- 网关地址配置错误

**诊断命令**:
```powershell
# 查看物理网卡网关
ipconfig /all | Select-String -Pattern "默认网关|Default Gateway"

# 查看是否有目标子网路由
route print | findstr 10.17.196

# 如果无输出，说明缺少路由
```

**快速修复**: 见 [修复-静态路由](../feature-skills/修复-静态路由.md)

---

#### ⚠️ 错误 5：重启后配置失效
**症状**:
- 昨天配置好的，今天重启电脑后又不能访问内网了
- 静态路由消失

**根因**:
- Windows 静态路由默认不持久化（使用 `route add` 而非 `route add -p`）
- FlClash 重启后重新应用配置，覆盖手动路由
- 网卡禁用/启用后路由表重置

**诊断命令**:
```powershell
# 查看持久化路由
route print | findstr "持久路由|Persistent Routes"

# 如果为空，说明路由未持久化
```

**快速修复**:
```powershell
# 添加持久化路由
route add -p 10.17.196.0 mask 255.255.255.0 10.17.77.1 metric 5

# 或使用 FlClash 配置（推荐）
# 在 config.yaml 中配置 inet4-route-exclude-address
```

### GREEN 级别：性能/体验问题

#### 💡 错误 6：内网访问缓慢
**症状**:
- 可以访问内网，但速度很慢
- ping 延迟高

**根因**:
- 流量绕了远路（经过 VPN 再转发回内网）
- Metric 值设置不当，路由选择次优
- DNS 查询走 VPN，增加延迟

**诊断命令**:
```powershell
# 跟踪路由路径
tracert 10.17.196.39

# 正确输出（1-2 跳）：
# 1   <1 ms   10.17.77.1        # 直接到网关
# 2   <1 ms   10.17.196.39      # 到目标

# 错误输出（多跳）：
# 1   <1 ms   <VPN网关>         # 走了 VPN
# 2   50 ms   <VPN服务器>
# 3   51 ms   10.17.196.39
```

**优化方案**:
- 调低内网路由 metric 值
- 使用 TUN 路由排除，避免流量进入 VPN

## 错误组合场景

### 场景 A：同时配置多种方案导致冲突
```yaml
# 错误：既排除路由，又配置静态路由，还过滤 fake-ip
tun:
  inet4-route-exclude-address:
    - 10.0.0.0/8           # 方案 A

# 同时在系统中：
route add 10.17.196.0 ...   # 方案 C

dns:
  fake-ip-filter:
    - '*.company.com'       # 方案 B
```

**问题**: 
- 优先级不明确
- 难以排查哪个生效
- 可能互相干扰

**正确做法**:
1. 选择一种主方案（推荐方案 A）
2. 必要时辅助方案 B（fake-ip-filter）
3. 避免静态路由与 TUN 排除同时使用

---

### 场景 B：配置生效时机问题
**症状**:
- 修改配置后没有立即生效
- 需要多次重启才生效

**根因**:
- FlClash 缓存了旧配置
- 系统路由表没有刷新
- DNS 缓存未清除

**解决流程**:
```powershell
# 1. 修改 FlClash 配置
# 2. 完全退出 FlClash（不是最小化）
# 3. 清除 DNS 缓存
ipconfig /flushdns

# 4. 清除路由缓存（可选）
route -f    # ⚠️ 会删除所有路由，慎用

# 5. 重启 FlClash
# 6. 验证配置
route print
```

## 错误预防检查清单

### 配置前检查
- [ ] 确认内网网段范围（不要盲目使用 RFC1918 全段）
- [ ] 记录当前路由表状态 (`route print > before.txt`)
- [ ] 备份 FlClash 配置文件
- [ ] 准备回滚方案

### 配置后验证
- [ ] 测试外网访问（GitHub、Kiro API）
- [ ] 测试内网 IP 访问
- [ ] 测试内网域名访问
- [ ] 测试跨子网访问
- [ ] 检查路由表优先级
- [ ] 重启系统后复测

### 监控指标
- [ ] ping 延迟 < 10ms（内网）
- [ ] DNS 解析时间 < 100ms
- [ ] HTTP 请求成功率 = 100%
- [ ] 路由表条目数量稳定（不增长）

## 快速诊断命令合集

```powershell
# ===== 网络连通性 =====
ping 10.17.196.39
Test-NetConnection 10.17.196.39 -Port 80
curl http://10.17.196.39

# ===== 路由表 =====
route print | findstr "10.17"
Get-NetRoute | Where-Object {$_.DestinationPrefix -like "10.17*"}

# ===== DNS =====
nslookup internal.corp
ipconfig /displaydns | findstr "internal"

# ===== 网卡 Metric =====
Get-NetIPInterface | Select-Object InterfaceAlias, InterfaceMetric | Sort-Object InterfaceMetric

# ===== TUN 接口状态 =====
Get-NetAdapter | Where-Object {$_.InterfaceDescription -like "*TUN*"}

# ===== 路由跟踪 =====
tracert -d 10.17.196.39
```
