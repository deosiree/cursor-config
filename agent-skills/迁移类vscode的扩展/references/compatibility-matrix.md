# 编辑器兼容性矩阵

## 类 VSCode 编辑器对比

| 编辑器 | 基础版本 | 扩展 API | 默认扩展目录（Windows） | 市场兼容性 |
|-------|---------|---------|------------------------|-----------|
| VSCode | 官方实现 | 标准 VSCode API | `%USERPROFILE%\.vscode\extensions` | 100%（官方市场） |
| Cursor | VSCode fork | VSCode API 兼容 | `%USERPROFILE%\.cursor\extensions`（推测） | 高（共享 VSCode 市场） |
| Kiro | VSCode fork | VSCode API 兼容 | `%USERPROFILE%\.kiro\extensions` | 高（共享 VSCode 市场） |

## 扩展兼容性级别

### Level 1: 完全兼容（95%+）
大部分扩展可直接复制使用，包括：
- 主题扩展
- 代码片段（Snippets）
- 语言高亮（Syntax Highlighting）
- 简单工具扩展

### Level 2: 大部分兼容（80-95%）
可能需要重新安装或调整配置：
- 语言服务器扩展（如 Python、Go）
- Linter 和 Formatter
- 代码补全扩展

### Level 3: 部分兼容（50-80%）
需要检查版本兼容性：
- 调试器扩展
- Git 集成扩展
- 远程开发扩展

### Level 4: 低兼容（<50%）
通常需要重新安装或寻找替代品：
- 深度集成系统 API 的扩展
- 硬编码检测 VSCode 品牌的扩展
- 使用 VSCode 专有 API 的扩展

## 常见兼容性问题

### 问题 1: 扩展签名验证失败
**症状**: 扩展显示"无法验证签名"或拒绝加载  
**原因**: 直接文件复制破坏了扩展签名  
**解决**: 在目标编辑器的扩展市场重新安装

### 问题 2: API 版本不匹配
**症状**: 扩展显示"不兼容"或"需要更高版本"  
**原因**: 扩展要求的最低编辑器版本高于目标编辑器  
**解决**: 
- 升级目标编辑器
- 或在扩展市场搜索兼容的旧版本

### 问题 3: 依赖项缺失
**症状**: 扩展加载失败，提示缺少依赖  
**原因**: 扩展依赖其他扩展或系统组件  
**解决**: 查看扩展详情页的依赖项，先安装依赖

### 问题 4: 配置路径问题
**症状**: 扩展功能异常，找不到配置文件  
**原因**: 扩展硬编码了配置路径  
**解决**: 
- 手动调整扩展设置
- 或在目标编辑器重新配置

## 扩展市场兼容性

### VSCode Marketplace
- 官方扩展市场
- 所有类 VSCode 编辑器通常可访问
- 部分扩展可能检测编辑器品牌

### Open VSX Registry
- 开源替代市场
- 完全兼容 VSCode 扩展格式
- 部分扩展版本可能滞后

## 测试建议

### 迁移前测试
1. 检查源编辑器版本
2. 检查目标编辑器版本
3. 列出核心扩展清单（如语言支持、调试器）
4. 在测试机上先试迁移

### 迁移后测试
1. 打开扩展视图检查警告/错误
2. 打开常用项目测试核心功能
3. 测试代码补全、格式化、调试
4. 检查扩展设置是否需要调整
