# 评估测试用例

## 测试场景设计

### 场景 1: VSCode → Kiro（50 个扩展）
**目标**: 验证大规模扩展迁移的完整流程

**前置条件**:
- VSCode 已安装 50+ 个扩展
- Kiro 已安装但扩展目录为空
- 已准备备份空间

**输入**:
```
用户说：把 VSCode 的扩展迁移到 Kiro，
迁移后检查失效的，最后清理冗余的。
```

**期望输出**:
1. 生成 `copy-extensions.ps1` 并执行
2. 输出 `extensions-list.txt`（50 个扩展）
3. 提示启动 Kiro 并检查扩展视图
4. 生成 `analyze-failed.ps1`（假设有 3 个失效）
5. 输出失效扩展详细报告
6. 生成 `identify-redundant.ps1`
7. 用户选择删除 5 个冗余扩展
8. 执行清理并输出日志

**成功标准**:
- ✅ 所有脚本无错误执行
- ✅ 至少 90% 扩展正常加载（≤5 个失效）
- ✅ 失效扩展报告包含 ID 和重装建议
- ✅ 冗余清理正确删除选中扩展

### 场景 2: Cursor → VSCode（主题冲突）
**目标**: 验证多个主题扩展的冗余识别

**前置条件**:
- Cursor 已安装 5 个主题扩展
- VSCode 已有 2 个主题扩展

**输入**:
```
用户说：把 Cursor 的扩展同步到 VSCode，
但我只想保留 1-2 个主题。
```

**期望输出**:
1. 复制所有扩展
2. 识别 7 个主题扩展
3. 提示用户选择保留哪些
4. 删除其余 5-6 个主题

**成功标准**:
- ✅ 正确识别主题类扩展（通过 categories）
- ✅ 仅删除用户选中的主题
- ✅ 非主题扩展不受影响

### 场景 3: 批量部署到 10 台机器
**目标**: 验证批量安装脚本生成

**前置条件**:
- 已有标准扩展清单（20 个扩展）
- 10 台开发机已安装 Kiro

**输入**:
```
用户说：生成批量安装脚本，
在 10 台机器上安装这 20 个扩展。
```

**期望输出**:
1. 读取扩展清单
2. 生成 `batch-install.ps1`
3. 脚本包含 20 个 `code --install-extension` 命令
4. 提供分发和执行指南

**成功标准**:
- ✅ 脚本在所有机器上可执行
- ✅ 所有扩展正确安装
- ✅ 生成安装日志

### 场景 4: 权限不足（失败场景）
**目标**: 验证错误处理和 fallback

**前置条件**:
- 以普通用户身份运行（无管理员权限）
- 目标目录被其他进程锁定

**输入**:
```
用户说：复制扩展到 Kiro
```

**期望输出**:
1. 尝试复制失败
2. 检测权限不足错误
3. 提示以管理员身份运行
4. 提供手动复制指南（fallback）

**成功标准**:
- ✅ 清晰的错误消息
- ✅ 可行的 fallback 方案
- ✅ 不破坏源或目标目录

### 场景 5: 编辑器正在运行（警告场景）
**目标**: 验证锁定文件的警告机制

**前置条件**:
- 目标编辑器（Kiro）正在运行

**输入**:
```
用户说：复制扩展
```

**期望输出**:
1. 检测到目标编辑器进程
2. 警告可能导致文件锁定
3. 建议关闭编辑器
4. 用户确认后继续（或取消）

**成功标准**:
- ✅ 检测到进程并警告
- ✅ 用户可选择继续或取消
- ✅ 如果继续，处理锁定错误

## Darwin 评估指标

### 指标 1: 流程完整性（0-10 分）
- 10 分: 完整执行所有步骤，无遗漏
- 7-9 分: 主要步骤完成，有少量遗漏
- 4-6 分: 部分步骤完成，关键步骤缺失
- 0-3 分: 大量步骤缺失或错误

### 指标 2: 错误处理（0-10 分）
- 10 分: 所有错误都有清晰提示和 fallback
- 7-9 分: 大部分错误有处理，少量未处理
- 4-6 分: 仅处理常见错误
- 0-3 分: 错误导致流程中断，无提示

### 指标 3: 用户引导（0-10 分）
- 10 分: 每个人工介入点都有清晰指引
- 7-9 分: 主要介入点有指引
- 4-6 分: 指引模糊或不完整
- 0-3 分: 缺少关键指引

### 指标 4: 输出质量（0-10 分）
- 10 分: 所有脚本可执行，报告清晰完整
- 7-9 分: 脚本可执行，报告有少量信息缺失
- 4-6 分: 脚本部分可用，报告不完整
- 0-3 分: 脚本不可用或报告缺失

### 指标 5: 兼容性覆盖（0-10 分）
- 10 分: 支持所有常见编辑器和平台
- 7-9 分: 支持主要编辑器（VSCode/Cursor/Kiro）
- 4-6 分: 仅支持部分编辑器
- 0-3 分: 仅支持单一编辑器

## 回归测试清单

每次更新 skill 后，运行以下测试：

- [ ] 场景 1: 大规模迁移（50+ 扩展）
- [ ] 场景 2: 冗余识别（多个主题）
- [ ] 场景 4: 权限不足错误处理
- [ ] 场景 5: 编辑器进程检测
- [ ] 跨平台测试（Windows PowerShell）
- [ ] 脚本模板变量替换正确
- [ ] 所有 feature skills 可独立调用

## 性能基准

| 指标 | 目标值 | 测量方法 |
|-----|--------|---------|
| 复制速度 | > 10 MB/s | 50 个扩展（约 500 MB）复制时间 |
| 扩展清单生成 | < 5 秒 | 100 个扩展清单生成时间 |
| 失效扩展分析 | < 10 秒 | 10 个失效扩展分析时间 |
| 交互响应 | < 1 秒 | 用户输入到反馈时间 |

## 用户满意度指标

- **流程清晰度**: 用户无需额外提问即可完成迁移
- **错误恢复**: 遇到错误后用户能根据提示解决
- **时间效率**: 整体流程 < 15 分钟（含人工检查）
- **成功率**: > 90% 扩展正常工作
