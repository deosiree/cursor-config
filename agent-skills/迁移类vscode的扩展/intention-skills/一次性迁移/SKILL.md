# 核心任务
完成一次性扩展迁移的完整流程：复制 → 人工验证 → 分析失效 → 清理冗余。

## 何时触发
- `migrationMode` 为 `one-time`
- 用户明确表示"一次性迁移"、"复制过去"等意图
- 不需要持续同步，只需要迁移一次

## 前置条件
- 已明确 `sourceEditor` 和 `targetEditor`
- 源扩展目录存在且可访问
- 目标编辑器已安装（但扩展目录可以为空或需要覆盖）
- 用户已确认或完成备份

## 流程编排

### 阶段 0：预检查（新增）
0. **环境验证**
   - 使用 `pre-check.ps1` 验证环境
   - 检查项：源目录、磁盘空间、权限、编辑器进程
   - 如果检查失败，提供修复建议或终止

### 阶段 1：准备与复制
1. **验证路径**
   - 检查源目录是否存在
   - 确认目标编辑器安装路径
   - 检查磁盘空间是否足够
   
2. **调用复制功能**
   - 使用 `[[../../feature-skills/扩展目录复制/SKILL.md]]`
   - 生成并执行复制脚本
   - 输出：扩展清单文件 `extensions-list.txt`

### 阶段 2：人工验证（CHECKPOINT）
3. **启动目标编辑器**
   - 提示用户启动目标编辑器（如 Kiro）
   - 等待编辑器完全加载扩展
   
4. **人工检查扩展视图**
   - 使用 `[[../../feature-skills/兼容性检测/SKILL.md]]`
   - 引导用户：
     1. 按 `Ctrl+Shift+X` 打开扩展视图
     2. 滚动查看所有扩展
     3. 记录有 ⚠️ 警告或 ❌ 错误的扩展名
     4. 将失效扩展名写入 `failed-extensions.txt`（每行一个完整文件夹名）

### 阶段 3：失效扩展处理
5. **分析失效扩展**
   - 使用 `[[../../feature-skills/失效扩展分析/SKILL.md]]`
   - 读取 `failed-extensions.txt`
   - 解析每个扩展的 `package.json`
   - 输出：失效扩展详细报告（ID、版本、说明、建议）
   
6. **引导重装**（可选）
   - 提供扩展 ID 列表
   - 用户在目标编辑器扩展市场搜索重装
   - 用户决定哪些需要重装、哪些暂时不用

### 阶段 4：冗余清理（可选）
7. **识别冗余扩展**
   - 使用 `[[../../feature-skills/冗余扩展识别/SKILL.md]]`
   - 生成交互式扩展列表（带编号）
   - 用户输入要删除的扩展编号
   
8. **执行清理**
   - 确认删除清单
   - 执行批量删除
   - 输出：清理后的扩展目录

### 阶段 5：最终验证
9. **重启编辑器**
   - 提示用户重启目标编辑器
   
10. **功能测试**
    - 引导用户：
      1. 打开常用项目
      2. 测试关键扩展功能（代码提示、格式化、调试等）
      3. 确认工作流正常

## 输入契约
继承自主 SKILL，额外需要：
- `backupConfirmed`: 是否已备份（布尔值，默认 false → 先询问）
- `allowCleanup`: 是否允许清理冗余（布尔值，默认 true）

## 输出产物
- `extensions-list.txt`: 已迁移扩展清单
- `failed-extensions.txt`: 用户记录的失效扩展（可选）
- `failed-extensions-report.txt`: 失效扩展详细分析（可选）
- 清理后的目标扩展目录

## 人工介入点（CHECKPOINT）
- ✋ **阶段 0**：预检查失败时，决定是否修复或终止
- ✋ **阶段 1 前**：确认是否已备份
- ✋ **阶段 2**：人工检查扩展视图并记录失效扩展
- ✋ **阶段 3.6**：决定哪些失效扩展需要重装
- ✋ **阶段 4**：选择要删除的冗余扩展
- ✋ **阶段 5**：最终功能验证

## 成功标准
- ✅ 大部分扩展正常显示（无警告/错误图标）
- ✅ 失效扩展已记录并提供重装指引
- ✅ 冗余扩展已清理（如果用户选择清理）
- ✅ 关键工作流功能正常（代码提示、格式化等）

## 失败处理
如果遇到以下情况：
- **复制失败**：检查权限和磁盘空间 → 回滚（删除目标目录）
- **大量扩展失效（>30%）**：
  - 检查编辑器版本兼容性
  - 考虑使用扩展市场重装而非复制
  - 回滚到备份
- **编辑器无法启动**：删除目标扩展目录 → 恢复备份

## 使用示例
```text
用户说：
"我想把 VSCode 的扩展复制到 Kiro，
复制后检查一遍，失效的我重装，
最后删掉不需要的。"

Agent 执行：
1. 确认备份状态
2. 调用 feature-skills/扩展目录复制
3. 提示启动 Kiro 并人工检查
4. 等待用户提供 failed-extensions.txt
5. 调用 feature-skills/失效扩展分析
6. 调用 feature-skills/冗余扩展识别
7. 执行清理
8. 引导最终验证
```

## 边界
- **仅处理扩展文件**：不迁移设置、快捷键、workspace 配置
- **仅单次执行**：不建立持续同步机制
- **仅本地迁移**：不支持跨机器的远程迁移
