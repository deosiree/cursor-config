# 检测未覆盖场景

> 被 `hermes-session-harvest` 的 Step 1-2 调用。判断本次会话的操作场景是否已在路由表中覆盖。

## 输入

- 本次会话的用户原始请求（触发 OpenCLI 的 prompt）
- OpenCLI 自生长路由表（`SKILL.md` 路由规则表）
- 已有 `references/场景-*.md` 文件列表
- 已有 `opencli-ux-*/` 子 skill 目录列表

## 执行步骤

### 1. 提取场景特征

从本次会话中提取场景的关键特征词：

```text
示例：
  用户请求: "权限配置显示异常，两个权限都给了但仍不显示 tab"
  提取特征: [权限配置, tab不激活, 安全配置页面, v-if权限判断]
```

### 2. 路由表匹配

遍历路由表的每一行，计算语义重合度：

| 路由表行 | 重合特征 | 重合度 | 判定 |
|---------|---------|:---:|------|
| 自动化测试-用户管理 | 权限、操作列 | 30% | 不匹配 |
| 自动化测试-权限/isOwner/Header | 权限、sessionStorage | 40% | 不匹配 |
| 以上都不是 | (无) | 0% | 兜底 |

### 3. 重合度计算规则

```text
重合度 = 共有特征词数 / max(场景A特征词数, 场景B特征词数)

判定:
  ≥ 80% → 已有场景可覆盖，只更新 references
  50-79% → 相似场景，检查是否需要新建还是扩展
  < 50% → 新场景，走自生长流程
```

### 4. 输出

```json
{
  "scene_features": ["权限配置", "tab不激活", "安全配置页面", "v-if权限"],
  "route_table_match": null,
  "best_existing_scene": "权限/isOwner/Header (重合度 40%)",
  "is_new_scene": true,
  "suggested_name": "权限配置排查-Tab激活诊断",
  "confidence": "high"
}
```

## 特殊规则

- 如果路由表最后一行 "以上都不是" 被命中 → 直接判定为新场景
- 如果场景涉及**跨工具组合**（如 OpenCLI + SSH + HTTP 三联）→ 即使有部分重合也优先标记为新场景
- 如果场景仅涉及**新页面**但操作模式已覆盖 → 更新已有场景文件，不新建

## 输出规范

返回结构化判定结果给 `hermes-session-harvest` 主引擎。
