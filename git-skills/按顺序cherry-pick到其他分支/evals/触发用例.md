# 触发用例

## should-trigger（至少 3）

1. **单挑到 develop**  
   「把 `feat(views): 登录页-MFA…` 那次提交 cherry-pick 到 develop，不要 stash。」  
   期望：激活本 skill；干净树 → checkout develop → `cherry-pick <hash>`。

2. **临时分支只取中间几次**  
   「临时分支历史很乱，只要中间那三次 translate 相关提交，按顺序搬到 main。」  
   期望：列出 old→new；离散 `cherry-pick h1 h2 h3` 或连续区间。

3. **按顺序落到 main 且不要 push**  
   「源分支 auto-optimize/…，相对 main 超前的提交全按旧到新捡到 main；先别 push。」  
   期望：确认清单后区间或列表 cherry-pick；不 push。

## should-not-trigger（至少 3）

1. **尚未 commit 的本地改动**  
   「工作区一堆未提交修改，帮我 stash 切分支再 pop。」  
   期望：不激活本 skill（或激活后明确拒绝并指向提交/stash 工作流）。

2. **用户明确要整支 merge**  
   「把 feature 整支 merge 进 main，不要 cherry-pick。」  
   期望：不走本 skill 主体；尊重 merge 口径。

3. **交互式改写历史**  
   「用 rebase -i 把这五次压成两次再合进去。」  
   期望：不激活本 skill；声明超出职责。

## 验收要点

- 脏工作区：必须停下并列出脏文件。
- 顺序：禁止新→旧。
- 冲突：默认停下等人；不擅自 abort。
- push / 删源分支：默认否。
