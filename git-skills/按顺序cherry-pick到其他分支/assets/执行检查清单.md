# 执行检查清单（agent 按需读取）

执行前后逐项自检；任一项失败则停下，不继续 cherry-pick。

## 启动前

- [ ] 已解析 `repo` / `source_branch` / `target_branch`
- [ ] 已解析待挑 commits（列表或 oldest…newest）
- [ ] `git status` 工作树干净；否则列出脏文件并停下
- [ ] 若为脏主仓下的**沙盒测试**：已用独立 worktree（Windows：短路径 + `git -c core.longpaths=true`，见 [[../references/Windows-worktree与长路径.md]]）
- [ ] **未**计划用 stash/reset 掏已落地 commit
- [ ] 已向用户展示 `hash + subject` 表（old→new），或用户已给出完整 hash 列表

## 命令形态

- [ ] 单挑：`git cherry-pick <hash>`
- [ ] 离散：`git cherry-pick <h1> <h2> …`（已按旧→新）
- [ ] 连续：`git cherry-pick <oldest>^..<newest>`（含两端）
- [ ] 未把顺序写成新→旧

## 冲突时

- [ ] 已停下并报告冲突文件
- [ ] 未擅自 `--abort`
- [ ] 用户解决并 `git add` 后才 `--continue`
- [ ] 或按用户明确选择：`--abort` / `--quit`

## 收尾

- [ ] `git log` / `git status` 验收通过
- [ ] 未默认 `push`（除非用户明确要求）
- [ ] 未默认删源分支（除非用户明确说不要临时分支，且目标已含所需变更）

## 输出字段

每轮至少回报：`currentUnderstanding`、`worktreeClean`、`plannedCommand`、`status`、`nextAction`。
