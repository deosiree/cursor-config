# 多提交与冲突手册

## 前置条件

工作树干净（相对 HEAD 无未提交修改）。不干净 → 停下，不要 cherry-pick。

## 复制单个

```bash
git cherry-pick <hash>
```

会在当前分支生成**新 hash** 的 commit；提交时间等信息可能保留源提交元数据习惯，以当前 Git 行为为准。

## 复制多个（离散）

按 **旧 → 新** 列出：

```bash
git cherry-pick <commit1> <commit2>
```

## 复制连续区间

含两端；`commit1` 为区间内**最早**提交：

```bash
git cherry-pick <commit1>^..<commit2>
```

说明：`A^..B` 表示从 A 的父提交之后到 B（含 A、含 B）。

## 冲突处理

多提交链式 cherry-pick 时，冲突会中断流程：

1. 解决冲突文件
2. `git add <已解决文件>`
3. `git cherry-pick --continue`

其它出口（须用户明确选择）：

| 命令 | 效果 |
| --- | --- |
| `git cherry-pick --abort` | 回到操作前，像没发生过 |
| `git cherry-pick --quit` | 退出流程，**保留**已经成功 cherry-pick 的 commit |

Agent **默认**不得擅自 `--abort`；冲突时停下等人。
