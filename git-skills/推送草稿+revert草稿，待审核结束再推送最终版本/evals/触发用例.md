# 触发用例

## 应触发

| ID | 用户说法摘要 | 期望 phase |
| --- | --- | --- |
| T1 / P1 | 先 push 草稿到 develop 给后端，再本地审查 | `push_draft`（随后可 `local_review`） |
| T2 | 草稿已推，建临时分支 reset 回来改 | `local_review` |
| T3 / P2 | revert 草稿 SHA，再 cherry-pick 最终版 push | `publish_final` |
| T4 / P4 | 多 commit 草稿要按序 revert 再上最终 | `publish_final` + 多 SHA |
| T5 / P5 | 要 publish 但忘记草稿 SHA | `blocked`，追问 `draft_commit` |
| T6 / P7 | 审查中先修 develop，再把草稿+热修整包收回本地审查 | `hotfix_during_review` |

## 不应触发 / 改路由 / STOP

| ID | 用户说法摘要 | 期望 |
| --- | --- | --- |
| N1 / P3 | feature 上 force-with-lease 盖掉重推 | `handoff_force_push`，不执行强推 |
| N2 / P6 | merge 临时分支进 main 并删除 | 改路由 merge skill |
| N3 | 只要中间三次 commit cherry-pick | 改路由 cherry-pick skill |
| N4 | 开 worktree 沙盒 | 改路由 创建沙盒分支 |
| N5 | 用 reset --hard 清掉草稿改动 | STOP，拒绝 hard |
| N6 / P8 | 脏审查分支不 stash 直接 checkout develop | STOP / blocked，须先 stash |

## 验收要点

- README 一句话能回答「这长名字干嘛的」
- 推草稿后必须出现 `draftSha`
- 热修后审查基线是 `draft^..series_tip` 整包，**不是** stash pop 旧 WIP
- publish 须 revert 系列全部相关 SHA（含热修）
- 父级检查点含 HOTFIX-STASH / HOTFIX-PUSH / RECLAIM-SERIES
