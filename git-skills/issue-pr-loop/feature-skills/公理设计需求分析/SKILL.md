# 公理设计需求分析

## 模式

先根据用户目标选择并标注一种模式：

| 模式 | 分析输入 | 输出与边界 |
| --- | --- | --- |
| 新需求设计 | 用户目标、约束和验收期待 | 从目标提取可验证 FR，提出候选 DP；分析结果进入 HITL-1 方案 |
| 既有项目优化 | 用户确认的目标、当前行为、代码和现有规格 | 用源码证据识别现状 DP 与耦合；保持 FR 不变，优先重设计 DP |
| 项目源码学习 | 代码、配置、测试、文档和可追踪调用链 | 只读说明现有行为、设计参数和未知关系；不生成 Issue 或改动授权 |

简单单点 Bug 和只发布 Issue 沿用现有精简流程，不强制进行本分析。用户意图不清且会改变只读边界时，先澄清模式。

## 分析步骤

1. **建立证据边界**：新需求以用户目标和明确约束为准；项目优化和源码学习先查入口、调用链、相关模块、测试及规格。把“代码已证明的行为”“用户确认的需求”和“分析推断”分开记录。
2. **定义 FR**：用可观察、可验收的结果描述功能需求，保留目标来源。源码学习没有产品确认时，只把源码可证明的现状写作“观察项/FR 候选”，不能冒充用户确认的需求。
3. **识别 DP**：从候选方案或源码证据提取实现这些 FR 的设计选择。FR 与 DP 使用同一抽象层级；DP 可以是边界、接口、状态、数据结构或其他设计决定，不能仅因一个模块对应一个词就假定一对一。物理组件数量不代表功能独立性。
4. **构建设计矩阵**：行标题写 DP，列标题写 FR。单元格 `X` 表示改变该 DP 可能改变该 FR；`?` 表示证据不足；留空只表示已核实无影响。为源码判断给出文件、符号、调用链、测试或规格位置。
5. **先判结构，再比较信息量**：
   - 只有 FR 与 DP 数量相等且所有关系已知时，才按方阵判结构。
   - 完整无耦合设计要求每个 FR/DP 都有对应的对角 `X`，所有非对角单元格都已确认无影响，并有验收依据证明每个 DP 可满足对应 FR；`X` 只表示依赖关系，不等于验收通过。缺失对角 `X` 表示 FR 未满足或 DP 未形成对应关系，不能只因矩阵形状是对角阵就判为完整设计。
   - 三角矩阵只有在存在可执行的 DP 调整顺序时才判为解耦。按本技能的“DP 为行、FR 为列”约定，下三角从最下方 DP 向上调整，上三角从最上方 DP 向下调整。
   - 其他方阵结构是耦合。含 `?` 时只能报告暂定结构，不能宣称已证实无耦合或解耦。
   - 非方阵报告未覆盖 FR 或冗余 DP；不得补造行列或关系。只有设计含义成立的行列顺序调整才可用于识别三角结构，不能为让矩阵过关而任意重排。
6. **重设计 DP**：发现耦合时，先尝试调整 DP、边界或方案，同时保留用户确认的 FR 与验收条件。仍无法解耦时列出具体耦合单元、约束及残余影响，不以改写 FR 掩盖设计问题。
7. **应用信息公理**：只在满足独立性公理的候选间比较。具备 FR 成功概率 `p` 时可用 `I = -log2(p)` 表示信息量；具备设计范围和系统范围数据时说明其概率依据。缺少必要数据就写“无法量化”，不估造概率、范围或排序。
8. **回流并停靠**：新设计和项目优化把分析映射到适用的 Goal/Issue 草稿、验收和 HITL-1 确认包。确认包列出项目当前为 `none` 的默认 Agent 状态，并在每个 HITL 交接让用户选择下一阶段 Agent。只有用户确认后才按外环授权实施或写远端。

## 输出

1. **模式与证据**：所选模式、用户确认事实、代码观察、推断和待核实项。
2. **FR / DP 表**：每项编号、抽象层级、验收/设计依据和源码引用。
3. **设计矩阵**：DP 为行、FR 为列，图例为 `X`、`?`、空白。
4. **结构判断**：方阵/非方阵、无耦合/解耦/耦合/未知；解耦时写出 DP 顺序。
5. **方案与信息量**：耦合的 DP 重设计建议、残余约束；信息量的比较依据或“无法量化”。
6. **外环交接**：适用的 Goal/Issue 草稿、验收映射、下一阶段 Agent 选择和 HITL 停止点。

单独源码学习只输出前五项，不创建/更新 Issue，不修改源码，不推送或开 PR。

## 方法依据

- [MIT 2.882, Axiomatic Design, Chapter 1](https://web.mit.edu/2.882/www/chapter1/chapter1.htm)：两条公理、设计矩阵、对角/三角结构、正确调整顺序与信息量定义。
- [The Minimum Constraint Design and the First Axiom, ICAD 2009](https://www.axiomaticdesign.com/wp-content/uploads/ICAD-2009-15.pdf)：三角矩阵的解耦含义及耦合矩阵的判别。

## 使用示例

```text
使用 $公理设计需求分析 分析一个新需求。把可验收结果列为 FR，把同层级候选实现选择列为 DP；给出 DP 为行、FR 为列的矩阵，说明未知关系、矩阵结构和解耦顺序。先输出分析草稿，交给 $issue-pr-loop 放入 HITL-1。
```
