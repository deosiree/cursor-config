# 阶段交接检查清单

## 候选评审前

- [ ] 新建议已保留原始来源和本地 Candidate ID。
- [ ] 对照已接受需求、真实代码入口、调用链和关键测试；已明确哪些是事实、推断和未知。
- [ ] Bug 分类有已接受契约/验收要求作为依据；证据不足时标为待验证或需求。
- [ ] 检查开放/近期关闭 Issue 和相关 PR；无法查询时标 `unknown`。
- [ ] 合并、拆分、延期、重复或拒绝均有理由；候选尚未自动变成实现任务。

## Goal 确认前（项目级规划需要时）

- [ ] 当前会话中记录目标用户、问题、结果和非目标。
- [ ] 标出会改变行为、安全或验收结果的未知项。
- [ ] `G-*` 验收标准可观察，有证据方式；性能/安全门禁有授权信息。
- [ ] 用户确认 Goal 基线版本。

## Issue 图发布前

- [ ] 本批次已由用户选择；每个候选有来源、单一职责、验收标准、依赖和 readiness。
- [ ] 只有项目级或多 Issue 规划才要求 Goal 来源和 Issue 图；单个小维护 Issue 可跳过。
- [ ] 依赖表与 Mermaid 一致；节点 ID 唯一，引用有效，图无环。
- [ ] 可并行项路径不冲突，共享接口冻结，测试数据隔离且工作树隔离。
- [ ] GitHub 写入在本次授权范围内；发布后读回 Issue 和依赖关系。
- [ ] 发布 Issue 后停在交接点；实现、PR、审查和合并分别授权。

## 单 Issue 开始与 PR

- [ ] 重读 Goal、图谱、计划、实时 Issue/PR 状态及仓库规则。
- [ ] 当前执行者/PR 作者身份与 Issue 创建者可以不同，实际职责和提交来源已记录。
- [ ] 前置依赖完成，路径边界清楚，用户脏改动已保护。
- [ ] 每个计划节点均对照验收；测试记录命令、环境、commit 和结果。
- [ ] PR 描述与实际 diff、验证和未验证项目一致。
- [ ] 人工审查完成并由授权人员合并后才推进下一节点。

## 项目终验

- [ ] 所有 Goal ID 映射到合并实现和验证证据。
- [ ] 端到端功能覆盖关键用户场景和异常路径。
- [ ] 性能目标实际已确认，压测在批准环境运行且结果达标。
- [ ] 安全测试有目标授权、边界、报告、修复与复测证据。
- [ ] 用户文档/API 文档与代码、测试、Issue 一致。
- [ ] 未运行的检查明确标 `not-run`；Critical/Major 风险已处理或留待用户决定。
