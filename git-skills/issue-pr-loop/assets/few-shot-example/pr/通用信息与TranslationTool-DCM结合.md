## 映射规则

- GitHub 的通用审阅要素通过“关联 Issue”“问题分析”“修复方案”“验证”“未运行”“风险与回滚”表达。
- DCM 的三个本地字段名和顺序保留；通用信息作为额外章节补足，不改写本地章节。
- PR 目标分支在创建 PR 时作为 `base` 选择，创建后读回核对；不能由 GitHub 默认分支推断。
- `develop` 等非默认目标分支上的 PR，不因正文使用 `Closes #N` 就假设 GitHub 会自动关闭 Issue；确认平台语义后再选择关联方式。
- `合并版本` 在实际合并前只能标为待记录；合并后再读回真实日期、实际合入分支和 SHA。
