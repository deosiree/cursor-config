# MVP 模板

按以下顺序整理工作：

1. `request-inbox.md`：新建议的来源、证据、分类、重复状态和批次决定。可持续追加，不代表已批准 Issue。
2. `goal.md`：新项目或需要跨 Issue 追踪时使用；旧项目可沿用长期维护 Goal。
3. `issue-graph.md`：多 Issue 批次的依赖表和展示图。单个边界清楚的维护 Issue 不强制建立全局图。
4. `issues/<issue-id>/develop.md`：仅在该 Issue 需要详细文件边界、执行步骤或验证计划时创建。

先在当前会话澄清高影响歧义，再批量评审候选。未获 GitHub 写入授权时只保留本地候选和 Issue 草稿。发布 Issue 不自动开始实现或创建 PR。
