# 核心任务

产出规范化的 `sandbox_path` 与 `sandbox_branch`，不改仓库。

## 命名惯例（默认）

1. 若项目已有 `.worktrees/` 或 `worktrees/`（且被 gitignore）→ 使用 `$LOCATION/$sandbox_branch`。
2. 否则采用 **sibling 目录**（本会话与 `apex_menu-io` 惯例）：

| 主仓目录名 | 分支 | 沙盒路径 |
| --- | --- | --- |
| `apex_dev` | `devmgr` | `../apex_devmgr`（同级 `apex_` + 分支名） |
| `{prefix}` | `{branch}` | `../{prefix}_{branch}` 当 prefix 以 `_dev` 等结尾时，优先 `{repoName去掉无关键后缀风格}`；**默认规则**：主仓 basename 为 `X`、分支为 `B` 时，若已存在 `X` 的 sibling 模式 `X`↔`X_menu-io` 类，则新沙盒为 **同级目录名 = 把主仓名中的功能后缀替换/追加为分支名**。对本仓库族：`apex_dev` + `devmgr` → `apex_devmgr`。 |

**可执行默认（写死）**：

- `repoRoot` 的父目录 + `/` + `deriveName(repoBasename, sandbox_branch)`
- `deriveName`：若 `repoBasename` 匹配 `^(.+_)dev$`，则 `$1 + sandbox_branch`（例 `apex_dev` + `devmgr` → `apex_devmgr`）；否则 `repoBasename + "_" + sandbox_branch`。

3. 用户显式给出 `sandbox_path` 时以用户为准，仍须校验不落在受保护路径上。

## 输出

`sandboxPath` | `sandboxBranch` | `namingRuleApplied` | `collision`

## 边界

- 发现路径已存在且为其它 worktree → 标 `collision=true`，交编排 STOP。

## 使用示例

```text
repo=F:/.../apex_dev，分支=devmgr。使用 $解析沙盒路径与命名惯例。
```
