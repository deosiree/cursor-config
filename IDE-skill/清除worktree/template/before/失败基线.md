# 失败基线（无 skill 时）

## 典型用户说法

- 「Source Control 里好多 agent-xxxx，帮我清掉 3 天前的」
- 「清理 nebula 下临时 worktree」
- 「.claude/worktrees 占磁盘了」

## Agent 常见失败

| 失败 | 后果 |
|------|------|
| 直接 `Remove-Item -Recurse` | Git 元数据残留，`git worktree list` 仍显示 phantom |
| 未 dry-run 就删 | 误删仍有用改动 |
| 跳过用户确认 | 不可恢复 |
| 只清 `apex_dev` | 忽略 `microfb` / `opsdeck` 等多 git 根 |
| 删主 checkout 或非白名单路径 | 破坏工作区 |
| 在 worktree 目录内执行 `git worktree remove` | 命令失败或行为异常 |
| 不跑 `git worktree prune` | 陈旧注册残留 |

## 本 skill 必须纠正

1. 只扫白名单临时目录
2. 默认 dry-run + 表格预览
3. 用户明确同意后才 `-Execute`
4. 仅用 `git worktree remove` + `prune`
5. 多 git 根递归扫描
