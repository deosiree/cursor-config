# 对话流程：dry-run → 确认 → execute

完整用户交互示例，适用于对 Agent 行为做 few-shot 参考。

## 典型对话

**用户**：
清除 nebula 下 3 天前的 agent worktree，根目录 `F:\Documents\Repertory\Sieyuan\nebula`，先预览。

**Agent（正确）**：

1. 加载 `清除worktree` SKILL.md，先读 `references/安全删除与红线条款.md`
2. 运行脚本（默认无 `-Execute`）：

```powershell
& "F:\Documents\Repertory\Sieyuan\nebula\.cursor\IDE-skill\清除worktree\scripts\clean-worktrees.ps1" `
  -WorkspaceRoot "F:\Documents\Repertory\Sieyuan\nebula" `
  -OlderThanDays 3
```

3. 展示表格：列出 `GitRoot | WorktreePath | LastWrite | AgeDays | Action | Reason`
4. **停止**，询问：「Dry-run 预览如上，共 N 条可删。是否执行删除？」

**用户**：确认删除。

**Agent（正确）**：

5. 加 `-Execute` 重跑同一命令
6. 汇报 `removed=N skipped=N failed=0` 计数
7. 建议：`cd apex_dev; git worktree list` 自检

## 反例（不应出现）

| 错误行为 | 后果 |
|---------|------|
| 第一步就 `-Execute` | 跳过 dry-run，不可恢复 |
| `Remove-Item -Recurse .claude/worktrees` | Git 元数据残留 |
| 只扫 apex_dev 不扫其他 Git 根 | 遗漏 microfb/opsdeck |
