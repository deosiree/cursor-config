# 渐进式教学 — 真实交互示例（一概念完整循环）

> **概念：** FastAPI vs Flask（三点核心区别）
> **方法：** 费曼概念解释 + 苏格拉底追问 ×2 + 考核（选择题+场景题）

---

## 阶段 1：教学

**讲解正文：**

FastAPI 比 Flask 多三个核心能力：

1. **原生 async** — Flask 是 WSGI 同步模型，一个请求卡 IO 时其他请求排队；FastAPI 是 ASGI，等 IO 时切去处理其他请求
2. **Pydantic 自动校验** — Flask 要手写 `if not body["x"]`，FastAPI 声明一个 model 就搞定
3. **自动 OpenAPI 文档** — Flask 要手写接口文档，FastAPI 直接 `/docs` 给前端

**类比：**
> Flask 像一个人工验票窗口，一次只验一个人，后面排队等着。
> FastAPI 像自助闸机，扫完码就进，闸机同时处理很多人。

## 阶段 2：追问

**追问 1：** 如果你用 Flask 写翻译 API，用户请求一多，你最先感受到什么问题？

> **用户：** 响应变慢，一个请求超时可能拖住后面所有请求

**追问 2：** Pydantic 自动校验省掉了手写 if 检查，但如果前端传了一个你 model 里没定义的字段会怎样？

> **用户：** 会被忽略掉还是报错？

**追问 3：** 那如果有字段需要自定义校验规则（比如手机号格式），Pydantic 能处理吗？

> **用户：** 可以用 validator 装饰器吧

## 阶段 3：考核

**选择题 1：** 以下哪个不是 FastAPI 相对于 Flask 的优势？
A. 原生异步支持
B. 自动生成 OpenAPI 文档
C. 内置 ORM 数据库操作
D. Pydantic 参数校验

正确答案：C

**场景题：** 你接到一个需求：给词条管理 API 加一个批量查询接口 `GET /terms?ids=1,2,3`。请用 FastAPI 写出路由定义 + 参数处理方式。

参考要点：
- Query 参数用 `List[int]` 类型注解
- FastAPI 自动解析逗号分隔或重复参数
- 返回统一 ApiResponse 格式
