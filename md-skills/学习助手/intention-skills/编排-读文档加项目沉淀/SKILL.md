# 编排：读文档 + 项目沉淀 → 双链回写

## 编排器 vs Agent（本层定位）

| | 本 intention（编排器 + 门禁） | 若改成纯 Agent intention |
|--|------------------------------|---------------------------|
| 适合 | 阶段顺序稳定：探索 → 落盘 → 回写；需可测、可复盘 | 每轮目标变化大、常跳步、难固定顺序 |
| 固定什么 | 阶段顺序、RED 约束、两次人审 | 仅高层目标，步骤自生成 |
| 可变什么 | 探索深度、篇目**执行顺序**、方法论/图表（步骤 5 目标清单内自排） | 全部由模型临场规划 |
| 结论 | **保持编排器**；步骤 5 用「必交付清单」代替逐步填表 | 仅当流水线频繁失效再考虑拆父 agent |

父级 `学习助手` 负责 **Agent 式意图路由**；本文件负责 **流水线与门禁**；步骤 5 只固定**交什么**，不固定**先写哪篇**。

## 输入

| 参数 | 来源 |
|------|------|
| `文档路径` | 用户入参 |
| `章节号` | 用户入参 |
| `项目名` | 用户入参或章节提取 |
| `--repo-path` | 可选 |

## 主线流程（步骤 1 → 7）

### 步骤 1：读文档 → 提取关注点 + 项目名

```
1. read_file(文档路径) → 定位 章节号
2. 提取：关注点列表、推荐项目名
3. 推断 owner/repo：
   a. 用户已给 owner/repo → 使用
   b. 文档含 GitHub URL → 解析
   c. 仅项目名 → web_search "{项目名} github" → 取首个合理结果
   d. 仍无法确定 → 🛑 STOP，请用户提供 owner/repo
4. 输出：{ 关注点列表, 项目名, owner/repo }
```

**若步骤 1 失败** → 见文末「失败与回退」。

---

### 步骤 2：探索项目源码

```
调 [[../../../../common-skills/探索skills/SKILL.md]]
→ 有 --repo-path → 探索-本地仓库
→ 仅 owner/repo → 探索-GitHub仓库
→ 网站 URL → 探索-网站（OpenCLI）

输出：目录结构 + 关键文件摘要 + 架构初步判断（2～3 句）
```

---

### 🔴 CHECKPOINT · CP1：确认探索结果

```
展示：项目名、owner/repo、目录树 depth≤3、架构判断 2～3 句

请用户选择：[继续] / [修正] / [取消]
- 继续 → 步骤 3
- 修正 → 用户补充 owner/repo 或路径 → 回到步骤 2
- 取消 → 终止；可保留探索摘要供下轮会话
```

**允许在 CP1 收窄范围**（不算偏离主线）：用户说「只做前 3 个关注点」→ 更新关注点列表后继续。

---

### 步骤 3：创建落盘目录

```
目录 = {文档所在目录}/{章节名}/
create_directory(目录)
```

---

### 步骤 4：写架构总览

```
调 [[../../feature-skills/沉淀-项目笔记落盘/SKILL.md]]
→ 输出 00-架构总览.md（含窄版 Mermaid 分层图、关注点导航双链）
```

### 步骤 5：目标驱动清单（分析文档）

**不规定** 01→02→03 的写作顺序；先立清单，再自选顺序填满。进入本步前须有 CP1 确认后的关注点列表。

#### 5.1 生成交付清单

根据关注点列表，写出结构化清单（可在回复中展示，不必单独落盘文件）：

```json
{
  "必交付": [
    {
      "id": "01",
      "关注点": "类型层如何抽离",
      "文件名": "01-类型层抽离.md",
      "完成标准": ["源码路径", "窄版Mermaid", "核心结论1-2句", "方法论标注", "正文≥2KB"]
    }
  ],
  "可选": [],
  "已跳过": []
}
```

- `id` / `文件名`：与 `00-架构总览.md` 导航表一致；序号可跳号（如只做 01、03）
- 用户已在 CP1 缩减范围 → 未入选的篇目不进 `必交付`，可记入 `已跳过` 并注明原因

#### 5.2 单篇完成标准（勾选制）

每篇进入 `[[../../feature-skills/沉淀-项目笔记落盘/SKILL.md]]` 前，须满足：

| 勾选 | 完成标准 |
|:---:|----------|
| ☐ | 从探索结果中已有**可引用源码路径**（目录或文件） |
| ☐ | 已用 `[[../../../../common-skills/方法论skills/SKILL.md]]` 选定方法并将在正文标注 |
| ☐ | 需要图时已调 `[[../../../../common-skills/渲染图skills/SKILL.md]]` 或明确「本篇无需图」 |
| ☐ | 正文含 **1～2 句可回写核心结论**（写前先想好，避免空心长文） |
| ☐ | 落盘后文件 **≥2KB** 且至少一个 `##` 小节 |

#### 5.3 执行（顺序自选）

```
while 必交付 中仍有未勾选项：
  1. 自选下一篇（建议：依赖少的先写、与总览导航呼应；允许先写难篇再补易篇）
  2. 对该篇勾选完成标准 → 写作 → 落盘
  3. 将该篇从 必交付 移到「已完成」；失败则移入 已跳过 并写原因
```

**退出条件**（满足其一即可进 CP2）：

- `必交付` 全部已完成，或
- 剩余篇目均已进入 `已跳过`，且已在对话中告知用户「跳过原因 + 是否补写」

**禁止**：为凑篇数写无源码引用的空心文档；禁止在未更新清单状态下静默少交付。

---

### 🔴 CHECKPOINT · CP2：确认分析文档

```
展示：
  - 步骤 5 清单终态：已完成 / 已跳过 表
  - 00-架构总览 + 各篇路径与大小 + 每篇 1 句核心结论

请用户选择：[回写] / [仅保留笔记] / [取消]
- 回写 → 步骤 6
- 仅保留笔记 → 跳过步骤 6，小结标注「笔记已落盘但未回写」
- 取消 → 保留已生成文件，不回写
```

---

### 步骤 6：回写主文档

```
调 [[../../feature-skills/回写-双链注入主文档/SKILL.md]]
→ 核心结论 + [[双链]] 注入章节；替换原「建议重点看」列表（若匹配失败走该 skill 内 A→B→C 回退）
```

---

### 步骤 7：输出小结

```
沉淀完成。
- 目录、清单完成率（已完成/必交付）、回写处数、图表数、方法论计数
- 已跳过篇目及原因；未回写 / 远程探索：逐项标注
```

## 何时可偏离主线（仍须满足 RED）

| 用户/现场情况 | 允许动作 |
|---------------|----------|
| 关注点过多 | CP1 后缩减 `必交付` 清单；步骤 5 可分批，未勾选项保留到小结「待补篇目」 |
| 仓库过大 | 探索只扫约定目录（如 packages/、src/），在 CP1 说明范围 |
| 暂不回写 | CP2 选「仅保留笔记」 |
| 探索失败 | 见下表；禁止无标注硬写「源码分析」 |

## 失败与回退

| 触发条件 | 一线修复 | 仍失败兜底 |
|----------|----------|------------|
| 文档/章节不存在 | 🛑 STOP，列可用章节标题 | 等用户改路径或章节号 |
| owner/repo 无法推断 | 请用户手填；或给 GitHub 链接 | 终止沉淀意图 |
| 探索超时/403 | 换 raw.githubusercontent.com / 缩小目录 | 小结标注「未完整探索」，问是否用 --repo-path |
| 回写 SEARCH 无匹配 | 走回写 skill 策略 B→C | 禁止静默失败；至少输出待粘贴 Markdown 块 |

## 约束

- GitHub 不爬 SPA；远程走 raw 或探索skills 既定路径
- 网站探索：`npx opencli fetch <url> --render`（由探索skills 约定）
- `00-架构总览.md` 必须含窄版 Mermaid 分层图
