# 编排：判定 · 掌握度评估

> **定位：** intention 编排器。给定当前概念 + 用户历史回答，运行完整评估管线，给出通过/边缘/不通过判定。

## 输入

| 参数 | 来源 |
|------|------|
| `概念` | 当前教学的概念 |
| `讲解内容` | 已输出的教学正文 |
| `追问记录` | 苏格拉底追问环节的所有追问 + 用户回答 |

## 执行流程

### 步骤 1：分析掌握画像

→ `[[../../feature-skills/评估-分析掌握画像/SKILL.md]]`

```
输入：用户的所有回答文本 + 概念
输出：掌握画像 {
  薄弱点: ["哪些子概念理解不透"],
  已掌握点: ["哪些概念回答正确"],
  置信度: "高/中/低",
  建议考核维度: ["知识点" / "代码实战" / 两者都要]
}
```

### 步骤 2：生成考核试卷

→ `[[../../feature-skills/评估-出题引擎/SKILL.md]]`

```
输入：掌握画像
输出：考核试卷 {
  题目列表: [
    { 类型: "选择题", 维度: "知识点", 题目: "...", 选项: [...], 正确答案: "..." },
    { 类型: "填空题", 维度: "知识点", 题目: "...", 正确答案: "..." },
    { 类型: "场景题", 维度: "代码实战", 题目: "...", 参考要点: [...] }
  ],
  策略说明: "薄弱点多出(60%) + 已掌握抽查(40%)"
}
```

### 步骤 3：用户作答

```
🔴 STOP — 展示试卷，等用户提交答案
收集用户答案
```

### 步骤 4：判分

→ `[[../../feature-skills/评估-判分/SKILL.md]]`

```
输入：试卷 + 用户答案
输出：判定结果 {
  每题得分: [{题号, 得分, 满分, 评语}],
  总分: {得分}/{满分},
  掌握等级: "通过" | "边缘" | "不通过",
  建议: "下一概念" / "加强后再考" / "回退重讲"
}
```

### 步骤 5：返回判定

将判定结果返回给上游（编排-渐进式教学）：

- **通过** → 上游调用回写-双链注入主文档，进入下一概念
- **边缘** → 上游增加 1 轮追问 + 再考
- **不通过** → 上游回到步骤 1 换角度重讲

## 考核设计原则

1. **薄弱点覆盖优先**：60% 题目针对薄弱点，40% 抽查已掌握点
2. **混合题型**：选择题（快速覆盖）+ 填空题（精确回忆）+ 场景题（综合应用）
3. **代码实战**：如果概念涉及代码，至少 1 道场景题需要写代码/伪代码
