# 评估 · 出题引擎

> **定位：** 纯功能 skill。根据掌握画像生成混合题型试卷，覆盖薄弱点和已掌握点。

## 输入

| 参数 | 说明 |
|------|------|
| `掌握画像` | 评估-分析掌握画像 的输出（含薄弱点、建议题型配比） |
| `概念` | 当前教学的概念及其子概念 |
| `讲解内容` | 已输出的教学正文（用于出题素材） |

🔴 CHECKPOINT：确认掌握画像已有足够的薄弱点信息再开始出题（置信度≠低）

## 出题策略

### 题型配比

| 题型 | 考核能力 | 默认占比 |
|------|---------|:-------:|
| **选择题** | 辨析能力（干扰项区分） | 40% |
| **填空题** | 精确回忆与理解深度 | 30% |
| **场景题** | 综合应用与代码实战 | 30% |

### 题目分配

- **薄弱点**：60% 的题目
- **已掌握点**：40% 的题目（抽查，防止遗忘）
- 如果建议考核维度含"代码实战" → 场景题中至少 1 道需要写代码/伪代码

### 题目难度递进

```
第 1 题：最容易（单一知识点，直接回忆）
中间题：中等（组合知识点，辨析/填空）
最后 1 题：最难（综合应用，场景题）
```

## 输出格式

```json
{
  "题目列表": [
    {
      "id": 1,
      "类型": "选择题"|"填空题"|"场景题",
      "维度": "知识点"|"代码实战",
      "目标": "薄弱点"|"已掌握点",
      "考核概念": "具体子概念名",
      "题目": "题目文本",
      "选项": ["A. xxx", "B. xxx", "C. xxx", "D. xxx"],
      "正确答案": "B",
      "参考要点": ["要点1", "要点2"]
    }
  ],
  "策略说明": "薄弱点多出(60%) + 已掌握抽查(40%)"
}
```

## RED

| 反模式 | 替代 |
|-------|------|
| 所有题都考同一个子概念 | 各子概念均匀覆盖 |
| 选择题干扰项是凑数的 | 每个干扰项代表一个常见误解 |
| 场景题没有参考要点 | 评分无法标准化 |
| 题量太少（<3） | 至少 3 道（1 选择 + 1 填空 + 1 场景） |
| 已掌握点完全不考 | 必须抽查 40% 已掌握点 |

## 约束

1. 至少 3 道题
2. 选择题干扰项有意义（代表常见误解）
3. 场景题须给出参考要点
4. 已掌握点的题目难度应略高于"直接回忆"（如辨析题而非默写）
