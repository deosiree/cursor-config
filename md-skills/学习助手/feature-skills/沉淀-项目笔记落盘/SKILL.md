# 沉淀：项目笔记落盘

## RED（失败基线）
- 文件内容 < 2KB → 空心文档，只有标题没有实质分析
- 缺少 Mermaid 图 → 被 渲染图skills 路由判定为"不需要图"但实际需要
- 双链路径错误（用了绝对路径或 `../` 深度不对）→ Obsidian 无法跳转

## GREEN（执行主线）
见下方"执行"流程。

## REFACTOR
- 输出格式要求膨胀 → 拆分到 `references/输出格式规范.md`
- 架构总览要求越来越长 → 独立为 `template/架构总览模板.md`（已做）

## 输入

- `目标目录`：{文档同级}/{章节名}/
- `文件名`：`{序号}-{关注点关键词}.md` 或 `00-架构总览.md`
- `内容`：完整的 Markdown 正文（含 Mermaid 图、双链、方法论标注）
- `元信息`：{ 关注点名, 方法论, 源码引用, 关联文档 }

## 执行

```
1. create_directory(目标目录) — 若不存在
2. write_file(目标目录/文件名, 内容)
3. 验证文件大小 > 0 且包含至少一个 ## 标题
```

## 输出格式要求

每篇分析文档必须包含：
- `# {关注点名}` 标题
- 至少一张 Mermaid 图
- "源码位置"引用（如 `packages/core/src/types/`）
- 结尾的 `> 📖 下一个推荐 → [[双链]]`
- 方法论标注（如"费曼检验"、"苏格拉底追问"）

## 架构总览特殊要求（00-架构总览.md）

额外包含：
- Mermaid monorepo 分层图（flowchart TD，窄版）
- 金字塔依赖关系
- 文件数量统计（建立规模感）
- 关注点导航表（带双链）
- 阅读路线建议

## 约束

- 文件命名必须有序号前缀，保证 Obsidian 文件列表排序
- 不覆盖已有文件。若目标文件已存在：
  1. 提示用户："{文件名} 已存在（{大小}，{修改时间}）"
  2. 提供选项：`[覆盖/跳过/重命名]`
  3. 覆盖 → 备份旧文件为 `{文件名}.bak.{时间戳}` → write_file
  4. 跳过 → 不写入，在输出小结中标注"已跳过 {N} 个已存在文件"
  5. 重命名 → 用户输入新文件名 → write_file
- 每篇 ≥ 2KB 内容（空心文档警告）
