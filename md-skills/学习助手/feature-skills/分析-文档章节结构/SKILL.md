# 分析：文档章节结构

## RED（失败基线）
- 提取了概念列表但遗漏了"建议画出"的图表需求 → 后续步骤缺少图表
- 把普通列表项误判为关注点 → 生成多余的空心文档
- `owner/repo` 推断错误（如把 `learn-claude-code` 推断成 `learn/claude-code`）→ 后续探索失败

## GREEN（执行主线）
见下方"执行"流程。

## REFACTOR
- 当文档格式不标准（无"需要理解的概念"等关键词）→ 在步骤 2 用 ### 子标题与列表项兜底提取，仍无法识别则 🛑 STOP 并请用户给出概念列表

## 输入

- `文档路径`
- `章节号`（如 `## 1.概念扫盲`）

## 执行

```
1. read_file(文档路径) → 定位章节号
2. 提取 Markdown 结构：
   - 该章节下的 ### 子标题
   - 列表项（- 开头）
   - "推荐项目:" 后的项目名
3. 识别模式：
   - "需要理解的概念" / "需要关注" → 概念/关注点列表
   - "建议画出" / "建议产出一张" → 图表需求
   - "推荐项目:" → 项目名
```

## 输出

```json
{
  "章节标题": "1.概念扫盲",
  "概念列表": [
    { "名称": "Agent", "是否有详细解释": false },
    { "名称": "Tool", "是否有详细解释": false }
  ],
  "关注点列表": [
    "类型层如何抽离",
    "共享业务逻辑如何组织"
  ],
  "建议图表": "概念 → 工程模块映射图",
  "推荐项目": {
    "名称": "craft-agents-oss",
    "owner/repo": "从文档推断"
  },
  "同级目录": "{文档所在目录的绝对路径}"
}
```

## 约束

- 只提取，不生成答案
- 列表项保持原文措辞，不改写
