# 评估 · 分析掌握画像

> **定位：** 纯功能 skill。分析用户对追问的回答，找出薄弱点和已掌握点。

## 输入

| 参数 | 说明 |
|------|------|
| `概念` | 当前教学的概念（含子概念列表） |
| `追问记录` | 所有追问 + 用户回答的完整记录 |
| `讲解内容` | 已输出的教学正文（用于对照） |

## 分析维度

| 维度 | 观察指标 | 评价标准 |
|------|---------|---------|
| 准确性 | 回答是否与文档/标准定义一致 | 完全一致/部分一致/不一致 |
| 完整性 | 是否覆盖了概念的核心特征 | 全部覆盖/部分覆盖/未覆盖 |
| 举例能力 | 能否主动给出自己的例子 | 能自己举例/能复述例子/不能举例 |
| 追问反应 | 追问后能否修正/深化理解 | 能修正/有所进步/无变化 |
| 表述方式 | 用自己话还是照搬原文 | 自己话/混合/照搬原文 |

## 输出

```json
{
  "薄弱点": [
    {
      "子概念": "X",
      "迹象": "回答含糊/回避/错误",
      "严重程度": "高/中/低",
      "具体引用": "用户原话片段"
    }
  ],
  "已掌握点": [
    {
      "子概念": "A",
      "迹象": "回答准确且有自己举例",
      "证据": "用户原话片段"
    }
  ],
  "置信度": "高"|"中"|"低",
  "建议考核维度": "知识点"|"代码实战"|"两者都要",
  "推荐题型配比": {
    "选择题": 40,
    "填空题": 30,
    "场景题": 30
  }
}
```

## RED

| 反模式 | 替代 |
|-------|------|
| 只有用户反馈文本也硬分析 | 无追问记录 → 置信度=低，建议考核全面覆盖 |
| 同一回答同时标为薄弱和掌握 | 按"最差表现"覆盖 |
| 分析时歪曲用户原意 | 引用用户原话片段做证据 |
