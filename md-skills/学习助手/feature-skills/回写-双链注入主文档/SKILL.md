# 回写：双链注入主文档

## RED（失败基线）
- 双链用了 Markdown 链接格式（`[text](path.md)`）而非 `[[wikilink]]` → Obsidian 不识别
- SEARCH 字符串在所有策略下均未匹配 → 静默失败，答案未注入
- 注入后未验证 → 双链指向的文件实际不存在

## GREEN（执行主线）
- 策略 A（匹配列表）→ B（匹配标题）→ C（人工 diff）三级回退
- 注入后必须 `read_file` 验证双链格式 + 目标文件存在

## REFACTOR
- 双链格式规范 → 已独立为下文"双链格式规范"段
- 注入策略变多 → 可拆分为 `feature-skills/注入-策略A匹配列表/` 等子 skill

## 输入

- `主文档路径`
- `章节号`
- `笔记目录`：{同级}/{章节名}/
- `关注点列表`：[{ 名称, 笔记文件名, 核心结论, 方法论 }]

## 执行流程

### 步骤 1：读主文档当前状态

```
read_file(主文档路径) → 定位章节号 → 读取该章节现有内容
```

### 步骤 2：构建替换内容

对每个关注点：

```markdown
### {序号} {关注点名}

**核心结论：** {1-2 句从笔记提取的核心结论}

{简短的源码证据或关键设计决策}

> 📘 完整分析（含{方法论} + 源码级细节）→ [[{笔记文件名}]]
```

### 步骤 3：注入主文档

```
策略 A：匹配"建议重点看"列表（优先）
  edit_file(主文档路径):
    SEARCH: "建议重点看这些部分" 到该章节末尾的原始列表
    REPLACE: 步骤 2 构建的完整内容 + 架构总览链接

策略 B：匹配章节标题（回退）
  若策略 A 的 SEARCH 未匹配：
    SEARCH: "## {章节号}" 后紧跟的内容
    REPLACE: "## {章节号}" + 步骤 2 构建的内容

策略 C：暂停人工确认（最终回退）
  若策略 B 仍失败：
    → 展示 diff preview（原内容 vs 新内容）
    → 请用户确认后手动合并
    → 标注 "⚠️ 自动注入失败，已生成内容在 {笔记目录}/_pending-injection.md"
```

### 步骤 4：验证

```
1. read_file(主文档路径, range=注入区域) → 确认双链格式正确
2. 确认每个 [[双链]] 指向的笔记文件存在
3. 确认答案正文可独立阅读（不依赖跳转）
```

## 双链格式规范

```
Obsidian wikilink 格式：
  [[相对路径/文件名|显示名]]

正确示例：
  [[3.拆解完整项日/01-类型层抽离|01-类型层抽离]]
  [[3.拆解完整项日/00-架构总览|00-架构总览]]

错误示例：
  [01-类型层抽离](3.拆解完整项日/01-类型层抽离.md)  ← 不要用 Markdown 链接
  [[01-类型层抽离]]  ← 缺少子目录路径（Obsidian 可能找不到）
```

## 约束

- 不改动章节以外的内容
- 双链使用相对路径（从主文档所在目录算起）
- 每个关注点的答案 ≤ 200 字正文 + 双链（详细内容在笔记中）
