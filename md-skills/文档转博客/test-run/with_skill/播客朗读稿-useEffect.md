# 播客朗读稿：useEffect 与依赖数组

## 卷首要点

**主播**：场景钩子——很多人照着 Vue/React 文档写 useEffect，页面却无限刷新，控制台请求刷屏，往往是依赖数组没写对。今天先记住三条：副作用和渲染分开管；依赖数组决定「什么时候再跑」；漏依赖和写错依赖是两类不同 bug。  
**嘉宾**：对，别把 useEffect 当语法糖，得先分清「画界面」和「画完再干活」。  
[停顿]

## 一、什么是副作用

### 铺垫

**主播**：第一节搞懂「副作用」——会出现渲染、请求、订阅、改标题。  
**嘉宾**：渲染是 React 根据 state 画 UI；副作用是画完之后才去干的事，比如拉接口。  
[停顿]

### 追问

**主播**：那在渲染函数里直接 await 请求行不行？  
**嘉宾**：那是另一条坑线；该用 useEffect 把「画完再请求」隔开。  
**嘉宾**：块末记一句：渲染归渲染，副作用归 useEffect。  
[停顿]

## 二、useEffect 的作用

### 铺垫

**主播**：第二节看 `useEffect(fn, deps)` 这句 API。  
**嘉宾**：意思是这轮 DOM 更新之后执行 `fn`；要清理订阅就 return 一个清理函数。  
[停顿]

### 追问

**主播**：它解决的核心问题是什么？  
**嘉宾**：把「渲染之外的工作」挂到正确的生命周期上，而不是塞进 render。  
[停顿]

## 三、依赖数组三种写法

### 铺垫

**主播**：第三节对照三种 deps——不写、`[]`、`[a,b]`。  
**嘉宾**：不写是每次渲染后都跑；空数组是挂载后跑一次；写变量是它们变了才跑。  
[停顿]

### 追问

**主播**：无限重渲染最常见怎么来的？  
**嘉宾**：effect 里 setState，又把刚变的 state 放进 deps——循环就来了。  
**嘉宾**：块末记一句：循环是依赖写多了，旧值是依赖写少了。  
[停顿]

## 四、常见错误

### 铺垫

**主播**：第四节专门讲「刷爆页面」那种疼法。  
**嘉宾**：先查 effect 里有没有 setState，再查 deps 是否包含这个 state。  
[停顿]

## 五、Strict Mode

### 铺垫

**主播**：开发环境 effect 跑两次，算不算生产 bug？  
**嘉宾**：Strict Mode 故意双调用来暴露没清理的订阅；生产一般单次。别为了少跑一次就关 Strict Mode，先补清理函数。  
[停顿]

## 卷尾·快问快答（共 5 题）

**主播**：快问一，副作用指什么？  
**嘉宾**：渲染之外的工作，比如请求和订阅。  
[停顿]

**主播**：快问二，useEffect 何时执行？  
**嘉宾**：本轮 DOM 更新之后。  
[停顿]

**主播**：快问三，空数组 deps 表示什么？  
**嘉宾**：挂载后执行一次（清理另说）。  
[停顿]

**主播**：快问四，无限刷新先查什么？  
**嘉宾**：effect 里 setState 是否进了 deps。  
[停顿]

**主播**：快问五，开发环境跑两次怎么办？  
**嘉宾**：先写清理函数，别关 Strict Mode 糊弄。  
[停顿]
