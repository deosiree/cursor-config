## 卷首要点（学习者卡点 + Primacy）

**主播**：场景钩子——很多人照着文档写 useEffect，页面却无限刷新，控制台请求一条接一条，多半是依赖数组没对齐。今天先记住三条：副作用和渲染分开管；依赖数组决定「何时再跑」；漏依赖和写错依赖是两类 bug。  
**嘉宾**：对，别把它当成「多写一行就完事」的语法糖，得先分清「画界面」和「画完再干活」。  
[停顿]

## 一、副作用与 useEffect

### 铺垫

**主播**：第一节搞懂副作用——会出现渲染、请求、订阅。  
**嘉宾**：渲染是 React 根据 state 画 UI；副作用是画完之后才去干的事，比如拉接口。直接在渲染里 await 请求是另一条坑线。  
[停顿]

### 追问

**主播**：那 useEffect 在组件里扮演什么角色？  
**嘉宾**：告诉 React：这轮 commit 之后，去跑这段函数。块末记一句：渲染归渲染，副作用归 useEffect。  
[停顿]

## 二、依赖数组三种写法

### 铺垫

**主播**：第二节对照三种依赖——不写、`[]`、写 `[a,b]`。  
**嘉宾**：像闹钟：不写是「每画一次就响」；空数组是「只在挂载响一次」；写变量是「它们变了才响」。  
[停顿]

### 追问

**主播**：无限刷新最常见怎么来的？  
**嘉宾**：effect 里 setState，又把刚变的 state 放进依赖——循环就来了。漏依赖则是界面一直用旧值，不一定刷爆。  
**嘉宾**：块末记一句：循环是依赖写多了，旧值是依赖写少了。  
[停顿]

## 三、和 Strict Mode 的关系（可选块）

### 铺垫

**主播**：开发环境 effect 跑两次，算不算 bug？  
**嘉宾**：Strict Mode 故意双调用来帮你发现没清理的订阅；生产一般只跑一次。别为了「少跑一次」关掉 Strict Mode，先写清理函数。  
[停顿]
