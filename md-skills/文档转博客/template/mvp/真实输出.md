# 播客朗读稿：useEffect 与依赖数组

## 卷首要点

**主播**：场景钩子——很多人第一次写 useEffect，页面突然无限刷新，控制台请求刷屏，往往就是依赖数组没写对。今天先记住两条：副作用要单独管；依赖数组决定「什么时候再跑」。  
**嘉宾**：对，准确说法是：useEffect 管「渲染之外的事」，依赖数组管「这些事何时重做」。  
[停顿]

## 一、副作用是什么

### 铺垫

**主播**：本节搞懂「副作用」——会出现渲染、请求、订阅这几个词。  
**嘉宾**：你可以把组件渲染想成「画界面」，副作用是「画完之后还要去干的事」，比如拉接口。别在渲染函数里直接 await 请求，那是另一类问题。  
[停顿]

### 追问

**主播**：那 useEffect 放哪？  
**嘉宾**：放在函数组件里，告诉 React：这轮画完以后，去执行这段函数。  
**嘉宾**：块末记一句：渲染归渲染，副作用归 useEffect。  
[停顿]

## 二、依赖数组

### 铺垫

**主播**：本节搞懂依赖数组——三种写法：不写、空数组、写具体变量。  
**嘉宾**：像闹钟：不写依赖是「每画一次界面就响一次」；`[]` 是「只在第一次挂载响」；`[a,b]` 是「a 或 b 变了才响」。  
[停顿]

### 追问

**主播**：无限循环一般怎么来的？  
**嘉宾**：常在 effect 里 `setState`，又把刚变的 state 写进依赖，或依赖漏写一直用旧值——两种都疼，但疼法不同。  
**嘉宾**：块末记一句：漏依赖是旧值 bug，依赖写错是循环 bug。  
[停顿]

## 卷尾·快问快答（共 3 题）

**主播**：快问一，useEffect 干什么的？  
**嘉宾**：管副作用，渲染之后执行。  
[停顿]

**主播**：快问二，空数组 `[]` 表示什么？  
**嘉宾**：只在挂载时执行一次。  
[停顿]

**主播**：快问三，无限刷新先查什么？  
**嘉宾**：查 effect 里是否 setState 且依赖把该 state 包进去了。  
[停顿]

**主播**：收束——先分清「画界面」和「画完再干活」，再谈依赖数组。  
[停顿]
