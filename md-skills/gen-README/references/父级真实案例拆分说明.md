# 父级真实案例拆分说明

`template/microfb/` 是父级 skill 的完整 few-shot 成品案例。

本轮对子 skill 的模板收敛原则：

- 不再用 `before/after` 解释“怎么改”
- 直接从 `template/microfb/` 拆出一次真实试跑的输入与输出
- 每个子 skill 的 `template/mvp/真实输出.md` 必须能指回 `microfb` 中的真实文档或真实片段

固定映射：

- `架构拓扑映射`：`前端架构拓扑图.md`、`运行时拓扑_登录到首屏.md`
- `源码符号定位`：`流程图符号定位表.md`
- `文档结构规划`：`template/microfb/README.md` 与三个主题目录
- `源码证据抽取`：总览文档、`状态链路/`、`说明文档/`
- `图类型判定`：总览图文与状态链路图文
- `文档内容生成`：至少一份状态链路文档与一份说明文档
- `Mermaid图语法修复`：父级真实图文中的 Mermaid 片段
- `最佳实践同步`：父级当前 Mermaid / skill 规则
- `README索引维护`：`template/microfb/README.md`
- `子技能路由决策`：围绕“基于 microfb 生成全套文档”的真实任务描述与 `routingPlan`

## 子 skill 试跑记录规范

每个子 skill 的 `template/mvp/` 至少包含四份材料：

1. `任务输入.md`
   - 记录一次真实试跑上下文
   - 明确目标、输入源、边界条件、是否允许人工澄清
2. `真实输出.md`
   - 保留真实字段、表格、正文片段、图块或 JSON 片段
   - 不允许只写摘要结论
3. `来源摘录.md`
   - 摘录父级 `template/microfb/` 中被真正消费的原始材料
   - 必须能让维护者知道“这个输出从哪里来”
4. `说明.md`
   - 解释为什么这样拆、最小复用核心是什么

`template/snapshot/产物快照.md` 不是提示语，而是稳定格式样板。
