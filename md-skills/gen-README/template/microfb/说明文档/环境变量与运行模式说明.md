# 说明文档：环境变量与运行模式（microfb）

本文档目标：把 `microfb` 的关键环境变量、默认值与“会影响行为的分支”固化下来，便于联调、排障与一致性配置。

## 1. 核心结论（MVP）

- **base 不是可选项（运行时）**：路由运行时 base 由 `VITE_APP_BASE` 决定（缺失会抛错），用于 `history.base` 与登录路径拼接。
- **mock 与 host 认证桥接是互斥语义**：`VITE_MOCK_DEV_SERVER=true` 时关闭 host 登录桥接（走本地登录兜底）。
- **子应用入口模式**：`VITE_SUBAPP_MODE` 控制 `Apex` 在 dev 下使用 `dynamic/static/auto`，`auto` 会探活 dynamic 不可达时回退 static。

## 2. 变量清单（按作用域分组）

### 2.1 部署路径与路由 base

- **`VITE_APP_BASE`**
  - **作用**：运行时路由 base；影响守卫 `stripBasePath` 的剥离逻辑；影响 `getLoginPath()` 拼接。
  - **默认/兜底**
    - **运行时**（`getAppBase()`）：**必须提供**，为空会抛错
    - **构建时**（`vite.config.ts normalizeAppBase()`）：缺失时默认 `/cloud`
  - **源码证据**
    - `src/api/gateway/route-base.gateway.ts`：`getAppBase()` / `getLoginPath()`
    - `src/router/index.ts`：`createWebHistory(getAppBase())`
    - `vite.config.ts`：`base: normalizeAppBase(env.VITE_APP_BASE)`

- **`VITE_APP_PORT`**
  - **作用**：dev/preview 端口
  - **兜底**：dev=5173、preview=4173（避免 NaN）
  - **源码证据**：`vite.config.ts`：`resolvePort()`

### 2.2 API 与代理

- **`VITE_APP_API_URL`**
  - **作用**：dev/preview 代理 target
  - **源码证据**：`vite.config.ts`：`apiTarget`

- **`VITE_APP_BASE_API`**
  - **作用**：API 前缀（决定是否启用 dev proxy；preview 有单独 proxy 逻辑）
  - **源码证据**：`vite.config.ts`：`baseApiPrefix`、`enableDevProxy`、`previewProxy`

### 2.3 认证模式（host 桥接 / mock）

- **`VITE_MOCK_DEV_SERVER`**
  - **作用**：作为统一 mock 开关；为 true 时 `isAuthMockMode=true`，从而 **关闭** host 登录桥接（`buildHostLoginUrl` 返回 null）
  - **源码证据**
    - `src/utils/auth-mode.ts`：`isAuthMockMode()` / `isHostAuthBridgeMode()`
    - `vite.config.ts`：也用于 mockDevServerPlugin include 逻辑

- **`VITE_HOST_APP_URL`**
  - **作用**：host（基座）域名/根 URL；缺失时无法桥接，自动走本地登录兜底
  - **源码证据**：`src/utils/auth-mode.ts`：`buildHostLoginUrl()`

- **`VITE_HOST_LOGIN_PATH`（可选）**
  - **作用**：覆盖 host 登录路径；缺失时默认使用 `getLoginPath()`（即 `${VITE_APP_BASE}${LOGIN_PATH}`）
  - **源码证据**：`src/utils/auth-mode.ts`：`ensureLeadingSlash(...)` + `getLoginPath()`

### 2.4 子应用（qiankun）入口与模式

- **`VITE_SUBAPP_MODE`**
  - **值域**：`dynamic | static | auto`
  - **作用**：Apex 在 dev 下入口选择；`auto` 下会探活 dynamic 不可达时回退 static
  - **源码证据**
    - `src/plugins/qiankun/apps.ts`：`applyApexDevAutoFallback()`
    - `src/utils/micro-app-config.ts`：`normalizeSubAppMode()` / `canReachSubAppEntry()`
    - `vite.config.ts`：`enableApexStaticServe`（static/auto 下启用本地静态入口服务）

- **`VITE_SUBAPP_APEX_ENTRY` / `VITE_SUBAPP_APEX_ENTRY_DYNAMIC` / `VITE_SUBAPP_APEX_ENTRY_STATIC`**
  - **作用**：Apex 入口地址；支持 `http(s)://`、`//host`、或以 `/` 开头的路径
  - **源码证据**
    - `src/plugins/qiankun/apps.ts`：`resolveSubAppEntry(...)`
    - `src/utils/micro-app-config.ts`：`resolveSubAppEntry(...)`
    - `src/store/modules/appConfig.store.ts`：`getDefaultApps()`（生产 fallbackProduction 也在此组装）

- **`VITE_SUBAPP_OPSDECK_ENTRY` / `VITE_SUBAPP_MicroGrid_ENTRY`**
  - **作用**：Opsdeck/MicroGrid 入口地址（缺失时有本地默认）
  - **源码证据**：`src/store/modules/appConfig.store.ts`：`getDefaultApps()`

## 3. 推荐的最小配置（MVP）

- **本地开发（dev）**
  - `VITE_APP_BASE=/cloud`
  - `VITE_APP_API_URL=...`
  - `VITE_APP_BASE_API=/dev-api`（示例）
  - `VITE_SUBAPP_MODE=auto`
  - `VITE_SUBAPP_APEX_ENTRY_DYNAMIC=//localhost:8081`
  - （可选）`VITE_MOCK_DEV_SERVER=true`（全局 mock）

- **联调/生产（非 dev）**
  - 必配 `VITE_APP_BASE`
  - 配置 `VITE_HOST_APP_URL` 用于桥接登录（若采用 host 统一登录）

## 4. 验收点（配置视角）

- base 配置一致：`history.base`、守卫入口判断、host 登录路径拼接三者一致。
- `VITE_SUBAPP_MODE=auto`：dynamic 不可达时可稳定回退 static（不会白屏）。
