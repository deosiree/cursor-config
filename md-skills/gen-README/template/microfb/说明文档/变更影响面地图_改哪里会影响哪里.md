# 说明文档：变更影响面地图（改哪里会影响哪里）

本文档目标：提供 `microfb` 的“改动点 → 影响面 → 必测项”映射，帮助在改代码前快速评估风险，避免“改一处炸一片”。

## 1. 使用方式（MVP）

- 第一步：定位你要改的文件/模块归属。
- 第二步：查本表对应的影响面与必测项。
- 第三步：执行对应最小验收脚本（可结合 `说明文档/联调验收脚本_手工回归最小步骤.md`）。

## 2. 影响面矩阵（核心）

| 改动点（文件/模块） | 主要影响面 | 高风险回归 | 必测项（最小） |
| --- | --- | --- | --- |
| `src/api/gateway/route-base.gateway.ts` | 路由 base、登录路径拼接、子应用 activeRule 前缀 | 入口 404、登录跳错地址、子应用激活失败 | 未登录访问、入口落点、子应用路由刷新 |
| `src/router/index.ts` | 静态路由装配、History 模式、base 生效 | 静态页不可达、子应用路由匹配错位 | 静态路由可达、`/cloud` 前缀下刷新 |
| `src/plugins/permission.ts` | 全局守卫、登录重定向、动态路由注入、异常恢复 | 死循环跳转、并发导航异常、全局 404 增多 | 未登录重定向、并发点击菜单、异常后恢复 |
| `src/store/modules/permission.store.ts` | 菜单转路由、动态路由树、routesLoaded 状态 | 页面 404、侧边栏错层级、功能项误生成路由 | 登录后首页、菜单类型过滤、路由重建 |
| `src/utils/menu-visibility.ts` | 菜单可见性归一化、类型归一化、菜单树标准化 | 菜单消失/误显示、权限按钮异常 | 菜单显隐、目录/页面/功能项渲染 |
| `src/utils/menu.ts` | 首菜单路径计算、参数拼装、redirect 处理 | 登录后落点错误、刷新后回退错误 | 首菜单落点、带 params 菜单跳转 |
| `src/services/menu/menu-repo.ts` | 菜单缓存读写、menuVersion、更新事件 | 菜单不同步、子应用不同步、串权 | 登录后菜单更新、刷新菜单、登出清理 |
| `src/store/modules/user/user.store.ts` | 登录后置、菜单刷新、登出强解散、子应用 props 同步 | 串权、菜单不刷新、登出后残留状态 | 登录成功、刷新菜单、切换账号 |
| `src/plugins/qiankun/apps.ts` | 子应用注册、entry 选择、props 契约、globalState 转发 | 子应用挂载失败、props 过期、联调白屏 | 子应用挂载、Apex auto 回退、props 更新 |
| `src/store/modules/appConfig.store.ts` | 子应用配置来源与兜底（store/local/public/default） | 线上配置漂移、子应用入口错误 | 生产加载配置、fallback 逻辑 |
| `vite.config.ts` | dev/preview base、proxy、mock、Apex 静态入口服务 | 本地联调不可用、preview 资源被代理吞掉 | dev 联调、preview 资源与 API 共存 |
| `src/utils/auth-mode.ts` / `src/utils/auth.ts` | 登录桥接模式、mock 模式、登录态判定 | 一直跳登录、误判已登录 | mock 与 bridge 切换、未登录重定向 |

## 3. 重点联动关系（最容易漏）

### 3.1 改 base 相关（`getAppBase` / `vite base`）
- 会联动：
  - 路由匹配（`createWebHistory(getAppBase())`）
  - 守卫路径判定（`stripBasePath`）
  - host 登录路径拼装（`getLoginPath` / `buildHostLoginUrl`）
  - 子应用 `activeRule`
- 典型事故：`/cloud` 下正常、根路径或 preview 异常；或反过来。

### 3.2 改菜单缓存（`menu-repo`）
- 会联动：
  - 守卫首页落点（`resolveEntryMenuPath`）
  - 动态路由生成（`generateRoutes` 读缓存）
  - 子应用 props（`menuList/menuVersion`）
- 典型事故：主应用菜单更新了，子应用还是旧菜单。

### 3.3 改登录/登出（`user.store`）
- 会联动：
  - `Auth.isLoggedIn()` 判定信号（`userInfo`）
  - 菜单缓存写入与清理
  - 子应用 props 同步与清空
- 典型事故：切换账号串权。

## 4. 改动分级建议（发布评审可用）

- **P0 高风险改动**：守卫、动态路由生成、base、qiankun 注册、user store 登录登出
  - 要求：执行完整手工回归脚本
- **P1 中风险改动**：菜单归一化、menu-repo、appConfig 配置加载
  - 要求：执行菜单链路 + 子应用链路回归
- **P2 低风险改动**：纯文案/样式、无状态逻辑的小修
  - 要求：冒烟 + 关键路径抽检
