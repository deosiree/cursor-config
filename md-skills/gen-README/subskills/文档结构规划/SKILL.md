# 文档结构规划

## 适用场景

- 需要从单篇说明扩展到多文件文档体系。
- 需要定义主题、功能域、层级和索引关系。

## 核心规则

- 结构拆分必须服务于目标受众和实际源码边界。
- 无法判断按主题还是按功能域拆分时，先问人。
- 输出要包含产物矩阵和索引建议。

## 最小节点契约

- 输入证据：文档目标、已有文档范围、源码主题划分、目标受众。
- 输出结果：文档结构方案、产物矩阵、索引层级、待确认问题。
- 失败条件：拆分维度会显著影响产物，但证据不足。
- 人工澄清回退：拆分维度不清楚时先提问。

## RED

- 常见失败：直接按感觉拆目录、没有说明索引关系。

## GREEN

- 至少给出主题矩阵、目录层级和索引建议。

## REFACTOR

- 若结构仍然过重，继续压缩到本轮最小可交付集合。

## 使用示例

```text
请把现有零散 docs 规划成按主题可导航的多文件结构。
```
