# 架构拓扑映射

## 适用场景

- 需要先画出系统边界或运行主链路。
- 后续写作必须依赖拓扑骨架。

## 核心规则

- 只基于仓库事实抽取边界、依赖和关键入口。
- 不对图类型做最终裁决，交由“图类型判定”处理。
- 如果入口、边界或依赖方向不清楚，先问人。

## 最小节点契约

- 输入证据：仓库入口、模块目录、关键链路、已有文档。
- 输出结果：拓扑草图、关键边界、待确认问题。
- 失败条件：入口或边界无法稳定确认。
- 人工澄清回退：边界不清楚时先提问。

## RED

- 常见失败：把局部实现误当系统边界、把猜测写进拓扑。

## GREEN

- 至少产出一份边界判断和一份关键链路草图。

## REFACTOR

- 若边界定义仍然过宽，继续压缩到本轮文档所需最小范围。

## 使用示例

```text
请基于仓库入口、目录结构和现有 docs，先给出这套系统的边界和主链路草图。
```
