# 源码证据抽取

## 适用场景

- 写正文前需要先沉淀事实证据。
- 现有文档可能脱离源码，需要做事实校准。

## 核心规则

- 只提炼能追溯到仓库的事实，不输出想象性结论。
- 先列事实，再标疑点和冲突。
- 关键事实缺失时先问人，不允许硬猜补齐。

## 最小节点契约

- 输入证据：仓库源码、已有文档、目标主题、few-shot 案例。
- 输出结果：结构化事实、源码落点、冲突点、缺失信息。
- 失败条件：关键事实在仓库内无法确认。
- 人工澄清回退：事实不足以支撑正文时先提问。

## RED

- 常见失败：跳过证据抽取，直接写成主观总结。

## GREEN

- 至少产出事实清单、冲突点和缺失信息。

## REFACTOR

- 若事实仍然太散，继续按主题归组。

## 使用示例

```text
请先抽取“登录到首屏”相关源码事实，不要直接生成说明文。
```
