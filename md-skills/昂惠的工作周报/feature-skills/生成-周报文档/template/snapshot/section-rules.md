# 四段拼装规则

> 从 `references/周报模板结构.md` 提炼，供 `生成-周报文档` 在拼装步骤中参考。

## 四段结构

```markdown
# 昂惠的工作周报

## 一、本周工作总结
## 二、本周工作内容
## 三、需要协调与帮助
## 四、下周工作计划
## 附件说明
## 图片说明
```

## 一、本周工作总结

**来源：** 对"二、本周工作内容"的汇总提炼（非单独输入）

**格式：**
```
本周围绕**领域一、领域二**...方向推进本周工作（MM.DD-MM.DD 第N周）：

* **抖音达人BD：** 合并所有抖音bd项 → 1-2句概括，保留关键数字
* **小红书PR种草：** 合并所有小红书pr项 → 1-2句概括，保留关键数字
```

**规则：**
- 每个 domain 1-2 句，不展开，不写细节
- 关键数字保留（达人数量、预算金额、筛选数量等）
- 口吻：资深BD，"推进/梳理/产出/完成/落地"
- 不支持 domain 的空项（如运营类不在此处展开）

## 二、本周工作内容

**来源：** `聚合-本周工作内容` 的输出（≤10 条聚合项）

**排序规则：**
1. 抖音bd 项（按原序号）
2. 小红书pr 项（按原序号）
3. 无 domain 项（运营/团建类，按原顺序）
4. 会议项

**格式：**
```
{N}. [**domain标签：**]{text}；（**进展{progress}**）
```

- 抖音bd → 加粗 `**抖音bd：**`
- 小红书pr → 加粗 `**小红书pr：**`
- 会议 → 加粗 `**会议参加：**`
- 无 domain → 不加标签，直接跟 text
- text 严格使用飞书原文，不编造细节

**进度格式：**
- `（**进展100%**）` — 已完成
- `（**进展____%**）` — 未完成/留白
- `（**进展50%**）` — 部分完成

## 三、需要协调与帮助

**来源：** 从"二"中自动提取阻塞项

**提取规则：**
| 条件 | 处理 |
|------|------|
| `progress = "____%"` 且 text 含"待/确认/跟进/申请/审批" | 提取为协调项 |
| `progress = "50%"` 等中间态且含阻塞描述 | 提取关键阻塞点 |
| 无阻塞项 | 写 `* 无` |

**格式：**
```
* 阻塞点描述（简洁，1 行）
* 另一个阻塞点
```

## 四、下周工作计划

**来源：** 飞书文档"下周计划"部分（由 `提取-本周飞书内容` 在截取时跳过，需额外提取）

**规则：**
- 逐条列出，无进度标记
- 过滤掉 `⏰YYYY-MM-DD HH:MM` 提醒时间
- 无内容时写 `* 待补充`

## 附件说明 / 图片说明

- 默认 `* --`
- 如有附件/图片再补充

## 口吻约束

| ❌ 避免 | ✅ 使用 |
|--------|--------|
| 了解、学习、构思 | 推进、梳理、产出、完成、落地 |
| 初步了解公司产品 | —（入职第一周内容，后续不再出现） |
| 尝试建联 | 建联、持续建联 |

## 领域→标签映射

| domain | "二"中的标签 | "一"中的概括键 |
|--------|-------------|---------------|
| `"抖音bd"` | `**抖音bd：**` | 抖音达人BD |
| `"小红书pr"` | `**小红书pr：**` | 小红书PR种草 |
| `"会议"` | `**会议参加：**` | —（在"一"中归入对应领域） |
| `""` | 无标签 | 运营基建（如有素材/包装类） |
