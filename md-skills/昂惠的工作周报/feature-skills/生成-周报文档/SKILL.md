# 生成-周报文档

## 依赖

- `[[../../scripts/embed-template.js]]` — 内嵌模板为 prompt block
- `[[../../scripts/embed-fewshot.js]]` — 内嵌 few-shot 为 prompt block
- `[[../../template/snapshot/周报模板结构.md]]` — 四段结构约束
- `[[../../references/聚合原则.md]]` — 领域分组关键词参考

## 输入

从 `聚合-本周工作内容` 输出的结构化列表：

```json
[
  {"domain": "抖音bd", "text": "建联25位...; 查找达人32位...", "progress": "100%"},
  ...
]
```

≤ 10 条聚合项，每条含 domain / text / progress。

## 流程

```
Phase 1（准备）          Phase 2（拼装）                          Phase 3（写盘）
步骤1 内嵌资源  ──→  步骤2 分组预览(CP0) ──→ 步骤3-6 拼装四段  ──→ 步骤7 写入文件(CP2)
                                            ↓                                    ↓
                                     步骤6.5 内容预览(CP1)                  步骤7.5 校验(CP3)
```

> 期望输出样本见 [[template/mvp/weekly-report-output.md]]，拼装规则见 [[template/snapshot/section-rules.md]]。

### Phase 1: 准备

#### 步骤 1: 内嵌静态资源

```bash
node ../../scripts/embed-template.js    # → 模板 prompt block（内嵌到 LLM 上下文）
node ../../scripts/embed-fewshot.js     # → few-shot prompt block（内嵌到 LLM 上下文）
```

> **降级：** 脚本执行失败时，LLM 直接 `read_file` 读取模板文件（`D:\FILE\Obsidian Vault\昂惠的工作周报\昂惠的工作周报-template.md`）和 few-shot 文件（`昂惠的工作周报-2026-05-31.md`），效果等同。

### Phase 2: 拼装

#### 步骤 2: 分组预览 (CP0)

> Agent 展示聚合项→周报段映射，等待人工确认"继续"后进入拼装。

```
二、本周工作内容：
  · 抖音bd 3 条（#1 #2 #3）
  · 小红书pr 2 条（#4 #5）
  · 无domain 2 条（#6 #7）
  · 会议 1 条（#8）

三、需要协调：
  · 从 #2 #3 #5 提取 N 个阻塞点

一、总结：
  · 抖音达人BD + 小红书PR种草 各 1 段
```

#### 步骤 3: 拼装"二、本周工作内容"

```
按 domain 分组输出：
  1. 抖音bd 项（#1, #2, #3...）
  2. 小红书pr 项（#4, #5...）
  3. 无 domain 项（运营/团建类，按原顺序）
  4. 会议项（#8）

每条格式：{序号}. [domain标签：]{text}；（**进展{progress}**）
```

- 抖音bd 和 小红书pr 项加粗 domain 标签（如 `**抖音bd：**`）
- 无 domain 的项不加标签
- 会议项加粗 `**会议参加：**`

#### 步骤 4: 提取"三、需要协调与帮助"

从聚合项中自动提取阻塞项：
- `progress = "____%"` 且文本含"待""确认""跟进""申请"等关键词 → 提取为协调项
- `progress = "50%"` 等中间态且含阻塞描述 → 提取关键阻塞点
- 无阻塞项时写 `* 无`

#### 步骤 5: 生成"一、本周工作总结"

```
按 domain 生成汇总段落：
  * **抖音达人BD：** 合并所有抖音bd项的 text → 一句话概括 → 提取关键数字
  * **小红书PR种草：** 合并所有小红书pr项的 text → 一句话概括 → 提取关键数字
  * **运营基建：** 或无 domain + 素材类 → 一句话概括
```

每个 domain 1-2 句，关键数字保留。

#### 步骤 6: 拼装完整周报

```
# 昂惠的工作周报

## 一、本周工作总结
{步骤 5 产出}

## 二、本周工作内容
{步骤 3 产出}

## 三、需要协调与帮助
{步骤 4 产出}

## 四、下周工作计划
{从飞书文档"下周计划"部分提取，逐条列出，无进度标记}

## 附件说明
* --

## 图片说明
* --
```

#### 步骤 6.5: 内容预览 (CP1)

> 展示完整周报预览（不写盘），确认内容无误后回复"继续"进入写盘。
> 如指出格式/分组/进度错误 → 回到对应步骤修正。

### Phase 3: 写盘

#### 步骤 7: 路径确认 + 写入 (CP2)

```
1. 展示目标路径：D:\FILE\Obsidian Vault\昂惠的工作周报\工作周报-YYYY-MM-DD.md
2. 人工确认"写入"后执行 write_file
3. YYYY-MM-DD 为当前周日日期，文件已存在则覆盖
```

#### 步骤 7.5: 写盘后校验 (CP3)

```
1. 校验文件存在且非空
2. 校验四段结构完整（含"本周工作总结""本周工作内容""需要协调与帮助""下周工作计划"）
3. 展示文件大小和行数
不通过 → 报错并检查写入权限/磁盘空间
```

## 边界条件

| 条件 | 处理 |
|------|------|
| 模板文件 `昂惠的工作周报-template.md` 不存在 | 报错：模板文件缺失，检查 `D:\FILE\Obsidian Vault\昂惠的工作周报\` 目录 |
| `embed-template.js` 或 `embed-fewshot.js` 执行失败 | 降级：LLM 直接读取模板和 few-shot 文件（不通过脚本内嵌） |
| 输出目录无写入权限 | 报错：无法写入 `{输出目录}`，检查文件夹权限 |
| 聚合项为空（0条） | 报错：无内容可生成，检查上游聚合步骤 |
| 聚合项的 `text` 为空 | 跳过该条，警告并继续 |
| "下周计划"无法从飞书文档提取 | 留空并标注 `* 待补充` |

## 关键约束

- **资深BD口吻**：避免"了解""学习""构思"，使用"推进""梳理""产出""完成"
- **工作内容文本严格使用飞书原文**，不编造细节
- **本周写进度**（进展XX%），**下周不写进度**
- 四段结构：总结 / 工作内容 / 协调帮助 / 下周计划
- 附件说明和图片说明默认为 `* --`
