# 双锚点截取模式

## 正则表达式

```regex
(\d{1,2})\.(\d{1,2})[\s\-–—]+(\d{1,2})\.(\d{1,2})
```

匹配模式示例：

| 文档原文 | 捕获组 | 解析 |
|---------|--------|------|
| `5.11-5.15` | `5`, `11`, `5`, `15` | start=5.11, end=5.15 |
| `5.18-22第三周工作记录` | `5`, `18`, `5`, `22` | start=5.18, end=5.22 |
| `5.25-5.29第四周` | `5`, `25`, `5`, `29` | start=5.25, end=5.29 |
| `4.27-4.30` | `4`, `27`, `4`, `30` | start=4.27, end=4.30 |
| `5.6-5.9工作记录` | `5`, `6`, `5`, `9` | start=5.6, end=5.9 |

## 算法

```
1. 在全文文本中扫描所有匹配的周标记
   → 构建锚点列表：[{pos, line, startDate, endDate}, ...]
   → 锚点按文档出现顺序排列（从上到下）

2. 匹配起始锚点
   → 遍历锚点列表，找 startDate === targetDateRange.start
   → 例如：target start="5.18"，匹配锚点 "5.18-22第三周工作记录"

3. 确定终止锚点
   → 终止锚点 = 锚点列表中起始锚点的下一个锚点
   → 如果起始锚点是列表最后一个 → 终止锚点 = 文档末尾（隐式）

4. 截取
   → 文本范围：[起始锚点.matchEnd, 终止锚点.pos)
   → 起始锚点.matchEnd = 起始锚点.pos + 起始锚点.fullMatch.length
```

## 示例

```
文档结构：
  ...（第一周内容）...
  5.11-5.15                      ← 锚点0, pos=500
  ...（第二周内容）...
  5.18-22第三周工作记录           ← 锚点1, pos=3200
  ...（第三周内容）...            ← 提取范围
  5.25-5.29第四周                ← 锚点2, pos=8500
  ...（第四周内容）...

提取"上周"(5.18-5.22)：
  起始锚点: 锚点1 (5.18-22第三周工作记录)
  终止锚点: 锚点2 (5.25-5.29第四周)
  截取范围: fullText[3242, 8500)

提取"本周"(5.25-5.29)：
  起始锚点: 锚点2 (5.25-5.29第四周)
  终止锚点: 文档末尾（隐式）
  截取范围: fullText[8519, fullText.length)
```

## 优势

- **不依赖"下周计划"字符串**：终止边界由下一个锚点而非文本内容决定，可靠性更高
- **支持任意周**：本周、上周、上上周、指定周均可通过 startDate 精确匹配
- **边界明确**：起始和终止都有明确定义，不会多截或少截

## 门禁

| 条件 | 处理 |
|------|------|
| 全文无周标记 | 报错：文档格式异常，未找到任何 MM.DD-MM.DD 格式的周标记 |
| 未找到匹配起始锚点 | 报错：未找到 `{targetWeek}` 对应的周标记。列出文档中可用的周范围 |
| 截取到 0 条工作项 | 报错：该周内容为空 |

## 跨月处理

周标记可能跨月（如 5.30-6.3），正则不做月份边界校验——仅匹配数字格式。跨月周的日期范围计算由 `resolveTargetWeek()` 函数的日期运算处理，不受飞书文档中周标记格式影响。

## 与 extract-week.js 的关系

此模式在 `scripts/extract-week.js` 中实现为 `extractWeek()` 函数。Agent 也可以直接调用脚本：

```bash
node scripts/extract-week.js --cache ./template/snapshot/飞书文档-全文缓存.md --start "5.25" --end "5.29"
```
