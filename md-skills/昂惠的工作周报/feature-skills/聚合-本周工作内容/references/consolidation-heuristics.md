# 聚合启发式规则

> 从 `references/聚合原则.md` 提炼，供 Agent 在聚合步骤中参考。

## 硬约束

**聚合后 ≤ 10 条。** 无论原始工作项有多少，最终输出不超过 10 条。如果首次聚合超过 10 条，放宽合并粒度重新执行。

## 六条指导原则

| # | 原则 | 判断依据 | 正例 | 反例 |
|---|------|---------|------|------|
| 1 | **同领域同层合并** | 同一平台 + 同一执行阶段 → 合并 | "建联25寄样10" + "查找32建联7" + "素材二创" → 合并为一条"抖音执行面" | "建联达人" + "预算申请" → 层级不同，不合并 |
| 2 | **预算独立** | 涉及跨部门审批（财务/人事/内控）→ 独立成条 | "2000投流预算申请"单独成条 | 预算合并到"执行面" → 错误 |
| 3 | **策略独立** | 长期方向探索/策略规划 → 独立成条 | "星图付费达人名单+好梦组品方案"独立成条 | 策略规划合并到日常执行 → 错误 |
| 4 | **跨平台分开** | 抖音和小红书永远不合并 | 抖音执行面 #1 + 小红书执行面 #4 各自独立 | 抖音+小红书合并 → 错误 |
| 5 | **会议汇聚** | 所有会议 → 合并为一条 | "安睡裤拉齐会议"合并为一条，标注关键结论 | 会议分散在多条 → 浪费条目名额 |
| 6 | **单项独立** | 非达人任务（包装采购、团建）→ 各自独立 | "包装采购"独立一条，"团建"独立一条 | 团建合并到会议 → 错误 |

## 平台/层级标注维度

Agent 在通读原始项时，为每条标注：

```
平台：抖音 / 小红书 / 通用
层级：执行 / 策略 / 预算 / 运营 / 会议
```

标注后按"同平台 + 同层级"初步分组，再判断是否同一执行阶段决定是否合并。

## 混合进度处理

| 场景 | 输出 |
|------|------|
| 所有子项 checked=true | `进展100%` |
| 所有子项 checked=false | `进展____%`（留白供人类填写） |
| 子项进度不一致 | Agent 给整体估计值，**不取 max 也不取 min** |

常见混合进度示例：

| 子项A | 子项B | 整体评估 | 理由 |
|-------|-------|---------|------|
| 规划完成 ✅ | 预算待审批 ❌ | `进展50%` | 规划完成但资金未到位，一半进度 |
| 大部分完成 ✅ | 一项卡住 ❌ | `进展70%` | 主体完成，单一阻塞 |
| 建联完成 ✅ | 寄样完成 ✅ | `进展100%` | 全部完成 |

## 输出格式

```json
[
  {"domain": "抖音bd", "text": "建联25位达人寄样10位...; 查找达人32位...", "progress": "100%"},
  {"domain": "抖音bd", "text": "2000投流费用预算申请...", "progress": "____%"},
  ...
]
```

- `domain`：`"抖音bd"` | `"小红书pr"` | `"会议"` | `""`（无领域）
- `text`：合并文本，子项间分号连接，**保留飞书原文不编造**
- `progress`：`"100%"` | `"____%"` | `"50%"` 等

## Agent 判断流程

```
1. 通读所有原始项 → 标注 平台/层级
2. 同平台+同层级 → 判断是否同一执行阶段 → 是则合并
3. 预算/策略项 → 判断独立价值 → 独立成条
4. 会议项 → 全部汇聚为一条
5. 计数 → 如 > 10 条，放宽合并粒度重新执行步骤 2-3
6. 混合进度处理 → 子项进度不一致时给整体估计值
7. 输出
```
