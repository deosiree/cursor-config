# 编排-生成工作周报

## 输入

| 参数 | 说明 | 默认值 |
|------|------|--------|
| targetWeek | `"本周"` / `"上周"` / `"上上周"` / `"5.18那周"` / `"5.18-5.22"` | `"本周"` |

如用户未指定，默认生成本周周报。

## 编排步骤

### 步骤 1：日期确认

```
获取当前日期 + targetWeek 参数
→ 按自然语言映射规则计算目标周的周一~周五
→ 输出：{start: "5.25", end: "5.29"}
```

- 当前日期 2026-05-31(周日)，`targetWeek="本周"` → 5.25(周一)~5.29(周五)
- 当前日期 2026-05-31(周日)，`targetWeek="上周"` → 5.18(周一)~5.22(周五)
- 详细映射表见 `feature-skills/提取-本周飞书内容` §2 步骤 A

**数据格式约定（步骤间传递）：**

步骤 2→3 传递格式：
```json
[{"text":"建联25位达人...","checked":true,"day":"周二"}, ...]
```

步骤 3→4 传递格式：
```json
[{"domain":"抖音bd","text":"建联25位...; 查找达人32位...","progress":"100%"}, ...]
```

步骤 4→5 传递格式：`"D:\\FILE\\Obsidian Vault\\昂惠的工作周报\\工作周报-2026-05-31.md"`

### 步骤 2：提取本周内容

```
调用 feature-skills/提取-本周飞书内容
→ 输入：飞书URL、日期范围 {start, end, label}
→ 输出：[{text, checked: boolean, day}, ...]  ← 约17条原始项
```

**门禁：**
- 提取内容为空 → 报错：未找到本周内容（`{label}`），检查飞书文档是否已更新
- 提取到其他周内容 → 报错：匹配到非本周内容，人工确认

### 步骤 3：聚合工作内容

```
调用 feature-skills/聚合-本周工作内容
→ 输入：[{text, checked, day}, ...] 约17条
→ 输出：[{domain, text, progress}, ...]  ≤10条聚合项
```

**门禁：**
- 聚合后 0 条 → 报错
- 聚合后 >10 条 → 重新聚合

### 步骤 4：生成周报

```
调用 feature-skills/生成-周报文档
→ 输入：≤10条聚合项、输出路径(工作周报-YYYY-MM-DD.md)
→ 输出：周报 .md 文件路径
```

### 步骤 5：最终落盘

```
1. read_file 读取周报 .md 文件
2. 校验：文件存在、非空、含"本周工作总结"
3. 输出 Markdown 原文（用户直接复制粘贴到微信/飞书/邮件）
```

**边界条件：**
- 文件不存在 → 报错：周报未生成，检查步骤4
- 文件为空 → 报错：写入失败
- 缺少结构标记 → 警告但继续输出

## 检查点

| 时机 | 触发条件 | 动作 |
|------|----------|------|
| **步骤 2 之后** | 提取内容 > 0 条 | 展示提取到的日期范围和条目数，等待人工确认"继续"后再进入聚合 |
| **步骤 3 之后** | 聚合完成 | 展示聚合结果摘要（条数、各领域分布），等待人工确认"继续"后再生成 |
| **步骤 4 之后** | 文件写入成功 | 展示文件路径和内容概要，等待人工确认"落盘"后输出最终文本 |

如人工在任一检查点回复"不对"或指出错误，回到对应步骤重新执行。

## 关键约束

- 步骤 2 提取为空时不继续
- 步骤 3 聚合 >10 条时重新聚合
- 任何步骤失败不回退，需人工介入
