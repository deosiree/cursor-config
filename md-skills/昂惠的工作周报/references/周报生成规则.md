# 周报生成规则

## 数据源

- **飞书文档：** `https://zru9fxhvq5.feishu.cn/wiki/IbuLwEv7fituvMkrSaWc86CjncX`
- **读取方式：** OpenCLI browser（用户已登录飞书）
- **文档结构：** 从上到下按周排列，最新周在最下面

## 周定位（自然语言 → 日期范围 → 双锚点截取）

### 第一步：自然语言 → 日期范围

| 用户输入 | 映射 | 示例（当前 2026-05-31） |
|---------|------|----------------------|
| 本周 / 这周 / 不指定 | 当前日期所在周的周一~周五 | 5.25-5.29 |
| 上周 | 上一周的周一~周五 | 5.18-5.22 |
| 上上周 | 上上周的周一~周五 | 5.11-5.15 |
| 5.18那周 | 指定日期所在周的周一~周五 | 5.18-5.22 |
| 5.18-5.22 | 直接使用 | 5.18-5.22 |

### 第二步：双锚点截取

1. 扫描全文匹配所有周标记（正则：`(\d{1,2})\.(\d{1,2})-(\d{1,2})\.(\d{1,2})`）
2. 起始锚点 = startDate 匹配目标 start 的周标记
3. 终止锚点 = 锚点列表中起始锚点的下一个锚点（若为最后一个则用文档末尾）
4. 截取 [起始锚点, 终止锚点) 之间的文本

**示例：** 提取上周(5.18-5.22)，起始锚点="5.18-22第三周工作记录"，终止锚点="5.25-5.29第四周"

## 勾选状态检测

- 已勾选 `[x]`：飞书文档中 `span[data-leaf].className` 包含 `todo-line-through`
- 未勾选 `[ ]`：无此类名
- 检测时注意飞书虚拟滚动限制，需分段滚屏覆盖全部 items
- **已勾选 → 进度100%**，**未勾选 → 进展____%**

## 周报口吻

- 用户是资深BD，非职场新人
- 用"推进/梳理/产出/完成/落地"替代"了解/学习/构思"
- 工作总结体现对公司业务的价值

> ⚠️ "避免'了解/学习/构思'"规则仅适用于**"一、本周工作总结"**的提炼措辞。
> **"二、本周工作内容"**严格使用飞书文档原文，即使包含"了解/学习"也不改写。

## 领域分类

| 领域 | 典型内容 |
|------|---------|
| 抖音达人BD | 建联、寄样、投流、星图、挂车、达人查找 |
| 小红书PR种草 | 种草、小红书、达人建联、测评博主、报价筛选、KOC、预算 |
| 素材 & 内容二创 | 素材、二创、千川 |
| 运营 & 规划 | 包装、采购、费用、立项 |
| 会议 | 各类会议（合并为一条） |
| 入职融入 | 了解、熟悉、学习、构思、建立资源库等 onboarding 类 |

## 特殊周处理

| 场景 | 特征 | 处理 |
|------|------|------|
| 入职第一周 | 原始项含"了解""熟悉""学习"等 onboarding 关键词 | 领域归为"入职融入"，不套用抖音bd/小红书pr分类；工作总结用资深措辞，工作内容保留原文 |
| 部分周 | 仅周一~周三有记录，缺某几天 | 按已有数据生成，不编造 |
| 空白周 | 飞书文档该周无任何记录 | 报错终止 |

## 进度标记

- 本周工作内容：每项末尾标注进度
- 下周工作计划：不写进度
- 混合进度：合并的多子项进度不一致时，给整体估计值（如50%、70%）
