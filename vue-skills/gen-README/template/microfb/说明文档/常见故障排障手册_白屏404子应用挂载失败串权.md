# 说明文档：常见故障排障手册（白屏 / 404 / 子应用挂载失败 / 串权）

本文档目标：把 `microfb` 常见故障按“状态链路”映射成可执行的排查清单，减少临场猜测与重复沟通。

## 1. 总原则（先定性再定位）

- **先判断是 base/路由问题，还是菜单/权限问题，还是子应用入口问题**。
- **排查顺序建议**：Base 一致性 → 会话信号 → 菜单缓存 → routesLoaded/动态路由 → 子应用 entry/容器 → props 同步/串权。

## 2. 白屏（页面空白或卡在加载）

### 2.1 可能原因

- base 配置不一致：`VITE_APP_BASE` 与实际部署路径不一致导致资源/路由异常
- 守卫异常进入恢复：发生异常后跳转 host 登录但被浏览器拦截/配置缺失
- 子应用挂载失败：容器不存在或 entry 不可达，导致局部白屏

### 2.2 排查清单

- **base 是否正确**
  - 看 `getAppBase()` 返回值是否符合部署路径
  - 守卫是否使用 `stripBasePath()` 剥离 base 后再判断入口/白名单
- **会话信号是否存在**
  - `Auth.isLoggedIn()` 是否因为 `Storage.get('userInfo')` 为空而返回 false（导致一直跳登录）
- **子应用是否被启动**
  - `router.isReady()` 后是否执行 `registerApps()`
  - 容器选择器是否为 `#subapp-container`

## 3. 404（刷新或跳转后进入 /404）

### 3.1 可能原因

- 动态路由未注入（`routesLoaded=false`）
- 动态路由生成失败或并发互斥等待超时导致放行
- 菜单缓存为空/无可用路由路径

### 3.2 排查清单

- **先看守卫分支**
  - 是否在 `handleAuthenticatedUser` 中走了 `generateAndAddRoutes`
  - 是否进入了 `to.matched.length===0 → next('/404')`
- **看并发互斥**
  - 是否出现 `isGeneratingRoutes=true`，其他导航在 `waitForRoutesGeneration()` 里 5s 超时放行
- **看菜单缓存**
  - `readMenuCache().menus` 是否为空
  - `findFirstValidMenuPath(menus)` 是否返回 null

## 4. 子应用挂载失败（Apex/Opsdeck 不显示或一直 loading）

### 4.1 可能原因

- entry 不可达（dev 下 dynamic 端口未起）
- `VITE_SUBAPP_MODE` 配置导致 entry 选择与预期不符
- 容器 id/selector 不一致（`#subapp-container`）

### 4.2 排查清单

- **dev 下看 auto 回退**
  - `auto` 模式下 `canReachSubAppEntry(dynamicEntry)` 探活失败应回退 static
- **static 入口依赖**
  - static 入口通常是 `/Apex?isSubApp=true`，需要本地静态目录服务/构建产物就绪
- **activeRule/routerBase 一致性**
  - `activeRule` 应以 `${getAppBase()}${APEX_ROUTE_ROOT}` 形式拼接

## 5. 串权（切换账号后仍看到旧菜单/旧权限/子应用沿用旧数据）

### 5.1 可能原因

- 登出未清理 `userInfo/menuCache`
- 未清空子应用 props（子应用沿用旧 menuList/userInfo）
- 子应用未按 `menuVersion` 感知变化并刷新

### 5.2 排查清单

- **登出是否强解散**
  - `logout()` 是否在 finally 执行 `resetUserState()`（清 userInfo + clearMenuCache）
  - 是否遍历 enabled appConfigs 清空子应用 props，并带 `forceReloadToken`
- **子应用同步契约**
  - 子应用是否使用 `menuVersion` 作为变更信号，触发内部刷新
