# Feature Specification: 技能库生命周期治理

**Feature Branch**: `feat/issue-pr-loop-dag-swarm`（当前工作分支；本次未创建新分支）

**Created**: 2026-11-27

**Status**: Draft

**Input**: User description: "盘点并治理已废弃、未完成及迁移重复的 Skill。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 识别技能状态与用途 (Priority: P1)

仓库维护者需要知道哪些技能仍在使用、哪些虽未完成但仍有价值、哪些已被替代，以及哪些用途尚不明确，从而决定后续维护顺序。

**Why this priority**: 只有先区分可触发入口、内部子流程和参考材料，才能避免把目录规模或文件外观误当成实际可用能力。

**Independent Test**: 对审查范围内的每个技能入口抽查状态、用途证据、引用关系和建议处置；单独完成此项即可形成可审阅的治理清单。

**Acceptance Scenarios**:

1. **前提** 仓库中存在技能入口、嵌套子流程、模板和示例，**当** 维护者完成盘点，**则** 每个候选项都有生命周期状态、是否可触发、用途证据和处置建议。
2. **前提** 某个嵌套文件没有独立入口元数据，**当** 尚未确认其加载方式，**则** 它被标记为待核实的子流程或引用材料，不因缺少元数据而判定为废弃。
3. **前提** 某个技能长期未更新但仍有有效调用或引用，**当** 维护者评估其状态，**则** 年龄只作为检查线索，不作为单独停用或删除理由。

---

### User Story 2 - 让入口描述与实际能力一致 (Priority: P1)

维护者需要让发现顺序、父子技能路由和仓库入口文档准确反映当前可用能力，避免用户被引导到未实现或不存在的内容。

**Why this priority**: 错误的能力声明会让用户依赖无法完成的流程，也会使维护者无法判断某个目录是否仍为正式入口。

**Independent Test**: 对每个仍可触发的入口执行路由和链接核对，确认目标存在、状态准确且描述的能力可以使用。

**Acceptance Scenarios**:

1. **前提** 父技能宣称支持但子流程仍未完成，**当** 该能力未获准进入近期补全范围，**则** 用户无法被路由到该未完成流程，且父技能不再将其描述为当前可用能力。
2. **前提** 入口文档引用不存在的目录或文件，**当** 文档与发现顺序完成校正，**则** 所有保留的入口和链接都指向现存且状态一致的目标。
3. **前提** 废弃技能仍有登记或仓库引用，**当** 维护者检查是否清理，**则** 先核对调用、引用和替代关系，再提出清理项供确认。

---

### User Story 3 - 安全处理迁移重复与关联资料 (Priority: P2)

维护者需要比较迁移前后的技能差异，选定唯一主入口，同时明确保留、迁移或删除旧技能中的样例、术语资料和生成结果。

**Why this priority**: 仅凭迁移说明或目录名称删除旧路径，可能丢失新路径未承接的能力或仍有价值的资料。

**Independent Test**: 为一组重复或迁移中的技能列出差异、真实调用、主入口选择和关联资料处置结论，并由维护者复核。

**Acceptance Scenarios**:

1. **前提** 迁移前后的技能内容并不相同，**当** 维护者比较它们，**则** 独有能力、脚本、调用方和关联资料都进入差异记录，且不能只凭迁移声明删除旧技能。
2. **前提** 两个路径承载相同用途，**当** 维护者选定主入口，**则** 保留路径有明确的唯一主入口，其他路径有迁移、停用或待决状态。
3. **前提** 旧目录包含样例、术语文件或输出结果，**当** 清理方案涉及这些资料，**则** 每项都有保留、迁移或删除决定；未经用户确认不得删除未评估资料。

---

### User Story 4 - 复核治理结果 (Priority: P2)

维护者需要在治理完成后确认剩余入口、替代关系和仓库引用彼此一致，并能解释每项停用或删除决定。

**Why this priority**: 没有结果复核，局部清理可能留下失效路由、孤立引用或无法追溯的资料损失。

**Independent Test**: 独立复核治理清单与仓库入口，确认每个可触发入口都有唯一目标，且清理项可以追溯到证据和确认记录。

**Acceptance Scenarios**:

1. **前提** 一项技能或路径被停用、迁移或删除，**当** 维护者复核引用，**则** 仓库入口、父子路由和模块登记中不再存在指向该失效路径的有效引用。
2. **前提** 有技能用途仍不明确或加载方式未确认，**当** 本轮治理结束，**则** 未决事项保留为待核实状态，不被伪装成已确认废弃。

### Edge Cases

- 只有更新时间较早的技能仍被有效调用时，必须保留并记录其使用证据。
- 缺少独立入口元数据的文件可能是运行时加载的子流程；加载关系未核实前不能按独立入口规则处置。
- 新旧迁移路径都存在时，目录名、内容相似度或迁移声明都不足以单独证明其中一个可删除。
- 找不到调用记录不等于确认无人使用；缺乏证据时应标记为用途不明并提出核实动作。
- 历史清单中的文件数量、路径和仓库状态可能已变化，实施时必须以目标 checkout 重新盘点。
- 任何会删除技能、子模块登记或关联资料的动作，都必须有明确的引用检查、资料处置结论和用户确认。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 维护者必须对仓库内审查范围的技能入口及相关嵌套材料建立清单，并区分可触发入口、内部子流程、模板、示例和参考资料。
- **FR-002**: 维护者必须为每个审查候选记录生命周期状态、是否可触发、用途证据、调用或引用关系、替代关系及建议处置；证据不足时必须标记为用途不明或待核实。
- **FR-003**: 维护者必须使用“在用”“未完成但仍需要”“已被替代”“无明确用途”作为主要生命周期分类，并允许标记待核实状态；更新时间和缺少入口元数据均不得单独构成停用或删除理由。
- **FR-004**: 仓库的发现顺序、父子路由和入口说明必须与技能实际状态一致；未完成能力不得被声明为当前可用或继续作为可触发目标。
- **FR-005**: 对废弃或迁移路径的清理必须建立在调用、仓库引用、替代关系和关联资料检查之上；删除动作须经用户确认后执行。
- **FR-006**: 对迁移重复的技能，维护者必须比较新旧内容、独有能力、脚本和调用方，并确定唯一主入口或记录尚未决策的原因。
- **FR-007**: 对迁移目录中的样例、术语资料和输出结果，维护者必须分别记录保留、迁移或删除结论；未评估或未获确认的资料不得删除。
- **FR-008**: 治理后的有效入口、仓库文档、模块登记和本地引用必须指向存在且状态一致的目标；被移除或改名的路径不得留下有效引用。
- **FR-009**: 本次治理必须只处理盘点确认的生命周期、路由和引用问题；不要求逐个重写所有技能，也不自动创建 Issue、PR 或进行其他对外操作。

### Key Entities

- **技能候选项**：被纳入盘点的正式入口、子流程或辅助材料，包含路径、用途和当前状态。
- **生命周期判定**：对候选项的状态、触发能力、证据、替代关系和处置建议的记录。
- **路由入口**：把用户或父技能引向具体技能能力的发现项、父子关系或入口说明。
- **迁移关系**：原路径与新路径之间的能力承接、差异、调用关系和主入口决定。
- **关联资料**：与技能配套的样例、术语、输入和输出资料及其保留决定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 纳入审查范围的候选项都有状态、可触发性、证据和处置建议；未能判定的项目明确留在待核实清单中。
- **SC-002**: 100% 保留的可触发入口都指向存在的目标，且父级说明与目标实际支持状态一致。
- **SC-003**: 治理中因更新时间较早或缺少入口元数据而单独停用或删除的项目为 0。
- **SC-004**: 100% 拟清理路径都完成调用、引用、替代关系和关联资料检查，并有用户确认记录。
- **SC-005**: 100% 迁移重复项都有唯一主入口，或有明确的待决原因；所有关联资料都有保留、迁移或删除结论。
- **SC-006**: 治理结束后，仓库入口与本地引用中指向不存在路径的有效引用为 0。

## Assumptions

- 上一轮盘点的文件数量、路径和个别候选结论仅作为检查线索，不能代替对当前工作副本的复核。
- 初始复核重点包括未完成的 VSCode 扩展迁移场景、已声明废弃的旧 Wiki 技能、翻译技能迁移重复、入口文档漂移，以及缺少独立入口元数据的嵌套流程。
- 翻译技能目录中的样例、术语文件和输出结果按独立资料评估，不随技能入口自动删除。
- 本规格只准备本地治理结果，不授权创建或更新远端 Issue、PR。
- 受影响范围可使用现有静态核对和 Darwin 流程抽样验证；不要求对仓库所有技能进行全量行为评测。
- 进入实施前，维护者需要复核候选范围、翻译资料处置边界及需要用户确认的清理项。

## Out of Scope

- 对所有技能逐一进行内容重写、质量进化或行为评测。
- 补全未完成技能所代表的完整产品能力；如确认仍有需求，应另行立项。
- 未经用户确认直接删除技能、关联资料、子模块登记或创建、更新远端协作事项。
