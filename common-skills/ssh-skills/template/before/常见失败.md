# Before — 常见失败

## 场景 A：kubectl logs 无输出

- `kubectl logs --tail=10000` 返回空 → 日志已滚动 → 改用 `-f` 实时跟
- grep 模式写错（大小写/中英文符号）→ 先 `kubectl logs ... | tail -50` 看原始日志格式
- Pod 名不对（hash 变化 / 命名空间错）→ `kubectl get pods -n platform` 确认

## 场景 B：plink 连接失败

- `Cannot confirm host key` → 缺 `-hostkey` 参数
- `Access denied` → 密码错或 SSH key 未设
- `plink: unknown option` → plink 版本不兼容参数

## 场景 C：多次 SSH 命令执行

- 每次 SSH 都是独立连接 → 不要在一条命令里 `kubectl get pods` 再 `kubectl logs`
- 换行符导致 plink 执行中断 → 确保命令是单行或 ` ` 拼接

## Agent 典型错误

- 不读前置检查直接执行 plink → host key 未缓存
- 硬编码 Pod hash → 下次部署后失效
- 把 `seccenter-v2-` 当完整 Pod 名 → `kubectl logs` 返回模糊匹配错误
