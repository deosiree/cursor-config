# 场景：权限与登录态诊断

## 适用条件

用户要排查 nebula **权限后门（`isOwner`）**、**登录后 Header/子应用按钮不显示**、或 **`checkHasPerm` 与 session 不一致** 等问题；需要用 OpenCLI 读 `sessionStorage`、模拟 bypass、验证登录后 UI **无需整页刷新**。

| 典型 prompt | 路由 |
|-------------|------|
| 租户所有者为什么没有 bypass | 本文件 + `opencli-ux-user-perm/references/perm-bypass-isOwner-pitfalls.md` |
| 登录后个人中心不显示 | 本文件 § Header 下拉断言 |
| isOwner / sessionStorage 诊断 | 本文件 § session 诊断 eval |
| 用户列表操作列 perm | → `opencli-ux-user-perm/feature-skills/操作列权限诊断/` |

## 环境与账号

| 项 | 值 |
|----|-----|
| 基座 | `http://localhost:8080/cloud/login` |
| 默认账号 | `admin@system.local` / `123456` |
| Session 名 | `nebula-ux` 或 `nebula-perm-test` |
| 登录 API | `POST /dev-api/direct/seccenter/v2/auth/login` |

## 执行流程

### 0. 前置

```bash
opencli doctor
opencli browser nebula-ux open "http://localhost:8080/cloud/login"
```

### 1. 清空旧 session（测冷启动 / 半登录态）

```bash
opencli browser nebula-ux eval "sessionStorage.removeItem('userInfo'); 'cleared';"
opencli browser nebula-ux eval "location.reload()"
```

### 2. 登录（ref 来自 state，勿硬编码）

```bash
opencli browser nebula-ux state
# 找 placeholder=请输入手机号/邮箱地址、请输入密码 的 [N] ref

opencli browser nebula-ux type <账号ref> "admin@system.local"
opencli browser nebula-ux type <密码ref> "123456"
opencli browser nebula-ux click "button:has(span)" --nth 0
```

等待跳离 `/login`（约 3–5s），**不要** `location.reload()`。

### 3. session 诊断 eval（核心）

```bash
opencli browser nebula-ux eval "(function(){
  const u=JSON.parse(sessionStorage.getItem('userInfo')||'null');
  const perms=u?.permissions||u?.perms||[];
  const bypass=u?.isOwner===true;
  function check(p){
    if(bypass) return true;
    if(!Array.isArray(perms)||!perms.includes(p)) return false;
    const meta=u?.permsMap?.[p];
    if(!meta) return false;
    if(meta.isVisible===false) return false;
    if(meta.isSystemOnly===true&&u?.isSystem!==true) return false;
    return true;
  }
  const keys=['sys:profile:view','sys:dashboard:view','sys:tenant:query'];
  const tests={};
  keys.forEach(k=>{ tests[k]=check(k); });
  return JSON.stringify({
    url:location.href,
    hasUserInfo:!!u,
    isOwner:u?.isOwner,
    isOwnerStrict:bypass,
    isSystem:u?.isSystem,
    permsLen:perms.length,
    tests
  });
})()"
```

**解读：**

- `isOwnerStrict: true` → bypass 应放行所有 perm 校验。
- `isOwnerStrict: false` 且某 `tests.*: false` → 正常按角色 perm + permsMap 拦截（非 bug）。
- `hasUserInfo: false` 但仍在业务页 → 半登录态，需重登。

### 4. 负向：模拟 isOwner 丢失

```bash
opencli browser nebula-ux eval "(function(){
  const u=JSON.parse(sessionStorage.getItem('userInfo'));
  u.isOwner=false;
  sessionStorage.setItem('userInfo', JSON.stringify(u));
  return 'tampered';
})()"
opencli browser nebula-ux eval "location.reload()"
# 子应用首页应出现「暂无权限查看首页」（若已加 sys:dashboard:view 守卫）
```

### 5. Header 下拉断言（登录后勿 reload）

```bash
opencli browser nebula-ux state
# 找 user-profile 旁 aria-haspopup=menu 的 ref

opencli browser nebula-ux click <用户下拉ref>
opencli browser nebula-ux eval "(function(){
  const items=[...document.querySelectorAll('[role=menuitem]')].map(el=>(el.textContent||'').trim());
  return JSON.stringify({
    profileVisible: items.includes('个人中心'),
    logoutVisible: items.includes('退出登录'),
    menuItems: items.filter(t=>t==='个人中心'||t==='退出登录')
  });
})()"
```

**通过标准（fix 后）：** `profileVisible: true` 且当前 URL 仍是登录跳转结果（未手动 reload）。

### 6. 登录 API 对照（可选）

```bash
opencli browser nebula-ux network --detail "POST localhost:8080/dev-api/direct/seccenter/v2/auth/login"
# 检查 $.data.user.isOwner === true
```

## 与源码的对应关系

| 层级 | 读什么 | bypass |
|------|--------|--------|
| microfb `checkHasPerm` | `sessionStorage.userInfo` | `isOwner===true` |
| apex 子应用 `checkHasPerm` | 同上（qiankun `syncUserInfoFromHost` 写入） | 同上 |
| 路由守卫 `Auth.isLoggedIn` | 有 `id` 或 `username` 即视为已登录 | 不 bypass |
