## 快速开始（Agent 执行路径）

读取本文件后，按以下步骤生成可执行脚本：

```
1. 复制 template/新脚本模板.sh 为 {场景名}.sh
```

| 方向 | 内容 | 示例 |

## 原理

OpenCLI `browser` 子命令驱动真实 Chrome，**就像一个人在操作浏览器**：

```
用户操作 → opencli browser 命令 → Chrome 扩展 → 真实浏览器执行 → 返回结果
```

区别在于代码可重复、可编排、不会手抖。

## 核心命令模式

```bash
SESSION="my-session"

# 1. 打开页面（或绑定已有标签）
opencli browser $SESSION open "https://example.com/login"

# 2. 等待页面加载
opencli browser $SESSION wait text "用户名" --timeout 10000

# 3. 填写表单
opencli browser $SESSION fill --role textbox --name "用户名" "admin"
opencli browser $SESSION fill --role textbox --name "密码" "******"

# 4. 点击按钮
opencli browser $SESSION click --role button --name "登录"

# 5. 等待操作结果
opencli browser $SESSION wait text "登录成功" --timeout 10000

# 6. 截屏确认
opencli browser $SESSION screenshot "./after-login.png"

# 7. 获取当前 URL 确认跳转
opencli browser $SESSION get url
```

## 高级操作

### eval 直接执行 JS（最灵活）

当 click/fill 基于 role 定位不精确时，直接用 JS：

```bash
# 点击特定元素
opencli browser $SESSION eval "
  document.querySelector('.dialog-footer .el-button--primary').click();
"

# 设置输入框值（触发表单校验）
opencli browser $SESSION eval "
  const input = document.querySelector('input[placeholder=\"角色名称\"]');
  const nativeInputValueSetter = Object.getOwnPropertyDescriptor(
    window.HTMLInputElement.prototype, 'value'
  ).set;
  nativeInputValueSetter.call(input, '测试角色');
  input.dispatchEvent(new Event('input', { bubbles: true }));
  input.dispatchEvent(new Event('change', { bubbles: true }));
"

# 滚动页面
opencli browser $SESSION eval "window.scrollTo(0, document.body.scrollHeight);"

# 获取完整页面信息（结构化返回）
opencli browser $SESSION eval "
  JSON.stringify({
    title: document.title,
    url: location.href,
    visibleButtons: [...document.querySelectorAll('button')].map(b => b.innerText.trim()),
  });
"
```

### 登录会话管理

**方式一：自动登录**
```bash
opencli browser $SESSION open "http://localhost:8080/login"
sleep 1
opencli browser $SESSION fill --role textbox --name "账号" "admin"
opencli browser $SESSION fill --role textbox --name "密码" "123456"
opencli browser $SESSION click --role button --name "登录"
# 等待跳转
for i in $(seq 1 30); do
  url=$(opencli browser $SESSION get url)
  [[ "$url" != *"/login"* ]] && break
  sleep 1
done
```

**方式二：手动登录后 bind**
```bash
# 人在浏览器手动登录
opencli browser $SESSION open "https://cloud.example.com/login"
# 手动操作... 登录完成后：
opencli browser $SESSION bind
# 现在 session 已绑定到登录后的标签
```

**方式三：复用已有 session**
```bash
# 如果 session 已存在且有有效登录态
opencli browser $SESSION get url  # 检查是否还在登录页
```

### 多步操作编排

```bash
#!/usr/bin/env bash
set -euo pipefail

SESSION="auto-task"
BASE="https://example.com"

# 步骤 1: 登录
echo "==> 登录"
opencli browser $SESSION open "$BASE/login"
opencli browser $SESSION fill --role textbox --name "用户名" "${USER}"
opencli browser $SESSION fill --role textbox --name "密码" "${PASS}"
opencli browser $SESSION click --role button --name "登 录"
sleep 3

# 步骤 2: 导航到操作页
echo "==> 导航到报表页面"
opencli browser $SESSION open "$BASE/report/export"
opencli browser $SESSION wait text "导出报表" --timeout 15000

# 步骤 3: 选择参数
echo "==> 设置导出参数"
opencli browser $SESSION click --role combobox --name "时间范围"
opencli browser $SESSION click --role option --name "本月"
opencli browser $SESSION fill --role textbox --name "接收邮箱" "me@company.com"

# 步骤 4: 提交
echo "==> 提交导出请求"
opencli browser $SESSION click --role button --name "导出"
opencli browser $SESSION wait text "导出任务已提交" --timeout 10000
echo "✅ 完成"

# 步骤 5: 截图确认
opencli browser $SESSION screenshot "./export-submitted.png"
```

## 与测试场景的区别

| 方面 | 自动化测试 | 手动点击自动化 |
|------|-----------|---------------|
| 目标 | 验证正确性 | 完成实际业务操作 |
| 输出 | 断言结果（通过/失败） | 操作结果（数据/文件/状态） |
| 失败处理 | 失败 + 截图 + 退出 | 重试 / 告警 / 跳过 |
| 验证点 | DOM 断言 | 操作是否完成 |
| 典型用途 | CI/CD 回归 | 日常自动化任务 |

## 完整示例：导出销售报表（基于模板）

以下是从 `template/新脚本模板.sh` 修改的具体场景：

```bash
#!/usr/bin/env bash
# ═══════════════════════════════════════════════
# 导出销售报表 — 每日定时任务
# ═══════════════════════════════════════════════

set -euo pipefail

# ── 配置区 ──
SESSION="nebula-ux"
BASE_URL="https://sales.company.com"
ACCOUNT="report-bot@company.com"
PASSWORD="$(cat ./config/.sales-pwd 2>/dev/null || echo "CHANGE_ME")"
SCREENSHOT_DIR="./screenshots"
mkdir -p "$SCREENSHOT_DIR"

# ── 工具函数（从 template/新脚本模板.sh 复制） ──
oc() { opencli browser "$SESSION" "$@" 2>&1; }
screenshot() { oc screenshot "${SCREENSHOT_DIR}/${1:-debug}.png" >/dev/null 2>&1 || true; }
log_step() { echo "==> [$1] $2"; }

# ── 主流程 ──
main() {
  # 1. 打开报表页（假设已有 session）
  log_step "nav" "打开报表页"
  oc open "$BASE_URL/report/export"
  oc wait text "导出报表" --timeout 20000 || { screenshot "nav-fail"; exit 1; }

  # 2. 选择时间范围
  log_step "param" "选择时间范围"
  # Element Plus select: click --name 可能失败，eval 兜底
  oc eval "document.querySelector('.el-date-editor .el-input__inner').click()" || {
    oc click --role combobox --name "时间范围" || true
  }
  sleep 1
  oc eval "[...document.querySelectorAll('.el-select-dropdown__item')].find(el => el.innerText.includes('本月'))?.click()"

  # 3. 填写接收邮箱
  log_step "param" "填写接收邮箱"
  oc fill --role textbox --name "接收邮箱" "${ACCOUNT}" || {
    oc eval "
      const i = document.querySelector('input[placeholder*=\"邮箱\"]');
      if(i) { i.value = '${ACCOUNT}'; i.dispatchEvent(new Event('input', {bubbles:true})); }
    "
  }

  # 4. 导出
  log_step "export" "提交导出请求"
  oc click --role button --name "导出" || {
    oc eval "document.querySelector('.el-button--primary').click()"
  }
  oc wait text "导出任务已提交" --timeout 15000 || {
    screenshot "export-fail"
    echo "⚠️ 导出提交可能失败，请检查截图"
    exit 1
  }

  screenshot "export-success"
  echo "✅ 导出任务已提交"
}

main "$@"
```

将此脚本保存后：
```bash
bash export-report.sh              # 首次（自动登录）
bash export-report.sh --skip-login  # 后续（复用 session）
```

> 定时执行：在 crontab 中添加 `0 8 * * * cd /path/to && bash export-report.sh --skip-login >> ./logs/export.log 2>&1`
