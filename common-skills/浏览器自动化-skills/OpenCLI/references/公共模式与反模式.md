# 公共模式与反模式

> 从 `test-skills/opencli-ux-role-tab-validation` 和 `test-skills/opencli-ux-tenant` 的 `lib/common.sh` 中提取的可复用模式。适用于自动化测试、手动操作、爬虫三大场景。

---

## 模式

### P1: eval JSON 断言（最通用）

```bash
# 用 eval 返回结构化 JSON，Python 提取字段做断言
result=$(opencli browser $SESSION eval "
  JSON.stringify({
    exists: !!document.querySelector('.el-dialog'),
    activeTab: document.querySelector('.el-tabs__item.is-active')?.innerText?.trim(),
    toast: document.querySelector('.el-message')?.innerText?.trim(),
  });
")
echo "$result" | python3 -c "
import sys, json
d = json.load(sys.stdin)
assert d.get('exists'), '弹窗未出现'
print('PASS: 弹窗存在, activeTab=' + d.get('activeTab', ''))
"
```

**来源：** `assert_role_dialog_tab`, `assert_role_form_error`（lib/common.sh）
**优势：** 一次 eval 获取多个断言点，减少浏览器交互次数

### P2: click → eval 兜底

```bash
# 先用 click --name，失败后用 eval JS 兜底
opencli browser $SESSION click --role button --name "确定" >/dev/null 2>&1 || {
  opencli browser $SESSION eval "
    (function(){
      const label = '确定';
      const footer = document.querySelector('.dialog-footer')
        || document.querySelector('.el-dialog__footer');
      const btn = [...footer.querySelectorAll('button')].find(
        b => (b.innerText || '').replace(/\\s+/g, '').trim() === label
      );
      if (btn) { btn.click(); return JSON.stringify({ ok: true }); }
      return JSON.stringify({ ok: false });
    })()
  " >/dev/null 2>&1
}
```

**来源：** `click_dialog_footer_button`（lib/common.sh）
**优势：** 兼容 Element Plus / Ant Design 等组件库的按钮渲染差异

### P3: fill → eval 兜底（触发框架事件）

```bash
# fill 不触发 Vue/React 的 input 事件时，用 eval 设置值
opencli browser $SESSION fill --role textbox --name "角色名称" "测试" >/dev/null 2>&1 || {
  opencli browser $SESSION eval "
    (function(){
      const value = '测试';
      const items = [...document.querySelectorAll('.el-form-item')];
      for (const item of items) {
        const label = item.querySelector('.el-form-item__label');
        if (!label || !label.innerText.includes('角色名称')) continue;
        const input = item.querySelector('input:not([type=hidden])');
        if (input) {
          const desc = Object.getOwnPropertyDescriptor(
            window.HTMLInputElement.prototype, 'value'
          );
          if (desc && desc.set) desc.set.call(input, value);
          else input.value = value;
          input.dispatchEvent(new Event('input', { bubbles: true }));
          input.dispatchEvent(new Event('change', { bubbles: true }));
          return JSON.stringify({ ok: true });
        }
      }
      return JSON.stringify({ ok: false });
    })()
  " >/dev/null 2>&1
}
```

**来源：** `fill_role_name`（lib/common.sh）
**优势：** 解决 `fill --role textbox` 对自定义输入框的无效填充

### P4: JSON 配置 + 本地覆盖

```bash
# 仓库内 config.json 含默认值，local.json（gitignore）覆盖敏感字段
# 用 Python 或 jq 合并两个 JSON

# 方法一：jq
merged=$(jq -s 'reduce .[] as $item ({}; . * $item)' config/base.json config/local.json)

# 方法二：Python
merged=$(python3 -c "
import json, sys
with open(sys.argv[1]) as f: a = json.load(f)
with open(sys.argv[2]) as f: b = json.load(f)
def merge(x, y):
    out = dict(x)
    for k, v in y.items():
        if k in out and isinstance(out[k], dict) and isinstance(v, dict):
            out[k] = merge(out[k], v)
        else:
            out[k] = v
    return out
print(json.dumps(merge(a, b), ensure_ascii=False))
" config/base.json config/local.json)
```

**来源：** `_merge_json_files`（lib/config.sh）
**优势：** 密码、token 等敏感信息不提交 git，本地覆盖即可

### P5: 验证码处理策略（三种模式）

| 模式 | 适用场景 | 行为 |
|------|---------|------|
| `auto` | 开发环境无验证码 | 直接登录，有验证码则报错 |
| `manual` | 有图形验证码 | 暂停等待人工输入后继续 |
| `bind-only` | 复杂 MFA 验证 | 不自动登录，人工登录后 `opencli browser <session> bind` |

**来源：** `handle_captcha_mode`（lib/common.sh）

### P6: 等待跳离登录页（超时重试）

```bash
# 登录后等待 URL 离开 /login 路径
wait_leave_login() {
  local session="$1"
  for _ in $(seq 1 60); do
    local url
    url="$(opencli browser $session get url | tr -d '\r\n')"
    if [[ "$url" != *"/login"* ]]; then
      echo "已离开登录页: $url"
      return 0
    fi
    sleep 1
  done
  echo "登录超时（60s 内未离开 /login）" >&2
  return 1
}
```

**来源：** `wait_leave_login`（lib/common.sh）

## 反模式

### A1: `sleep` 代替条件等待

```bash
# ❌ 反模式
sleep 5
opencli browser $SESSION click --role button --name "提交"

# ✅ 正确
opencli browser $SESSION wait text "提交" --timeout 10000
opencli browser $SESSION click --role button --name "提交"
```

**问题：** 网络波动时 sleep 不足或过长，脆弱且慢。

### A2: eval 返回自由文本

```bash
# ❌ 反模式
opencli browser $SESSION eval "document.title"

# ✅ 正确
opencli browser $SESSION eval "JSON.stringify({ title: document.title })"
```

**问题：** 自由文本含换行/空格，shell 变量捕获困难。JSON 结构化可精确提取。

### A3: 每个脚本新建 session

```bash
# ❌ 反模式
SCRIPT_A: opencli browser session-a open ...
SCRIPT_B: opencli browser session-b open ...

# ✅ 正确
ALL SCRIPTS: opencli browser nebula-ux open ...
```

**问题：** 每个 session 需重新登录 + 验证码，耗时且脆弱（见 test-skills 共用 `nebula-ux` 的实践）。

### A4: 硬编码敏感信息

```bash
# ❌ 反模式
PASSWORD="my_real_password_123"

# ✅ 正确
# config.json: { "password": "CHANGE_ME" }
# config.local.json（gitignore）: { "password": "my_real_password_123" }
```

**问题：** 不小心 git push 导致密码泄露。

### A5: 断言失败时不截图

```bash
# ❌ 反模式
# 只输出错误信息，无视觉证据

# ✅ 正确
screenshot() {
  opencli browser $SESSION screenshot "screenshots/fail-${case}.png"
}
echo "断言失败" >&2
screenshot "tc1"
exit 1
```

**问题：** 只看文字错误无法判断页面实际状态（是否渲染异常？定位偏了？）。

## eval 兜底准则

当 `click --name` / `fill --role textbox` 等结构化命令定位不到元素时，统一使用 eval JS 兜底：

```
1. 先用结构化命令（95% 情况够用）
2. 失败时降级到 eval JS
3. eval 内部按以下优先级定位：
   a. CSS 选择器：document.querySelector()
   b. 文本内容过滤：[...els].find(el => el.innerText.includes('关键词'))
   c. 角色/属性过滤：[...els].filter(el => el.getAttribute('role') === 'button')
4. 始终返回 JSON.stringify({ ok: boolean, ...data })
```

这种模式来自 `test-skills` 的 lib 库，在 Element Plus / Ant Design 等组件库环境下验证了数百次执行。
