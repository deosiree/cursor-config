# 苏格拉底 · 追问链 — 真实输出

**触发：** "为什么技术栈要分层？"  
**来源：** 对 `Agent开发学习路线` 第 4 节"技术栈按层理解"的真实回答

---

**追问 1：** 如果所有代码写在一个文件里，会怎样？

> Agent 系统需要同时处理用户输入、模型推理、工具调用、上下文管理、状态保存。如果这些逻辑全混在一起，改一个工具的描述就要改"大模型调用函数"——这个函数会变成几千行的不可维护代码。

**追问 2：** 那为什么恰好是这 7 层？不能是 5 层或 10 层？

> craft-agents-oss 的实际代码给出了答案：不是先有"7 层"的理论再有代码，而是代码自然收敛成了这些边界。`packages/core/`（类型）≠ `packages/shared/`（逻辑）≠ `apps/`（入口）——每层有独立的 package.json、独立的测试、独立的修改节奏。**层数不是设计出来的，是耦合度自然切割出来的。**

**追问 3：** 哪一层最容易变成"垃圾桶"？

> Agent 后端层。因为它是"大脑"，容易把所有决策逻辑都塞进去。每轮循环里真正属于 Agent 后端的只有"调模型 → 识别 tool_use → 注入结果 → 判断是否继续"。权限检查应该在独立的 PermissionManager 里，上下文裁剪应该在 Context 层，工具路由应该在 MCP Pool 层。
