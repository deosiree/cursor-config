# 苏格拉底-skills

> **定位：** 父级 agent 入口。生成递进追问链，引导读者从表面疑问深入到核心结论。
> **核心原则：** 不问「你知道 X 吗」，问「如果 X 不成立会怎样」。

## 何时使用

- 读者有一个决策点/选型问题（"为什么选 X 而非 Y"）
- 读者容易产生"但是..."的疑问
- 需要引导读者自己发现结论，而非直接给答案

## 何时不要使用

- 知识点是单一术语定义 → 用 `[[../不嵌入/SKILL.md]]`
- 需要用一个场景串联多术语 → 用 `[[../费曼-skills/SKILL.md]]`
- 需要先给全局认知再展开 → 用 `[[../金字塔-skills/SKILL.md]]`
- 读者时间紧迫需要直接答案 → 跳过追问，给直接结论

## 入口判断

| 用户需求 | 路由 |
|---------|------|
| 对决策点/选型做追问引导 | → `[[intention-skills/编排-追问链/SKILL.md]]` |
| 需要生成单个追问问题（用于已有链中） | → 直呼 `[[feature-skills/交互-生成追问/SKILL.md]]` |
| 需要判断追问链深度是否足够 | → 直呼 `[[feature-skills/判定-追问深度/SKILL.md]]` |
| 不明确 | → 问用户：生成完整追问链 / 补充单个追问 / 评估现有链？ |

## RED（失败基线）

| 触发条件 | 一线修复 | 兜底 |
|---------|---------|-----------|
| 纯概念段落后硬插追问 | 追问必须嵌入决策点/矛盾点 | 去掉追问，改用定义输出 |
| 追问无递进（平行罗列 3 个独立小问题） | 每问建立在前一问答案上 | 降级为对比表 |
| 超过 5 问仍在绕 | 收敛到核心约束，直接给出结论 | 标注⚠️ 追问链超过合理长度 |
| 问题太抽象读者无法回答 | 把问题改到具体的判断场景中 | 改为"如果...你会怎么选？"式问题 |
| 读者一直答"不知道" | 降维到更基础的前提问题 | 切换到费曼概念解释 |
| 上层路由传入了非决策点（如纯概念） | 返回"不适合追问链" | 建议改路由到费曼-skills |

## GREEN（执行主线）

### Step 1：接收路由指令

```
输入：method = "苏格拉底·追问链"
      决策点 = "为什么选 A 而非 B？"
      背景 = 读者当前认知 + 常见疑问
```

### Step 2：路由执行

🔴 CHECKPOINT：确认决策点适合追问链（非纯概念解释），再跳转

跳转 `[[intention-skills/编排-追问链/SKILL.md]]`，传入决策点和背景。

### Step 3：返回结果

将生成的追问链（2-5 问 + 最终结论）返回给调用方。

## REFACTOR

- 追问策略超过 5 种 → 拆出子 intention（如 `苏格拉底-skills/选型追问/` 和 `苏格拉底-skills/概念追问/`）
- 追问深度判定规则复杂化 → 下沉到 `references/追问深度判定细则.md`
- 入口判断的"不明确"选项被高频触发 → 在入口判断中增加辨析示例

## 输入契约

| 参数 | 来源 | 说明 |
|------|------|------|
| `决策点` | 方法论路由 | 需要分析的选择/判断问题，如 "为什么选 async/await 而非回调？" |
| `背景` | 方法论路由 | 读者认知水平 + 常见疑问点，如 "了解 JS 基础，写过回调函数" |
| `约束` | 方法论路由 | 影响决策的核心限制条件，如 "团队 5 人，项目代码库 3 万行" |

## 使用示例

```
输入：
  决策点 = "为什么用 async/await 而非回调？"
  背景 = "读者了解 JavaScript 基础，写过回调函数"

路由 → intention-skills/编排-追问链
输出：
  追问 1："如果用回调写一个异步请求，最让你头疼的是什么？"
  → 追问 2："那如果同时要处理 3 个并行请求，回调怎么组织？"
  → 追问 3："Promise 解决了回调嵌套，但你怎么把多个 Promise 串联成有序步骤？"
  → 结论：async/await 让异步代码看起来像同步代码，降低心智负担
```

## 约束

1. 追问链 2-5 问，不超过 5 问
2. 每问必须建立在前一问答案上
3. 最终必须落到可操作的结论（非开放式讨论）
4. 不用于纯概念解释（那是费曼的职责）
