# 编排：苏格拉底 · 追问链

> **定位：** 给定一个决策点/选型问题，生成递进追问链，引导读者发现核心约束。

## 输入

| 参数 | 来源 | 说明 |
|------|------|------|
| `决策点` | 父级入口 | 待分析的选择/判断（"为什么选 A 而非 B？"） |
| `背景` | 父级入口 | 读者当前认知水平 + 常见疑问点 |
| `约束` | 父级入口 | 影响决策的核心限制条件 |

## RED（失败基线）

| 触发条件 | 一线修复 | 兜底 |
|---------|---------|------|
| 决策点描述不清 | 追问用户明确"对比的是什么和什么" | 🛑 STOP，请用户澄清 |
| 背景信息不足 | 追问读者"你现在用的什么方案？遇到什么问题？" | 基于常见误区做通用追问 |
| 追问链超过 5 问仍无结论 | 强制收尾，直接输出当前结论 | 标注⚠️ "追问链已超过合理长度" |
| 读者连续 2 问答不上来 | 降维到更基础的前提问题 | 切换到费曼概念解释先补基础 |
| 追问变成审讯式（连续否定读者回答） | 每问先肯定前一步再递进 | 第一句用"你说得对，那再考虑..." |
| 读者直接给出正确答案 | 不需要追问，验证后直接通过 | 跳到最终结论 |

## GREEN（执行主线）

### Step 1：识别追问起点

```
找到读者最可能产生的第一个疑问（"但是..."点）：
1. 常见的反直觉点：为什么不是更简单的方式？
2. 常见的权衡点：A 好为什么还需要 B？
3. 常见的混淆点：A 和 B 不是做同一件事吗？

第 1 问必须：读者凭直觉就能回答
→ 格式："如果...你首先会遇到什么问题？"

🔴 CHECKPOINT：第 1 问是否具体且可凭直觉回答？→ 是则继续，否则调整起点
```

### Step 2：构建递进链

```
第 1 问：表面疑问（读者自己会想到的）
  正面：读者答对 → "对的，那再考虑这种情况..."
  反面：读者答错 → "不错的方向，但换个角度..."

第 2 问：基于第 1 问答案，追问上一层漏洞
  目标：让读者发现表面方案的限制

第 3 问：逼出核心约束
  目标：读者自己说出核心设计原则或权衡

第 4-5 问（可选）：验证理解深度
  目标：读者能自己举一反三
```

### Step 3：输出格式

```
**追问 1：** {具体场景下的问题}
（🔴 等读者回答）

**追问 2：** {基于回答的递进}
（🔴 等读者回答）

...

**结论：** {核心约束或决策原则，一句话}
> 由以上追问链自然得出
```

## REFACTOR

- 追问起点模式超过 5 种 → 独立为 `feature-skills/识别-追问起点/SKILL.md`
- 递进链构建规则膨胀 → 下沉到 `references/递进链构建细则.md`

## 使用示例

```
决策点 = "为什么选 TypeScript 而非 JavaScript？"
背景 = "读者写过 JS 小项目，团队 3 人"

追问 1："一个 5000 行 JS 项目，你重构一个函数，怎么确保不破坏其他调用者？"
  → 预期：手动搜索引用/靠记忆

追问 2："要是新同事接手，也靠记忆吗？"
  → 预期：应该有类型检查/自动提示

追问 3："那 TypeScript 加上的类型系统, 是不是就是这个'自动检查'的保障？"
  → 结论：TS 的类型系统在编译期做静态检查，替代人工记忆
```

## 约束

1. 2-5 问，严格不超过 5 问
2. 每问必须建立在前一问答案上（禁止平行罗列）
3. 最后一问必须逼出核心约束或决策原则
4. 展示追问后 🔴 STOP 等待读者回答
