# 编排：金字塔 · 结论先行

> **定位：** 给定一个需要建立全局认知的知识主题，生成金字塔结构的章节开篇。

## 输入

| 参数 | 来源 | 说明 |
|------|------|------|
| `主题` | 父级入口 | 章节主题（如"微服务三组件"） |
| `关键概念` | 父级入口 | 需要覆盖的概念列表 |
| `目标读者` | 父级入口 | 读者当前认知水平 |

## RED（失败基线）

| 触发条件 | 一线修复 | 兜底 |
|---------|---------|------|
| 关键概念列表为空 | 🛑 STOP，请求上层补充 | 无 |
| 塔尖不可验证 | 改为"X 由 {N} 步组成/有 {N} 种模式" | 标注⚠️ 塔尖无验证标准 |
| 论据层超过 3 层 | 合并次要层级 | 保留 2 层，第 3 层下沉 |
| 论据互相重叠（不 MECE） | 调分组逻辑直到互斥 | 标注⚠️ "论据间有重叠" |
| 塔尖与论据脱节 | 塔尖必须能自然分解为论据 | 重写塔尖 |
| 生成内容与后文无关 | 最后一层加过渡句 | 标注⚠️ "金字塔与正文脱节" |
| 关键概念太多（>7） | 先建上层分组再展开 | 只展示顶层分组，细节由后文展开 |

## GREEN（执行主线）

### Step 1：提炼塔尖

```
用一句话写出可检验的核心结论：

[定位式] "X 是 Y，不是 Z"（适用于消除混淆）
[流程式] "X 由三步组成：A → B → C"（适用于有先后顺序）
[分类式] "X 有 {N} 种模式，按 {维度} 区分"（适用于有分类）
```

**塔尖要求**：可检验（能回答"怎么验证这个结论"）。

🔴 CHECKPOINT：塔尖是否可检验？→ 是则继续，否则重写塔尖

### Step 2：构建支撑层

```
塔尖：{一句话结论}
  ├── 论据 1：{核心支撑 1}
  │   ├── 细节 1.1
  │   └── 细节 1.2
  ├── 论据 2：{核心支撑 2}
  │   ├── 细节 2.1
  │   └── 细节 2.2
  └── 论据 3：{核心支撑 3}
      └── 细节 3.1
```

**要求**：每层论据 MECE。

### Step 3：与后文呼应

```
金字塔最后一层 → 加过渡句指向后文：
"下面 {对比表/图示} 将展开论证上述论据 2 的具体判断标准。"
```

## REFACTOR

- 塔尖模板超过 5 种 → 独立为 `feature-skills/执行-塔尖生成/SKILL.md`
- MECE 检查自动化为规则引擎 → 下沉到 `references/MECE检查细则.md`

## 使用示例

```
主题 = "FastAPI 的三个核心优势"
关键概念 = ["async/await", "Pydantic", "OpenAPI"]

塔尖："FastAPI 相比 Flask 有三个核心差异：异步模型、参数校验、接口文档"
第 2 层：
  - 异步模型：async/await 原生支持，IO 不阻塞
  - 参数校验：Pydantic type hints 自动校验，零样板代码
  - 接口文档：自动生成 OpenAPI，/docs 即文档
第 3 层：这三个优势分别对应"并发能力"、"开发效率"、"协作成本"
过渡句："下文逐一展开三个优势的具体用法和效果对比"
```

## 约束

1. 层级 2-3 层，不超过 3 层
2. 每层 2-5 项，不超过 7 项
3. 塔尖可验证（有数字/步骤/分类的断言）
4. 论据 MECE
