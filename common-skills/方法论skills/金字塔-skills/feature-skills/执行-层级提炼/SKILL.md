# 执行：层级提炼

> **定位：** 纯功能 skill。把平铺信息按金字塔结构分层组织。

## 输入

| 参数 | 说明 |
|------|------|
| `信息列表` | 需要组织的原始信息项（5-15 项） |
| `分组维度` | 按什么标准分组（按流程/按类别/按重要性/按依赖关系） |

## 分组维度选择

| 信息特征 | 推荐维度 | 示例 |
|---------|---------|------|
| 有先后顺序 | 按流程/时间线 | 编译步骤、部署流程 |
| 有类别差异 | 按类别/领域 | 数据库类型（SQL vs NoSQL） |
| 有重要性差异 | 按优先级 | 必须做/应该做/可以做 |
| 有依赖关系 | 按依赖链 | 底层→中间层→应用层 |

## 输出

```
顶层：{分组 A（维度名）}
  ├── {子项 A1}
  │   └── {细节（可选）}
  ├── {子项 A2}
  └── {子项 A3}
顶层：{分组 B}
  ├── {子项 B1}
  └── {子项 B2}
```

## 分层原则

1. 每层信息抽象级别一致（不将原则和例子放在同一层）
2. 每层 2-5 项，不超过 7 项（Miller 定律）
3. 顶层 2-3 层，不超过 3 层
4. 如果信息项少于 5，不需要提炼，直接平铺即可

## RED

| 反模式 | 替代 |
|-------|------|
| 信息项少于 5 还硬分层 | 直接平铺，不需要金字塔 |
| 分组后的组间有重叠 | 调分组维度直到 MECE |
| 某一组只有 1 项 | 合并到邻近组或去掉这一层 |
