# 执行：MECE 分组

> **定位：** 纯功能 skill。确保金字塔每一层的论据满足 MECE 原则。

## 输入

| 参数 | 说明 |
|------|------|
| `信息项` | 需要分组的原始项列表（2-10 项） |
| `分组试探` | 1-2 种可能的分组方式（按什么维度切分） |

## MECE 检查流程

```
1. [相互独立] 检查：
   遍历所有组对 (G1, G2)：
     if G1 中的某个项也能归入 G2：
       → "不独立"：调整分组边界使得归属唯一

2. [完全穷尽] 检查：
   遍历所有项：
     if 存在不属于任何组的项：
       → "不穷尽"：需要新增组或放宽组定义

3. 输出检查结果
```

## 常见 MECE 维度

| 场景 | 推荐维度 |
|------|---------|
| 技术组件分层 | 接入层 / 业务层 / 数据层 |
| 决策因素 | 成本 / 性能 / 维护性 / 可扩展性 |
| 流程阶段 | 输入 / 处理 / 输出 |
| 问题分类 | 技术 / 流程 / 人员 |
| 数据分类 | 结构化 / 半结构化 / 非结构化 |

## 输出

```
推荐分组：{按维度 X 的 MECE 分组}
├── 组 1（{特征}）：{项列表}
├── 组 2（{特征}）：{项列表}
└── 组 3（{特征}）：{项列表}

MECE 检查结果：
- 相互独立：组间是否有重叠？→ {通过 / 不通过（说明原因）}
- 完全穷尽：是否有遗漏？→ {通过 / 不通过（说明原因）}
```

## RED

| 反模式 | 替代 |
|-------|------|
| 组间有重叠但忽略 | 调整分组维度使得归属唯一 |
| 遗漏项但视为穷尽 | 新增组或放宽组定义 |
| 硬凑 MECE（含义勉强） | 接受小幅重叠，标注⚠️ 用于指引而非严格分类 |
