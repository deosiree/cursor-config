# 方法论路由中心 — 说明文档

## 我该什么时候用？

当你写技术文档、学习笔记、面经、skill 输出时，希望**不只是平铺知识点**，而是用费曼、苏格拉底、金字塔等名人方法论让内容更有层次感和可读性。

## 快速使用

1. 告诉 Agent：`用方法论路由选择合适的方法`
2. Agent 读 `SKILL.md` → 按优先级判断 → 跳转到对应方法文档
3. Agent 按方法文档的指引写内容

## 可用方法一览

| 方法 | 一句话 | 例子 |
|------|--------|------|
| **费曼** | 用一个场景串起所有术语 | "想象你是一个新来的工程师……" |
| **苏格拉底** | 用2~5个递进问题逼出结论 | "为什么不直接用 if/else？→ 因为……那如果……？" |
| **金字塔** | 先给结论，再展开论据 | "核心结论：类型层就是系统的词汇表。展开：①……②……③……" |
| **不嵌入** | 知识点已经够清楚，直接用 | 定义 + 对比表 |

## 方法来自哪里

所有方法的详细文档在 `QA转面经/references/方法论库/references/` 中。这个路由中心只是帮你选，不拷贝内容。

## 自然语言触发示例

| 你这样说 | Agent 会做什么 |
|---------|---------------|
| "解释 Agent Loop 和 Tool 的关系" | 多术语+层级 → 费曼统合叙事 → 用一个场景串联 |
| "为什么用 AsyncGenerator 而不是 Promise？" | 决策点/选型 → 苏格拉底追问链 → 递进追问 |
| "什么是 JSONL？" | 知识点够清晰 → 不嵌入 → 直接定义+示例 |
| "概述 Agent 系统的 7 层架构" | 章首缺全局 → 金字塔结论先行 → 先给结论再展开 |
| "讲讲 Memory 这个概念" | 需要对术语做通俗解释 → 费曼概念解释 |
