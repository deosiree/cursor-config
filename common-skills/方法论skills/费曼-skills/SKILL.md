# 费曼-skills

> **定位：** 父级 agent 入口。判断教学场景 → 路由到对应的 intention skill。
> **核心原则：** "如果你不能简单地解释它，说明你还没有真正理解它。"

## 何时使用

- 需要用一个场景串联多个技术术语并解释它们的关系
- 需要对单个技术概念做通俗类比解释（"什么是 X？举个例子"）
- 需要校验已写好的方法论内容是否真正说明了问题

## 何时不要使用

- 知识点是单一术语/格式定义，无歧义 → 用 `[[../不嵌入/SKILL.md]]`
- 需要对决策点/选型做追问引导 → 用 `[[../苏格拉底-skills/SKILL.md]]`
- 需要先建立全局认知再展开 → 用 `[[../金字塔-skills/SKILL.md]]`

## 入口判断

| 用户需求 | 路由 |
|---------|------|
| 用场景串联多术语、解释层级关系 | → `[[intention-skills/编排-统合叙事/SKILL.md]]` |
| 对单个术语做通俗类比解释 | → `[[intention-skills/编排-概念解释/SKILL.md]]` |
| 写完方法论内容后做质量校验 | → `[[intention-skills/编排-理解校验/SKILL.md]]` |
| 不明确 | → 问用户：串联多个术语 / 解释单个概念 / 校验已写内容？ |

## RED（失败基线）

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 只有类比没有场景串联 | 改用场景驱动，类比嵌入场景中 | 标注⚠️ 降级为定义+示例 |
| 概念解释用了多个并列类比 | 收敛为单一类比贯穿全文 | 定义+示例输出 |
| 校验发现 cargo cult | 补决策信息/边界 case | 标注⚠️ 校验未通过项 |
| 上层路由传入了"不嵌入"的知识点 | 直接返回不处理 | 返回空结果，不报错 |
| 知识点包含代码但解释完全没有代码 | 在场景/类比中加入至少一段代码示例 | 标注⚠️ "缺少代码支撑" |
| 场景与术语领域完全不匹配（如用餐厅类比解释数据库事务） | 换一个同领域场景 | 改用概念解释+独立类比 |
| 用户反馈"还是不懂" | 换一个视角的类比/场景重新解释 | 降级为直接定义+逐条拆解 |
| 费曼校验连续 2 次未通过 | 输出校验报告，建议改用手动审查 | 标注⚠️ "费曼校验连续失败" |

## GREEN（执行主线）

### Step 1：接收路由指令

```
输入：方法论路由传来的 {method, reason, suggestion}
确定目标 intention：
- method = "费曼·统合叙事" → [[intention-skills/编排-统合叙事/SKILL.md]]
- method = "费曼·概念解释" → [[intention-skills/编排-概念解释/SKILL.md]]
- method = "费曼·理解校验" → [[intention-skills/编排-理解校验/SKILL.md]]
```

### Step 2：路由执行

🔴 CHECKPOINT：确认方法选择与知识点特征匹配后，再跳转

跳转到对应 intention skill，传入：
- `术语列表`（统合叙事）/ `单个术语`（概念解释）/ `待校验内容`（理解校验）
- `上下文`（文档主题、读者水平）
- `建议`（来自上层路由的 suggestion）

### Step 3：写后校验（仅统合叙事和概念解释）

🔴 CHECKPOINT：校验通过？ → 通过则交付，不通过则修正后再校验

```
if method == "费曼·统合叙事" or method == "费曼·概念解释":
  → 跳转 [[intention-skills/编排-理解校验/SKILL.md]]
  → 校验通过？→ 交付；不通过 → 修正后再次校验
```

### Step 4：返回结果

将生成的解释正文（含校验报告）返回给调用方。

## REFACTOR

- intention 超过 5 个 → 拆出子分类（如 `费曼-skills/理科场景/` 和 `费曼-skills/文科场景/`）
- 单条 RED 修复流程超过 3 步 → 独立为 feature skill
- 理解校验规则膨胀 → 下沉到 `references/费曼-理解校验-详细规则.md`
- 概念解释与统合叙事的边界模糊（经常选错）→ 在入口判断中增加辨析示例

## 输入契约

| 参数 | 来源 | 说明 |
|------|------|------|
| `method` | 方法论路由 | 指定哪种费曼方法（统合叙事/概念解释/理解校验） |
| `术语列表` | 方法论路由 | 需要解释的术语集合，如 `["API Gateway", "Service Mesh"]` |
| `关系描述` | 方法论路由 | 术语间的层级/派生/调用关系，如 "请求先到 Gateway → 转发到 Mesh → Balancer 分发" |
| `上下文` | 方法论路由 | 当前章节主题、目标读者水平，如 "微服务章节，读者有后端基础" |
| `待校验内容` | 外部传入 | 需要校验的已写内容字符串（仅理解校验需要） |

## 使用示例

### 示例：统合叙事

```
输入：
  method = "费曼·统合叙事"
  术语列表 = ["API Gateway", "Service Mesh", "Load Balancer"]
  关系描述 = "三者按调用链排列：请求先到 Gateway，Gateway 转发到 Service Mesh，Mesh 内 Load Balancer 分配实例"
  上下文 = "微服务架构章节，读者有基本分布式系统概念"

路由 → intention-skills/编排-统合叙事
输出：以"一次移动端请求到达微服务集群"为场景的三段式解释
```

### 示例：概念解释

```
输入：
  method = "费曼·概念解释"
  术语 = "上下文窗口"
  上下文 = "LLM 章节，读者是程序员"

路由 → intention-skills/编排-概念解释
输出：工作台面类比 + 令牌(Token)映射表 + 代码示例
```

## 约束

1. 不重复做 Q1→Q6 判断（那是上层方法论路由的职责）
2. 每知识点顶层最多一种费曼方法（统合叙事/概念解释二选一）
3. 统合叙事必须用**一个**场景贯穿，禁止并列类比
4. 概念解释的类比与读者背景匹配（程序员用编程概念，非程序员用生活概念）
5. 所有输出要求：可脱离项目笔记独立阅读

## 与上层路由的关系

被 `[[../SKILL.md]]`（方法论路由）调用。路由中心已完成 Q1→Q6 判断，本套件只负责执行。
