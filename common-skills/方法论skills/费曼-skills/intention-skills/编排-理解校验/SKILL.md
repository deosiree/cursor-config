# 编排：费曼 · 理解校验

> **定位：** 写后门禁。给定一段已写好的方法论内容，做质量校验，输出通过/不通过判定及修改建议。

## 输入

| 参数 | 来源 | 说明 |
|------|------|------|
| `待校验内容` | 上层传入 | 统合叙事或概念解释的输出正文 |
| `类型` | 上层传入 | "统合叙事" 或 "概念解释" |
| `原始术语` | 上层传入 | 原先需要解释的术语，用于对照 |

## RED（失败基线）

| 触发条件 | 一线修复 | 兜底 |
|---------|---------|------|
| 内容长度 < 100 字 | 要求补充至少一个场景/类比 | 标注⚠️ 内容过短，无法校验 |
| 待校验内容不是费曼方法的输出（如纯定义堆叠） | 标注"这不是费曼输出"，建议重写 | 返回不通过 |
| 校验标准不明确 | 降级检查三关中最关键的"命名≠理解" | 标注⚠️ 部分指标不适用 |
| 同一内容连续 2 次校验不通过 | 输出完整校验报告，建议作者手动审 | 标注⚠️ 自动校验已达上限 |

## GREEN（执行主线）

### 第一关：命名 ≠ 理解

自问并检查：
```
1. 能否去掉术语堆叠，用六年级能懂的话复述？ 
   → 检查：正文是否有一个没有术语的段落？
2. 换种问法还能答吗？
   → 检查：类比/场景是否有足够的通用性？
3. 有没有可感知例子（数字、界面、一次调用）？
   → 检查：至少有一个具体的数据或操作描述
```

**判定**：若只有名词没有机制 → 不通过。

### 第二关：反自欺（cargo cult 检测）

| 货物崇拜 | 合格信号 |
|---------|---------|
| 有对比表但行列无决策信息 | 表驱动选型结论（"因此选 X"） |
| 有面试钩子但无追问链 | 钩子 + 递进追问 |
| 有代码块但与论证无关 | 代码支撑边界 case |
| 快问快答只背定义 | 每题有应答要点+边界 |

**判定**：存在任意一项 cargo cult → 不通过。

🔴 CHECKPOINT：如果第二关不通过，是否已给出具体 cargo cult 类型和修改建议？

### 第三关：写入门禁

- [ ] 至少一处用**具体场景**替代纯定义开场
- [ ] 对比表/选型结论能回答「所以呢」
- [ ] 区分度标准可验证（规则、数字、反例），非「很有经验」

**判定**：三项未全通过 → 不通过。

## 输出校验报告

```
校验结果：通过 / 不通过
类型：统合叙事 / 概念解释

第一关（命名≠理解）：通过 / 不通过
  问题：{具体问题}
  建议：{修改建议}

第二关（cargo cult）：通过 / 不通过
  问题：{具体货物崇拜类型}
  建议：{修改建议}

第三关（写入门禁）：通过 / 不通过
  未通过项：{列出未通过的门禁项}

综合建议：{一句话说明是否需要重写/局部修改/通过}
```

## REFACTOR

- 校验规则超过 5 条 → 下沉到 `references/理解校验-详细规则.md`
- cargo cult 模式超过 5 种 → 拆出 `feature-skills/执行-cargo cult检测/SKILL.md`

## 约束

- 不自动修改内容（只出报告）
- 三关独立执行（不因第一关不通过就跳过第二关）
- 校验报告中的问题项必须给出具体位置（引用原文片段）
