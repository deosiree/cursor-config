# 方法论路由中心

> **定位：** 只做路由，不做拷贝。所有方法论内容引用已有 skill，本文件只负责"根据知识点特征选择合适的方法论 → 跳转到对应 skill"。
> **使用者：** 任何需要"在输出 md 时嵌入名人方法论"的 skill 套件（学习助手、QA转面经、写skill……）

## 常见问题速查

根据问题模式直接定位方法，适用于经验丰富的 Agent 快速路由。不确定时走下方 Q1→Q6 详细流程。

| 问题模式 | 直接路由 | 示例 |
|---|---|---|
| "什么是 X"（单一术语/格式定义） | 不嵌入 | "什么是 JSONL？" |
| "解释 A、B、C 的关系"（多术语+层级） | 费曼·统合叙事 | "Agent Loop、Tool、Memory 的关系" |
| "为什么选 X 而非 Y"（决策点/选型） | 苏格拉底·追问链 | "为什么用 AsyncGenerator 而非 Promise？" |
| "概述/整体理解 X"（章首需全局） | 金字塔·结论先行 | "概述 Agent 系统 7 层技术栈" |
| "A、B、C 各做什么，怎么配合"（多术语+缺全局） | 金字塔顶层 + 费曼子节 | "API Gateway、Service Mesh、Load Balancer" |
| "通俗解释 X"（需比喻，无层级） | 费曼·概念解释 | "什么叫上下文窗口？" |
| "对比 X 和 Y"（无层级，纯对比） | 不嵌入（对比表） | "JSON vs JSONL" |

> 速查表是 Q1→Q6 的索引，不替代详细流程。遇模糊问题仍走完整判断优先级。

## RED（失败基线）

方法论路由的 3 条已知失败模式，按「触发条件 → 一线修复 → 仍失败兜底」三段式处理：

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 对简单概念用苏格拉底长篇追问 | 改用「不嵌入」直接定义+示例（触发规则1/6） | 恢复默认定义格式，删除追问链 |
| 对层级概念用「不嵌入」 | 改用金字塔结论先行或费曼统合叙事（触发规则3/4） | 至少输出一句话全局概括+对比表 |
| 目标方法文档路径失效（wikilink 断裂） | 回退到已注册方法表的「适用场景」自行按原则写 | 标注⚠️方法文档不可达，基于原则自行应用 |

## GREEN（执行主线）
输入知识点 → 特征分析(Q1→Q6) → 方法选择(或查冲突表) → 路由执行(读方法doc+写内容) → 若方法含费曼则追加理解校验

## REFACTOR
- 判断优先级规则超过 6 条 → 下沉到 `references/判断优先级详细规则.md`
- 新增方法 → 在 QA转面经 方法论库中新增，本文件只更新"已注册方法"表

## 判断优先级

**输入：** 待解释的知识点文本
**输出：** `{ method, reason, suggestion }`
**流程：** 逐条判断 Q1→Q6（每Q独立，**不因命中Qn就跳过Qn+1**）。收集所有命中编号 → 查冲突表或直接路由。

```
[Q1] 单一术语/格式定义，无需进一步解释？              → 不嵌入           → 停
     判断要点：概念有标准定义、无歧义、读者只需知道"是什么"

[Q2] 是决策点/选型问题（"为什么选X而非Y"）？          → 苏格拉底追问      → 停
     判断要点：问题含"为什么/还是/选哪个/优劣"，读者期待权衡而非事实

[Q3] 涉及多术语混淆或有层级/派生/调用关系？          → 费曼统合叙事      → 停
     判断要点：有2+个关联术语，读者分不清边界或先后顺序

[Q4] 章首缺少全局认知（读者需要先看到"地图"）？      → 金字塔结论先行    → 停
     判断要点：问题含"概述/整体/架构/全貌"，或知识有层次依赖

[Q5] 需要对术语做通俗解释（非层级关系，仅需类比）？  → 费曼概念解释      → 停
     判断要点：经典FF问题（"什么是RLHF? 举个例子"），需比喻不搭结构

[Q6] 以上都不符合？                                 → 不嵌入           → 停
```

> **注意：** 同一知识点可能同时满足多个 Q（如 Q3+Q4）。此时不取第一个命中的方法，而是参考「冲突解决」表决定主次分配。

## 使用方法（Agent 视角）

### 输入 → 输出管道

```
原始知识点文本
    ↓
🔴 CHECKPOINT: 确认知识点已理解、无歧义
    ↓
Step 1 特征分析 → 特征标签（如"多术语""决策点""章首缺全局"）
Step 2 方法选择 → { method, reason, suggestion }
Step 3 路由执行 → 按方法格式生成的解释内容
Step 4 写后校验（仅费曼）→ 校验报告 + 修正内容
```

### 分步规格

```
Step 1 — 知识点特征分析
  Input:  知识点文本
  Action: 依次过判断优先级 Q1→Q6，记录所有命中的规则编号
  Output: 特征标签（如"多术语+层级关系" "决策点+章首缺全局"）

Step 2 — 方法选择
  Input:  命中的规则编号列表
  Action: 
    · 仅1个命中 → 直接选对应方法
    · ≥2个命中 → 查冲突解决表确定顶层+子节方法
  🔴 CHECKPOINT: 确认方法选择与知识点特征匹配
  Output: { method: "费曼·统合叙事"|"苏格拉底·追问链"|"金字塔·结论先行"|"不嵌入",
            reason: "命中Q3: 多术语+层级关系",
            suggestion: "用一个场景串联四个概念" }

Step 3 — 路由执行
  Input:  method + suggestion
  Action: 按已注册方法表的「路由目标」跳转读取对应 .md
  🔴 CHECKPOINT: 验证目标方法文档路径可访问；若不可达，回退到适用场景自行写
  Output: 按选定方法生成的解释内容

Step 4 — 写后校验（仅费曼）
  Condition: method = "费曼·统合叙事" 或 "费曼·概念解释"
  Action: 追加执行 费曼-理解校验.md
  🔴 CHECKPOINT: 校验通过？
    · 通过 → 交付最终内容
    · 不通过 → 修正后再次校验；仍不通过则降级为不嵌入，标注⚠️费曼校验未通过，以定义+示例输出
  Output: 校验报告 + 修正后内容 或 ⚠️降级输出
```

## 完整示例

以「解释微服务架构中 API Gateway、Service Mesh、Load Balancer 三个组件各自的作用和关系」为例：

```
Step 1 — 特征分析
  Input:  "解释微服务架构中 API Gateway、Service Mesh、Load Balancer 三个组件的作用和关系"
  Action: 过 Q1→Q6，记录命中规则
  → Q3: 多术语（3个组件名）+ 层级关系（三者有调用编排链）
  → Q4: 章首缺全局（读者需要先理解三者在架构中的位置）
  Output: 特征标签 = "多术语+层级关系 + 章首缺全局"（冲突组合）

Step 2 — 方法选择
  Input:  命中 Q3 + Q4（冲突）
  Action: 查冲突解决表 → "规则3+规则4"行
  → 顶层：金字塔·结论先行（先建全局认知）
  → 子节：费曼·统合叙事（串联三个术语）
  🔴 CHECKPOINT: 确认匹配 ✓
  Output: {
    method: "金字塔·结论先行（顶层）+ 费曼·统合叙事（子节）",
    reason: "Q3多术语+Q4章首缺全局，冲突表指定金字塔优先",
    suggestion: "先用一句话概括三者定位关系（塔尖），再分节用场景串术语"
  }

Step 3 — 路由执行
  Input:  method = 金字塔·结论先行 + 费曼·统合叙事
  Action: 
    1. 跳转 金字塔-结论先行.md → 读取"塔尖→第二层→第三层"结构
    2. 按金字塔框架写顶层：塔尖一句话概括三者定位
    3. 跳转 费曼-统合叙事.md → 读取"用一个场景串术语"方法
    4. 在子节用费曼串联三个组件（如"一次API调用经过的完整链路"）
  🔴 CHECKPOINT: 路径可达 ✓
  Output: 章首金字塔全局认知 + 子节费曼场景解释

Step 4 — 写后校验（费曼方法适用）
  Condition: 子节用了费曼·统合叙事 → 执行 费曼-理解校验.md
  Action: 校验是否真的用一个场景串起了三个术语
  Output: 校验通过 ✓
```

> 更多示例见 `template/few-shot-*.md` 和 `test-prompts.json`。

## 边界条件

- 若目标方法文档路径失效（wikilink 无法跳转）→ 回退到本文件的"已注册方法"表中的"适用场景"描述，自行按方法论原则写，标注"⚠️ 方法文档不可达，基于原则自行应用"
- 若知识点同时满足多个方法 → 见下方「冲突解决」表，按冲突类型决策

## 冲突解决

当知识点同时命中多条判断优先级规则时，按以下冲突类型决策：

| 冲突组合 | 顶层方法 | 子节方法 | 示例 |
|---|---|---|---|
| 规则3(费曼·统合叙事) + 规则4(金字塔·结论先行) | 金字塔 · 结论先行（先建全局认知） | 费曼 · 统合叙事串联术语 | 微服务三组件关系 |
| 规则2(苏格拉底·追问链) + 规则4(金字塔·结论先行) | 金字塔 · 结论先行（先建全局认知） | 苏格拉底 · 追问链逐层深入 | 技术栈分层原因 |
| 规则2(苏格拉底·追问链) + 规则3(费曼·统合叙事) | 费曼 · 统合叙事（场景驱动，先串联全景） | 苏格拉底 · 追问链（嵌入关键决策点） | REST vs gRPC vs GraphQL 选型 |
| 规则2/3/4 任意 + 规则5(费曼·概念解释) | 规则2/3/4 中命中者 | 费曼 · 概念解释（写后校验用，非输出结构） | — |
| 规则2/3/4/5 任意 + 规则1(不嵌入) | 规则2/3/4/5 中命中者（规则1不激活） | — | — |
| **未在上表覆盖的组合** | 按命中规则中权重最高的执行（规则4>3>2>5>1） | 命中规则中次高者（若适用） | — |

**决策原则：**
1. **规则4（金字塔）永远优先** — 全局认知是理解的前提，先搭骨架再填肉
2. **规则3（费曼）> 规则2（苏格拉底）** — 叙事性场景可内嵌决策追问，但追问链不能脱离场景
3. **子节方法只用于次级层次** — 不影响顶层结构选择

## 反例与黑名单

以下是在方法论路由过程中**不要做**的事，每条来自真实 RED 案例：

| # | 不要做（反模式） | 为什么 | 替代做法 |
|---|---|---|---|
| 1 | 对简单概念用苏格拉底长篇追问 | 过度工程化，读者厌烦；把明确事实变成哲学辩论 | 用「不嵌入」直接定义 + 示例 |
| 2 | 对层级概念用「不嵌入」 | 读者丢失全局地图，在术语森林中迷失 | 用金字塔结论先行或费曼统合叙事 |
| 3 | 一个知识点分配两种及以上顶层方法 | 写法混乱，读者无法建立一致的心智模型 | 顶层只选一种；第二种只用于子节（见冲突解决） |
| 4 | 静默引用失效路径 | wikilink 断裂导致 agent 读到空内容而不自知 | 边界条件回退 + 标注 ⚠️ |
| 5 | 跳过判断优先级直接凭直觉选方法 | 倾向于用最熟悉的方法（通常是苏格拉底），与知识点脱节 | 逐条过 1→6，命中即停 |

## 约束

- 只判断，不写作
- 每知识点顶层最多一种方法；子节可用第二种方法（见冲突解决）
- 不复制 QA转面经 的方法文档内容——通过 wikilink 跳转读取
