# 方法论路由中心

> **定位：** 只做路由，不做拷贝。所有方法论内容引用已有 skill，本文件只负责"根据知识点特征选择合适的方法论 → 跳转到对应 skill"。
> **使用者：** 任何需要"在输出 md 时嵌入名人方法论"的 skill 套件（学习助手、QA转面经、写skill……）

## RED（失败基线）

方法论路由的 3 条已知失败模式，按「触发条件 → 一线修复 → 仍失败兜底」三段式处理：

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 对简单概念用苏格拉底长篇追问 | 改用「不嵌入」直接定义+示例（触发规则1/6） | 恢复默认定义格式，删除追问链 |
| 对层级概念用「不嵌入」 | 改用金字塔结论先行或费曼统合叙事（触发规则3/4） | 至少输出一句话全局概括+对比表 |
| 目标方法文档路径失效（wikilink 断裂） | 回退到已注册方法表的「适用场景」自行按原则写 | 标注⚠️方法文档不可达，基于原则自行应用 |

## GREEN（执行主线）
见下方"判断优先级"和"使用方法"。

## REFACTOR
- 判断优先级规则超过 6 条 → 下沉到 `references/判断优先级详细规则.md`
- 新增方法 → 在 QA转面经 方法论库中新增，本文件只更新"已注册方法"表

## 判断优先级

**输入：** 待解释的知识点文本
**输出：** `{ method, reason, suggestion }`
**流程：** 顺序执行以下检查，**命中即停**。若多个规则同时命中 → 暂存全部编号，转「冲突解决」表。

```
[Q1] 知识点本身已够清晰（如单一术语定义）？          → 不嵌入           → 停
[Q2] 是决策点/选型问题？                            → 苏格拉底追问      → 停
[Q3] 涉及多术语混淆或有层级/派生关系？              → 费曼统合叙事      → 停
[Q4] 章首缺少全局认知（读者需要先看到"地图"）？      → 金字塔结论先行    → 停
[Q5] 需要对术语做通俗解释（非层级关系，仅需比喻）？  → 费曼概念解释      → 停
[Q6] 以上都不符合？                                 → 不嵌入           → 停
```

> **注意：** 同一知识点可能同时满足多个 Q（如 Q3+Q4）。此时不取第一个命中的方法，而是参考「冲突解决」表决定主次分配。

## 使用方法（Agent 视角）

### 输入 → 输出管道

```
原始知识点文本
    ↓
Step 1 特征分析 → 特征标签（如"多术语""决策点""章首缺全局"）
Step 2 方法选择 → { method, reason, suggestion }
Step 3 路由执行 → 按方法格式生成的解释内容
Step 4 写后校验（仅费曼）→ 校验报告 + 修正内容
```

### 分步规格

```
Step 1 — 知识点特征分析
  Input:  知识点文本
  Action: 依次过判断优先级 Q1→Q6，记录所有命中的规则编号
  Output: 特征标签（如"多术语+层级关系" "决策点+章首缺全局"）

Step 2 — 方法选择
  Input:  命中的规则编号列表
  Action: 
    · 仅1个命中 → 直接选对应方法
    · ≥2个命中 → 查冲突解决表确定顶层+子节方法
  🔴 CHECKPOINT: 确认方法选择与知识点特征匹配
  Output: { method: "费曼·统合叙事"|"苏格拉底·追问链"|"金字塔·结论先行"|"不嵌入",
            reason: "命中Q3: 多术语+层级关系",
            suggestion: "用一个场景串联四个概念" }

Step 3 — 路由执行
  Input:  method + suggestion
  Action: 按已注册方法表的「路由目标」跳转读取对应 .md
  🔴 CHECKPOINT: 验证目标方法文档路径可访问；若不可达，回退到适用场景自行写
  Output: 按选定方法生成的解释内容

Step 4 — 写后校验（仅费曼）
  Condition: method = "费曼·统合叙事" 或 "费曼·概念解释"
  Action: 追加执行 费曼-理解校验.md
  Output: 校验报告 + 修正后内容
```

## 冲突解决

当知识点同时命中多条判断优先级规则时，按以下冲突类型决策：

| 冲突组合 | 顶层方法 | 子节方法 | 示例 |
|---|---|---|---|
| 规则3(费曼·统合叙事) + 规则4(金字塔·结论先行) | 金字塔 · 结论先行（先建全局认知） | 费曼 · 统合叙事串联术语 | 微服务三组件关系 |
| 规则2(苏格拉底·追问链) + 规则4(金字塔·结论先行) | 金字塔 · 结论先行（先建全局认知） | 苏格拉底 · 追问链逐层深入 | 技术栈分层原因 |
| 规则2(苏格拉底·追问链) + 规则3(费曼·统合叙事) | 费曼 · 统合叙事（场景驱动，先串联全景） | 苏格拉底 · 追问链（嵌入关键决策点） | REST vs gRPC vs GraphQL 选型 |
| 规则2/3/4 任意 + 规则5(费曼·概念解释) | 规则2/3/4 中命中者 | 费曼 · 概念解释（写后校验用，非输出结构） | — |
| 规则2/3/4/5 任意 + 规则1(不嵌入) | 规则2/3/4/5 中命中者（规则1不激活） | — | — |

**决策原则：**
1. **规则4（金字塔）永远优先** — 全局认知是理解的前提，先搭骨架再填肉
2. **规则3（费曼）> 规则2（苏格拉底）** — 叙事性场景可内嵌决策追问，但追问链不能脱离场景
3. **子节方法只用于次级层次** — 不影响顶层结构选择

## 反例与黑名单

以下是在方法论路由过程中**不要做**的事，每条来自真实 RED 案例：

| # | 不要做（反模式） | 为什么 | 替代做法 |
|---|---|---|---|
| 1 | 对简单概念用苏格拉底长篇追问 | 过度工程化，读者厌烦；把明确事实变成哲学辩论 | 用「不嵌入」直接定义 + 示例 |
| 2 | 对层级概念用「不嵌入」 | 读者丢失全局地图，在术语森林中迷失 | 用金字塔结论先行或费曼统合叙事 |
| 3 | 一个知识点分配两种及以上顶层方法 | 写法混乱，读者无法建立一致的心智模型 | 顶层只选一种；第二种只用于子节（见冲突解决） |
| 4 | 静默引用失效路径 | wikilink 断裂导致 agent 读到空内容而不自知 | 边界条件回退 + 标注 ⚠️ |
| 5 | 跳过判断优先级直接凭直觉选方法 | 倾向于用最熟悉的方法（通常是苏格拉底），与知识点脱节 | 逐条过 1→6，命中即停 |

## 约束

- 只判断，不写作
- 每知识点顶层最多一种方法；子节可用第二种方法（见冲突解决）
- 不复制 QA转面经 的方法文档内容——通过 wikilink 跳转读取
