# 探索-本地仓库 策略

> 当用户已 clone 项目到本地，或传了 `--repo-path` 时使用。

## 探索步骤

### 1. 建立全局结构（depth=3）

首选 `directory_tree(path, maxDepth=3)` 拿到整体结构。
目的：看到 monorepo 的 apps/packages 分层、关键配置文件。

**回退：** 如果 `directory_tree` 不可用，用 `list_directory` 逐层手动组装 + `run_command("dir /s /b /a-d <path> | find /c /v \"\"\"`（Windows）或 `find . -type f | wc -l`（Linux）算文件总数。

### 2. 读入口文件

按优先级：
1. `README.md` — 项目介绍、架构说明
2. `package.json` — 技术栈、脚本、依赖
3. 入口文件（`src/index.ts` / `main.tsx`）— 启动逻辑
4. 类型定义（`src/types/` / `packages/core/`）— 核心词汇表

### 3. 按关注点深入

如果调用方（如学习助手）提供了"关注点列表"：
- 每个关注点 → 找到对应源码目录 → `read_file` 关键文件 → 提取架构决策

### 4. 输出

```markdown
## {项目名} — 本地探索结果

**路径：** {repo-path}
**文件总数：** 约 {N} 个

### 目录结构
{directory_tree 输出}

### 架构分层
- 层 1：{名称} — {职责} — {核心文件}
- 层 2：...

### 关键设计决策
1. {决策} → {源码证据}
2. ...
```

## 约束

- 深度 ≤ 3 层（token 预算控制）
- 不读 node_modules / .git / dist / build
- 单文件读不超过 200 行（超过用 head + range 分次读）
- 仓库 > 500 个文件：只探索一级目录 + README.md + package.json，输出摘要而非完整树
- 仓库 > 2000 个文件：只读 README.md + package.json，提示用户指定具体关注点
