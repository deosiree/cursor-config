# Go 语义化任务 ID 规范

## 目标
生成具备业务语义的任务 ID，使重试可去重、问题可追踪、运维可定位。

## ID 规则
1. 优先使用稳定业务维度：`module + action + resource`。
2. 同一业务意图的重试必须保持同一 task ID。
3. 仅在“独立重跑”场景增加版本号或时间因子。
4. 在存储层/缓存层增加唯一约束作为兜底。

## 推荐格式
`{module}_{action}_{resource}_{variant}`

示例：
- `image_upload_retry_order123456`
- `invoice_sync_rebuild_tenant88_v2`

## 实现模式
1. 提供统一 ID Builder 包并约束入参类型。
2. 重试场景基于不可变业务键派生 ID。
3. 去重使用唯一索引 / `SETNX` / 幂等记录表。
4. 提供按 task ID 反查执行链路能力。

## 审查清单
- 值班同学能否从 ID 直接判断任务意图？
- 同一次业务重试是否稳定生成同一 ID？
- 独立重跑是否能通过受控后缀区分？
- 是否存在内存外的持久化去重屏障？

## 反模式
- 仅使用随机 UUID 作为唯一任务标识。
- 引入易变字段导致重试幂等性失效。
- 各模块各自定义拼接规则，格式失控。
