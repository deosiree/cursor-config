# Go 错误码国际化 Manifest

## 目标
集中维护错误码翻译资源，并按请求语言动态返回本地化错误信息。

## 架构规则
1. 错误码在代码中保持稳定，不因语言变化而变化。
2. 语言文案统一放在 manifest 资源（key 为错误码）。
3. 从请求元数据解析语言（如 `Accept-Language`）。
4. 未命中目标语种时必须有默认语言兜底。

## 实现模式
1. 提供翻译资源加载器，按需支持热更新。
2. 提供 `Translate(code, lang)` 统一翻译入口。
3. 响应字段固定为 `code`、`message`、可选 `locale`。
4. 建立词条提取、缺失校验、发布检查工具链。

## 审查清单
- 业务分支中是否移除了硬编码文案？
- 对外错误码是否全部在 manifest 中有映射？
- 默认语言回退策略是否确定且可测试？
- 是否在本地化 message 的同时保留机器可读 code？
- 语言解析是否能稳健处理未知 locale？

## 反模式
- 在 handler 中直接返回硬编码中英文文案。
- 按部署机房决定语言而非按请求决定语言。
- 业务逻辑改动与翻译词条改动高度耦合且分散。
