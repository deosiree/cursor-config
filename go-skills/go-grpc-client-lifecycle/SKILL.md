# Go gRPC 客户端生命周期治理

## 目标
通过 SDK 统一管理 gRPC 客户端，避免重复初始化、连接浪费和高并发下的延迟抖动。

## 必选设计决策
1. 以服务名作为全局 key 管理客户端实例。
2. 由 SDK 暴露统一获取接口，不允许业务侧直接拨号。
3. 优先复用长连接，禁止按请求临时建连。
4. 每个下游调用都必须显式设置 timeout/deadline。

## 实现模式
1. 建立进程级注册表：`map[string]ClientHandle`。
2. 在 SDK 层接入注册发现（如 Nacos）解析实例列表。
3. 在启动期或首次访问时完成连接初始化与受控重试。
4. 使用确定性路由策略（轮询或健康感知）选择连接。
5. 输出连接池与调用健康指标。

## 审查清单
- 业务代码是否仍直接调用 `grpc.Dial`？
- 注册表 key 是否为服务维度而非方法维度？
- 连接是否在多个 goroutine 间安全复用？
- timeout 是否配置且被强制执行？
- 重连与退避策略是否显式可见？
- 可观测字段（target、latency、code）是否完整输出？

## 反模式
- 在每个 handler/函数内新建 gRPC client。
- 依赖默认零值导致超时策略失效。
- 把服务发现逻辑散落在业务处理代码里。
