# Go 横切逻辑拦截器治理

## 目标
将公共非业务逻辑统一沉淀到拦截器/中间件，降低重复代码并提升一致性。

## 边界规则
1. 入口层横切逻辑进入拦截器：审计、鉴权、追踪、指标、结构化日志。
2. 领域业务决策保留在 service 逻辑，不放入拦截器。
3. 服务内部函数调用不会自动被拦截，需要显式补充埋点。

## 实现模式
1. 明确拦截器链顺序并固化注册位置。
2. 基于 `fullMethod` 做按接口粒度策略匹配。
3. 关键校验失败要快速失败，避免隐藏副作用。
4. 提供标准拦截器模板供新服务复用。

## 审查清单
- 审计/日志/鉴权是否仍在多个 handler 中重复？
- 拦截器执行顺序是否确定且有文档？
- 被豁免接口是否有显式清单与理由？
- 拦截器注入 context 值是否被安全消费？
- 错误包装是否在拦截器边界内保持一致？

## 反模式
- 每个 RPC 方法里手写鉴权和日志。
- 在拦截器中编写重业务事务逻辑。
- 随意注册拦截器导致执行顺序不确定。
