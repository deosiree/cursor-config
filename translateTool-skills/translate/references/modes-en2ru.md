# 模式说明：en2ru（英文 → 俄文）

## 何时使用

- 用户明确说：英译俄、en2ru、俄文翻译列、把英文翻译翻成俄文
- 输入为平台导出的 CSV/XLSX，含「英文翻译」「俄文翻译」列
- 典型样例：`qt通用语言.xlsx`（词条多为英文字符串）

## 何时不要使用

- 中文 → 英文（用默认 `zh2en`）
- JSON / `.dic` / `.report` 超长俄文缩短（用 `json-精简超长翻译`）
- 数据库回滚或审核副作用（用 `db-回滚数据库`）

## CLI

```bash
node translateCsv.js <input.xlsx|csv> <output_dir> --mode en2ru [--limit N] [--debugPrompt] [--force]
```

| 参数 | 含义 |
|------|------|
| `--mode en2ru` | 源列 `英文翻译`（空则 fallback `词条`）→ 目标列 `俄文翻译` |
| `--limit N` | 只处理前 N 条待译词条（试跑用） |
| `--debugPrompt` | 写出 `*_prompt_debug.md` |
| `--force` | 覆盖已有俄文（默认跳过已填，便于断点续跑） |

输出：`{原文件名}_RU机翻.csv` / `_RU机翻.xlsx`（CSV 输入或断点续跑）。

## 与 zh2en 差异

| 步骤 | zh2en | en2ru |
|------|-------|-------|
| 术语库提取 | 执行 | **跳过** |
| 中文校验 | 执行 | **跳过** |
| comment 大小写纠正 | 执行 | **跳过** |
| 占位符校验 | 执行 | **保留** |
| 批次大小 | 100 | **40** |
| 目标列 | 英文翻译 | 俄文翻译 |
| 并发 | 与 en2ru **同池**≤20 | 同左；见 `concurrency-dag.md` |

流水线请用 `--mode pipeline`（中好立刻投递俄），勿再拆成两次全量串行。

## 占位符规则（Qt）

1. `%1`、`%2`、`%n`、`{}`、`{:.3f}` 等必须原样保留（禁止 `% 1`）。
2. `%1/%2` 可按俄语句法调整相对语序，token 本身不可拆分/改写。
3. 专有名词（Qt、SSL、XML）通常不译或用业界通用写法。
4. 校验失败写入 `备注1`，不中断整批。

## 失败模式（三段式 fallback）

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| API 限流/失效 | 自动 fallback 智谱 → Gemini → Opencode | 写 `_errors.log`；`skipIfFilled` 断点续跑 |
| 占位符校验失败 | `备注1` 标记，继续下一条 | 人工复核后 `--limit` / 按 id 重跑 |
| 俄文疑似超长 | `备注1` 警告（`翻译最大长度` 有值时） | 对接 `json-精简超长翻译` |
| 源列英文为空 | fallback 到 `词条` | 仍空则跳过并记日志 |
| 依赖缺失 `xlsx` | 在 skill 目录 `npm install` | 告知用户补齐 `package.json` 依赖 |

## 反例黑名单

- 不要在 en2ru 加载中文术语库 / comment 大小写规则
- 不要默认覆盖已有「俄文翻译」（除非 `--force`）
- 不要对 en2ru 跑 `validateChinese`
- 不要在 Cursor 聊天里手工分批翻 5000+ 条（应用脚本）
- 不要把 en2ru 输出写成「覆盖输入文件」；交付 `_ru.xlsx`

## 试跑与全量门禁

1. 先：`--limit 20 --debugPrompt`
2. 核对占位符通过率 ≥ 95%
3. **🔴 CHECKPOINT**：用户确认后再全量
