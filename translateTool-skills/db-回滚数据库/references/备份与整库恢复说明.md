# 备份与整库恢复说明

## 备份目录

| 项 | 值 |
|----|-----|
| 路径 | `translationtool/db/backups/` |
| 命名 | `translationtool_YYYYMMDD_HHmmss[_label].sql` |
| 最新指针 | `db/backups/.latest`（文本，存绝对路径） |
| 保留提醒 | `db/backups/.retention-state.json`（月提醒，禁静默删） |
| git | `*.sql` 与 `.latest` 已 gitignore |

## 编码硬约束（红灯 / 绿灯）

| 禁止（红灯） | 后果 |
| --- | --- |
| PowerShell `>` / `Out-File` / `Set-Content` 接 `mysqldump` 管道 | OEM/控制台解码 → UTF-16 或截断中文 COMMENT → import **1064** |
| `Get-Content \| docker exec mysql` | 二次解码，再次破坏 |

| 锁定（绿灯） | 说明 |
| --- | --- |
| `mysqldump --result-file=...`（或 `-r`） | dump **自己写文件**，不经 PowerShell 文本层（[官方文档](https://dev.mysql.com/doc/refman/8.0/en/mysqldump.html)） |
| 容器内 dump + `docker cp` 出主机 | Docker Windows 下最稳 |
| 恢复：`docker cp` 进容器 + `mysql --default-character-set=utf8mb4 < file` | 禁止 PS 管道喂入 |

**已损坏的 dump（COMMENT 截断如 `权限�?`）无法可靠转码救回**，只能作废并用新脚本重备。

## 备份（backup 模式）

脚本：[`scripts/backup-database.ps1`](../scripts/backup-database.ps1)

成功条件：文件大小合格 **且** [`verify-dump-encoding.ps1`](../scripts/verify-dump-encoding.ps1) 通过，否则删除坏文件且 **不写** `.latest`。

```powershell
& scripts\backup-database.ps1 -ProjectRoot <root> -Label "before_test"
# 可选更严：-SmokeImport（导入临时库 translationtool_restore_smoke 再 DROP）
```

验收脚本：[`scripts/roundtrip-encoding-smoke.ps1`](../scripts/roundtrip-encoding-smoke.ps1)

## 恢复（restore 模式）

脚本：[`scripts/restore-database.ps1`](../scripts/restore-database.ps1)

**破坏性流程：**

1. 默认先跑 encoding verify（失败则拒绝 restore，不得声称回滚成功）
2. （默认）pre_restore 备份当前库
3. `DROP DATABASE` + `CREATE DATABASE ... utf8mb4`
4. `docker cp` + `mysql < file`
5. 验证表数量

必须 **`-Force`** 且用户口头确认。

**禁止**：把 `--all-databases` 整文件交给本脚本（会碰 `mysql` 系统库）。须先 [`extract-database-from-all-dump.ps1`](../scripts/extract-database-from-all-dump.ps1)。

## 指定分类保留还原（keep_classify_restore）

口令：「用服务器备份还原通用平台部的 mon-cn-1.9.0 和 develop」。

脚本：[`scripts/restore-keep-classifies.ps1`](../scripts/restore-keep-classifies.ps1)  
Inspect：[`scripts/inspect-classify-keep.ps1`](../scripts/inspect-classify-keep.ps1)  
编排：[`intention-skills/编排-指定分类保留还原/SKILL.md`](../intention-skills/编排-指定分类保留还原/SKILL.md)

流程：verify →（all-DB 则 extract）→ rewrite（临时库名 + 消毒 `@OLD_TIME_ZONE`）→ 临时库导入 → keep 子树+产品/词条闭包 → 灌本机 → `after_keep_*` 备份。

### 与服务器脚本对照

| 能力 | 服务器（Linux `>` / all-databases） | 本仓 |
|------|-------------------------------------|------|
| 备份 | all-databases + `>` | 单库 result-file + docker cp + verify |
| 删旧 | 可静默 | 人审 prune |
| scp 多节点 | 有（勿照搬） | **不做** |
| 还原 | 无 | restore + **keep_classify_restore** |

**明确不做**：Windows 复刻 `mysqldump >`；静默删备份；自动 scp。

## 每月备份清理提醒

- 状态：`.retention-state.json`（`lastRemindedAt` / `nextDueAt`，默认 +30 天）
- 触发：`backup-database.ps1` / `list-backups.ps1` 发现到期 → **只提醒**，Agent 须问用户
- 用户确认删除 → [`prune-backups.ps1`](../scripts/prune-backups.ps1) `-ConfirmDelete`
- 用户拒绝 → [`remind-backup-retention.ps1`](../scripts/remind-backup-retention.ps1) `-SnoozeDays 30`
- 可选计划任务：`remind-backup-retention.ps1 -RegisterTaskHint`（只弹提醒，不删文件）

## 选型：整库 restore vs audit 逐条

| 场景 | 推荐 |
|------|------|
| 本地功能测试，操作多且杂 | **backup + restore** |
| 只撤销几条术语同意，不能动其他数据 | **audit_rollback** |
| 按时间窗清理术语学习产物 | **term_day_cleanup**（dry-run → 确认） |
| 不确定改了什么 | **restore 到测试前备份** |
| 生产环境 | 禁止自动 restore；走 DBA + 快照 |

## term_day_cleanup

脚本：[`scripts/term-day-cleanup.ps1`](../scripts/term-day-cleanup.ps1)

- **范围 A（默认）**：时间窗内 `term_agent_audit`；可选 `-IncludeApprovedSideEffects` 软删术语库副作用
- **不做范围 B**：全库「本日所有表 INSERT」无操作日志时不安全
- 前置：库非空且有 `term_agent_audit`；空库须先恢复完好 dump

## .latest 指针

每次 `backup-database.ps1` **verify 成功后**写入 `.latest`。`restore-database.ps1 -UseLatest` 读取该文件。

## Redis

整库 restore **不包含** Redis。若出现缓存不一致，重启 `translationtoolservice` / `terminology-agent`，或按需 flush Redis。

## 风险

- restore 覆盖 **整个** translationtool 库
- 恢复前默认再 dump 一份 `pre_restore`，误操作可再 restore 回来
- verify 失败不得声称 backup/restore 成功
