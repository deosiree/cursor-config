# 扩展场景：本地术语库精简（直改数据）

本仓库配套的 translationtool **本地库不是上线产品**时，允许走后台 SQL 直接改 MySQL，再实跑 UI/Agent 验收。

权威 SSOT（translationtool 仓）：

- `docs/ops/DEV_DB_CHECKPOINT.md` → 节「本地直改数据 / 术语库精简」
- SQL：`db/opt/cleanup-syk-unused-and-dup.sql`、`db/opt/cleanup-syk-low-han-ratio.sql`

## 与本 skill 的关系

| 诉求 | 走哪里 |
|------|--------|
| 测试前备份 / 测后整库恢复 | 本 skill：`backup` / `restore` |
| 精简术语库（空挂/重复/中文占比） | **先**本 skill `backup`，**再**执行上述 `db/opt/cleanup-*.sql`；**不是**新 rollbackMode |
| 生产库 | **禁止**自动精简与 restore |

## 硬约束（摘要）

1. 先 `backup-database.ps1`，Label 如 `before_syk_cleanup` / `before_syk_low_han`
2. 只软删 `t_translate.delete_state=1`（`public_state=0` 术语库）
3. 中文占比 &lt; 80%：软删后须清空 `t_entry_info` 上对应 `*_trans_id`（本地可接受）
4. 禁止主观「没意义」乱删；禁止 PowerShell 管道写 dump
