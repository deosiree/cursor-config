# 连接与执行约定



## 本地 Docker（默认）



来自 `translationtool/docker-compose.yml`：



| 项 | 值 |

|----|-----|

| 容器名 | `translation-mysql` |

| 库名 | `translationtool` |

| 用户 | `root` |

| 密码 | `123456` |

| 端口 | `3306` |



## 备份目录



| 项 | 值 |

|----|-----|

| 路径 | `translationtool/db/backups/` |

| 指针 | `db/backups/.latest` |

| gitignore | `db/backups/*.sql`、`db/backups/.latest` |



## 字符集



**必须** 使用 utf8mb4：



```powershell

docker exec translation-mysql mysql -uroot -p123456 --default-character-set=utf8mb4 translationtool -e "SET NAMES utf8mb4; ..."

```



mysqldump 参数：`--default-character-set=utf8mb4`



## backup（整库导出）



- 脚本：`scripts/backup-database.ps1`

- 非破坏性，可随时执行

- 输出写入 `db/backups/` 并更新 `.latest`



## restore（整库导入）



- 脚本：`scripts/restore-database.ps1`

- **DROP DATABASE** + CREATE + 导入

- 必须 `-Force` + 用户确认

- 默认 restore 前先 `pre_restore` 备份

- remote / 生产 → 只输出命令，禁止自动 `-Force`



## audit inspect（只读）



- 脚本：`scripts/inspect-audit-rollback.sql`

- 默认 `dryRun=true`



## audit execute（写入）



- 脚本：`scripts/execute-audit-rollback.sql`

- 仅 `delete_state=1` 软删除，禁止硬 DELETE

- 用户必须明确「确认执行 / 直接在数据库中执行」



## 时区注意



容器 `NOW()` 可能与业务 `updated_at` 不一致；audit inspect 为 0 时可扩大 `@hours` 或改用绝对时间。



## 服务重启



整库 restore 后若 UI/API 数据异常，重启 `translationtoolservice`、`terminology-agent`（连接池缓存）。
