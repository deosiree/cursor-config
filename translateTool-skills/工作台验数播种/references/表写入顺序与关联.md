# 表写入顺序与关联

## 推荐顺序

```text
1. t_user_product          （测试用户能看见产品）
2. t_task_info             （五人员 + product_id + translate_type）
3. t_translate             （可选：术语库命中种子，translate_state=3）
4. t_entry_info            （product_id、task_id、entry_state=3、*_trans_id NULL）
5. t_product_relation      （entry_id + product_id + task_id）
```

种子真源（ProjectRoot 相对路径）：

| 档案 | 文件 |
|------|------|
| syk_glossary | `db/opt/seed-verify-syk-admin-product.sql` |
| adm_matrix | `db/opt/seed-verify-term-syk.sql` |
| custom | `template/custom-seed.example.sql` → `new-custom-seed.ps1` → `db/opt/seed-verify-custom-<slug>.sql` |

## 关键键

| 关系 | 表.字段 |
|------|---------|
| 任务属产品 | `t_task_info.product_id` |
| 词条属产品 | `t_entry_info.product_id` |
| 词条属任务 | `t_entry_info.task_id` |
| 下发三联 | `t_product_relation.(entry_id, product_id, task_id)` |
| 用户可见产品 | `t_user_product.(user_id, product_id)` |

## 术语库命中 vs 工作台待译

- **术语库命中种子**：独立 `t_translate` 行，`translate_state='3'`，**不要**写进词条的 `en_trans_id`（否则工作台已挂译文，不是「待译点术语库」场景）
- **工作台待译**：`en_trans_id IS NULL` + `entry_state=3`

## 执行通道

```text
docker cp <host.sql> <container>:/tmp/….sql
docker exec <container> sh -c "mysql -u… -p… --default-character-set=utf8mb4 < /tmp/….sql"
```

禁止：PowerShell `Get-Content | docker exec -i mysql` 对大文件/dump 的默认编码路径（与 db-回滚红灯一致）。
