# 任务人员与词条状态机

项目侧同步约束：`translationtool/docs/ops/DEV_DB_CHECKPOINT.md`。

## t_task_info 五人员（硬约束）

| 字段 | 含义 | 本地验数默认 |
|------|------|--------------|
| `creator` | 创建人 | `admin` |
| `developer` | 开发员 | `admin` |
| `entry_auditor` | 词条审核员 | `admin` |
| `translator` | 翻译员 | `admin` |
| `translation_auditor` | 翻译审核员 | `admin` |

缺任一角色 → UI 任务流/权限过滤异常（任务「看不见」或阶段按钮不对）。

## entry_state 与工作台阶段

| entry_state | 含义 | 验数进「翻译」 |
|-------------|------|----------------|
| `0` | 新建 | **禁止** |
| `1` | 词条待审等 | 非本套件默认目标 |
| `3` | 词条审核通过 | **必须** |

进翻译待译时：目标语种 `en_trans_id`（或其它 `*_trans_id`）保持 **NULL**。

## getTaskPending 翻车

Java：`TaskStateEntity.convertFrom` 对 `entry_state.equals("0")` 抛 `RuntimeException`。  
前端：`/taskManage/getTaskPending` → `code:201`「系统服务异常」。

**修复**：该任务下词条全部改为 `entry_state=3`（或移出任务），不要只改 UI。

## 反例黑名单

- 只写 `creator`，其余人员 NULL
- 种子词条默认 `entry_state=0`「先能插进库再说」
- 用 PowerShell 管道/`Set-Content` 写 mysqldump 或大 SQL
- 未建 `t_product_relation` 却声称「已下发任务」
