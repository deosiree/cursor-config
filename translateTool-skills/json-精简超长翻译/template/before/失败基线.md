# 失败基线：没有脚本时 LLM 估算字节的常见偏差

## 典型失败场景

### 场景 1：LLM 用"字符数"代替"字节数"

用户：*"帮我缩短这条俄语翻译，不要超过 63 个字符"*

LLM 会把"63 个字符"理解为 63 个俄文字母，但实际上俄语 UTF-8 下每个字母 2 字节，63 字节 ≈ 31 个俄文字母。结果 LLM 缩短后还是超标一倍。

### 场景 2：LLM 不知道标点和空格是单字节

用户给了一条 150 字节的俄语翻译，LLM 凭感觉砍掉一半，没有精确计算字节。缩短后实际还剩 80 字节，仍然超标。

### 场景 3：没有工具回验

LLM 缩短后把结果直接写回源文件。用户运行 C++ 编译才发现字符串太长导致编译警告。此时源文件已经被覆盖了。

### 场景 4：每次重新人工检测

每次有新 JSON 文件需要检查时，用户都要手动打开文件、复制俄语字符串到在线工具看字节长度，再记录超标条目。重复劳动。

## 基线数据

| 指标 | 无脚本时 | 有脚本后 |
|------|---------|---------|
| 检测耗时 | 5-10 分钟/文件 | <1 秒 |
| 回验覆盖率 | 0%（不回验） | 100% |
| 输出目录安全 | 覆盖源文件 | 隔离到 _new 目录 |
| LLM 估算偏差 | 2-8 字节 | 精确到字节 |
