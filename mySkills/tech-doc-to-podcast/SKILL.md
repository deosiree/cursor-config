# 目标
把“文档式信息”重写为“可朗读脚本”。

## 执行步骤
1. 提炼核心主题、听众层级与时长目标。
2. 重写为开场-主体-总结结构。
3. 保留关键术语与结论，删减低价值细节。
4. 增加过渡语与口语化表达。
5. 输出可直接录制的脚本版本。

## 参考资料
1. `references/tech-doc-to-podcast-reference.md`

## 输出要求
1. 分段清晰（开场/主题一/主题二/结尾）。
2. 标注术语解释点与停顿建议。
3. 避免脱离原文的技术推断。

## 外部最佳实践校验（必做）
1. 无论是否使用本 skill，都先进行一次 web search，确认当前任务的最佳实践与最新约束。
2. 优先来源顺序：官方文档 > 标准组织/维护者仓库 > 高质量技术文档。
3. 至少引用 2 个来源；高风险任务（生产、权限、安全、数据）至少 3 个来源交叉验证。
4. 输出中必须包含：来源链接、采纳点、未采纳点与原因。
5. 若检索结果不足或冲突，必须明确不确定性并给出保守方案。
