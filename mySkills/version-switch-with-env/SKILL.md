# 目标
把版本控制从“散落 if-else”收敛为“统一解析 + 入口路由 + 版本实现隔离”。

## 执行步骤
1. 定义版本类型与切换粒度（环境/租户/请求）。
2. 实现统一版本来源（只在单点读取 env/config）。
3. 在入口建立版本路由（`switch(version)`）。
4. 拆分 `impl-v1`/`impl-v2` 并抽取共享逻辑。
5. 定义灰度与回滚策略。

## 约束
1. 禁止在深层业务代码直接读取 `process.env`。
2. 非法版本值必须回退安全默认值。
3. 每次版本扩展都要补齐测试与回滚验证。

## 输出要求
1. 给出目录改造建议。
2. 给出最小可行代码骨架。
3. 给出发布与回滚操作说明。

## 外部最佳实践校验（必做）
1. 无论是否使用本 skill，都先进行一次 web search，确认当前任务的最佳实践与最新约束。
2. 优先来源顺序：官方文档 > 标准组织/维护者仓库 > 高质量技术文档。
3. 至少引用 2 个来源；高风险任务（生产、权限、安全、数据）至少 3 个来源交叉验证。
4. 输出中必须包含：来源链接、采纳点、未采纳点与原因。
5. 若检索结果不足或冲突，必须明确不确定性并给出保守方案。
