# 目标
在给定 `source_version -> target_version` 的条件下，只输出可执行、可追溯、有证据的迁移项。

## 输入
1. `spec_path`：Swagger/OpenAPI 文件路径。
2. `project_paths`：一个或多个项目目录。
3. `source_version` 与 `target_version`。
4. `ready_rule`（可选，默认 `summary` 包含 `[ready]`）。

## 执行步骤
1. 从规范文件提取满足 ready 规则的接口。
2. 在代码中定位真实调用证据（方法调用或 URL 命中）。
3. 建立 source/target 映射并标注置信度。
4. 检查 mock 兼容性（复用/新增/可下线）。
5. 按项目输出 P0/P1/暂不纳入项。

## 强约束
1. 无调用证据的接口不纳入迁移。
2. 每条迁移项必须包含证据路径（`绝对路径:行号`）。
3. 每条迁移项必须包含文件影响面（API/调用方/mock）。
4. 明确区分：已在目标版本、可迁移、暂不可迁移。

## 输出模板
1. 过滤规则（ready/usage）。
2. Ready 接口概览（按模块计数）。
3. 按项目的 P0/P1/已完成/暂不纳入列表。
4. 执行顺序与验收标准（功能、网络、mock）。

## 外部最佳实践校验（必做）
1. 无论是否使用本 skill，都先进行一次 web search，确认当前任务的最佳实践与最新约束。
2. 优先来源顺序：官方文档 > 标准组织/维护者仓库 > 高质量技术文档。
3. 至少引用 2 个来源；高风险任务（生产、权限、安全、数据）至少 3 个来源交叉验证。
4. 输出中必须包含：来源链接、采纳点、未采纳点与原因。
5. 若检索结果不足或冲突，必须明确不确定性并给出保守方案。
