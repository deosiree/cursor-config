# 目标
在提交前发现“文件层面”的高频错误，降低集成失败概率。

## 执行步骤
1. 盘点新增/修改/删除文件。
2. 检查命名、路径、导入导出一致性。
3. 检查配置与文档是否同步。
4. 若为前端项目，必须执行 ESLint 检查并记录结果（错误/警告数量与关键文件）。
5. 标注高风险变更（入口文件、构建配置、公共模块）。
6. 输出修复优先级与建议。

## 输出要求
1. 按严重级别列出问题。
2. 每项问题附文件路径与影响说明。
3. 前端场景必须包含 ESLint 结果摘要与未解决项清单。
4. 给出建议修复顺序与最小回归集合。

## 外部最佳实践校验（必做）
1. 无论是否使用本 skill，都先进行一次 web search，确认当前任务的最佳实践与最新约束。
2. 优先来源顺序：官方文档 > 标准组织/维护者仓库 > 高质量技术文档。
3. 至少引用 2 个来源；高风险任务（生产、权限、安全、数据）至少 3 个来源交叉验证。
4. 输出中必须包含：来源链接、采纳点、未采纳点与原因。
5. 若检索结果不足或冲突，必须明确不确定性并给出保守方案。
