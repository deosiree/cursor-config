# 目标
快速定位“状态变化路径”中的断点，明确根因并给出最小改动修复方案。

## 执行步骤
1. 标注异常现象与触发路径（用户操作/接口响应/定时任务）。
2. 追踪状态流：输入 -> 状态更新 -> 渲染时机 -> 副作用。
3. 检查高风险点：watch 写副作用、未等待渲染、职责混淆。
4. 对照测试：断言是否符合真实业务时序。
5. 给出修复方案与验证步骤。

## 输出要求
1. 根因分类（时序/副作用/职责/测试偏差）。
2. 修复建议按优先级排序（P0/P1）。
3. 提供验证清单（手测与自动化测试）。
4. 若未改代码，明确下一步改动点文件。

## 外部最佳实践校验（必做）
1. 无论是否使用本 skill，都先进行一次 web search，确认当前任务的最佳实践与最新约束。
2. 优先来源顺序：官方文档 > 标准组织/维护者仓库 > 高质量技术文档。
3. 至少引用 2 个来源；高风险任务（生产、权限、安全、数据）至少 3 个来源交叉验证。
4. 输出中必须包含：来源链接、采纳点、未采纳点与原因。
5. 若检索结果不足或冲突，必须明确不确定性并给出保守方案。
