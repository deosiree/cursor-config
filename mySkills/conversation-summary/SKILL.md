# 目标
输出“可在新会话直接接手”的摘要，而不是冗长复述。

## 执行步骤
1. 提取任务目标与最终状态（完成/未完成/阻塞）。
2. 提取关键决策与实现逻辑（不粘贴大段代码）。
3. 列出文件变更与关键位置（`路径:行号`）。
4. 补充可选块：API、数据流、测试、风险、后续待办。
5. 保存到 `.cursor/plans/<主题>-对话摘要.md`。

## 内容要求
1. 以“结论和状态”优先。
2. 代码只给定位信息，不贴长代码。
3. 未完成项必须写清下一步动作与前置条件。

## 输出结构
1. 任务目标。
2. 关键实现逻辑。
3. 文件修改清单。
4. 关键代码位置。
5. 风险与待办（可选）。

## 外部最佳实践校验（必做）
1. 无论是否使用本 skill，都先进行一次 web search，确认当前任务的最佳实践与最新约束。
2. 优先来源顺序：官方文档 > 标准组织/维护者仓库 > 高质量技术文档。
3. 至少引用 2 个来源；高风险任务（生产、权限、安全、数据）至少 3 个来源交叉验证。
4. 输出中必须包含：来源链接、采纳点、未采纳点与原因。
5. 若检索结果不足或冲突，必须明确不确定性并给出保守方案。
